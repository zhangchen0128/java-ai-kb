# 反射与模块化系统

## 概述

反射（Reflection）是 Java 最强大的元编程能力，允许程序在运行时检查、获取和操作类的内部结构。它是 Spring IoC、AOP、JPA、序列化框架以及几乎所有 Java 框架的基石。MethodHandle 和 VarHandle 则提供了更底层、更高性能的动态方法调度和变量访问能力。

JPMS（Java Platform Module System，即模块化系统）从 JDK 9 引入，彻底改变了 Java 的封装模型——不再是"所有 public 类都可以被访问"，而是由 module-info.java 显式声明哪些包对哪些模块开放。

AI 开发中，反射被广泛用于动态 Tool 注册、JSON Schema 自动生成等场景——理解反射是构建可扩展 AI Agent 框架的基础。

## 一、反射 API 核心

### 1.1 获取 Class 对象

```java
// 三种方式
Class<String> clazz1 = String.class;                      // 编译时已知
Class<?> clazz2 = Class.forName("java.lang.String");      // 运行时动态加载
Class<? extends String> clazz3 = "hello".getClass();      // 通过实例获取
```

### 1.2 构造函数：动态创建实例

```java
// 获取无参构造函数
Constructor<MyService> ctor = MyService.class.getDeclaredConstructor();
var instance = ctor.newInstance();

// 获取带参构造函数
Constructor<MyService> ctorWithArgs = MyService.class.getDeclaredConstructor(
    String.class, int.class);
var instance2 = ctorWithArgs.newInstance("config", 42);

// 访问私有构造函数（框架常用，如单例模式）
Constructor<MyService> privateCtor = MyService.class.getDeclaredConstructor();
privateCtor.setAccessible(true); // 绕过访问控制
var singleton = privateCtor.newInstance();
```

### 1.3 Field：读写字段值

```java
class User {
    private String name;
    private int age;
}

// 反射读写字段
var user = new User();
var nameField = User.class.getDeclaredField("name");
nameField.setAccessible(true); // 私有字段必须设置
nameField.set(user, "Alice");

var ageField = User.class.getDeclaredField("age");
ageField.setAccessible(true);
var age = (int) ageField.get(user);

// JDK 25 var 优化
var fields = User.class.getDeclaredFields();
for (var field : fields) {
    field.setAccessible(true);
    System.out.println(field.getName() + " = " + field.get(user));
}
```

### 1.4 Method：动态调用

```java
class Calculator {
    public int add(int a, int b) { return a + b; }
    private String format(String prefix, int value) { return prefix + ": " + value; }
}

// 调用公有方法
var calc = new Calculator();
var addMethod = Calculator.class.getMethod("add", int.class, int.class);
var result = (int) addMethod.invoke(calc, 3, 5); // result = 8

// 调用私有方法
var formatMethod = Calculator.class.getDeclaredMethod("format", String.class, int.class);
formatMethod.setAccessible(true);
var formatted = (String) formatMethod.invoke(calc, "Result", 42);
```

### 1.5 动态代理

动态代理是 AOP 的底层基石：

```java
import java.lang.reflect.*;

interface Greeter {
    String greet(String name);
}

class GreeterImpl implements Greeter {
    public String greet(String name) { return "Hello, " + name; }
}

// 创建动态代理
Greeter proxy = (Greeter) Proxy.newProxyInstance(
    Greeter.class.getClassLoader(),
    new Class<?>[]{Greeter.class},
    (Object proxyObj, Method method, Object[] args) -> {
        var start = System.nanoTime();
        System.out.println("Before: " + method.getName());
        var result = method.invoke(new GreeterImpl(), args); // 委托给真实对象
        System.out.println("After: " + method.getName()
            + " took " + (System.nanoTime() - start) / 1_000_000 + "ms");
        return result;
    }
);

String response = proxy.greet("World"); // 触发 InvocationHandler
```

**局限性：** JDK 动态代理只能代理接口。如果目标类没有实现接口，需要使用 CGLIB（字节码生成子类代理）。这是 Spring AOP 的双代理策略根源。

### 1.6 泛型反射（TypeToken 模式）

```java
import java.lang.reflect.ParameterizedType;

// TypeToken 模式：通过匿名子类保留泛型信息
abstract class TypeToken<T> {
    private final Type type;

    protected TypeToken() {
        var superclass = getClass().getGenericSuperclass();
        this.type = ((ParameterizedType) superclass).getActualTypeArguments()[0];
    }

    public Type getType() { return type; }
}

// 使用
var token = new TypeToken<List<String>>() {}; // 匿名子类
var type = token.getType();
System.out.println(type); // java.util.List<java.lang.String>

// 实际场景：Jackson 反序列化泛型
// mapper.readValue(json, new TypeReference<List<User>>() {});
```

## 二、MethodHandle 与 VarHandle

### 2.1 为什么需要 MethodHandle？

反射的 `Method.invoke()` 每次调用都要做安全检查、参数包装、自动装箱，性能开销大。MethodHandle 通过 `invokedynamic` 指令，JIT 可以内联优化到与直接调用同等的性能。

```java
import java.lang.invoke.*;

// 获取 MethodHandle
var lookup = MethodHandles.lookup();
var methodType = MethodType.methodType(int.class, int.class, int.class);
var addHandle = lookup.findVirtual(Calculator.class, "add", methodType);

// 调用（避免自动装箱）
var calc = new Calculator();
int result = (int) addHandle.invokeExact(calc, 3, 5); // 精确调用，性能最优

// 绑定接收者
var boundHandle = addHandle.bindTo(calc);
int result2 = (int) boundHandle.invokeExact(3, 5);
```

### 2.2 MethodHandle vs 反射性能对比

| 维度 | 反射（Method.invoke） | MethodHandle.invokeExact |
|------|----------------------|-------------------------|
| 类型检查 | 运行时 | 编译时（通过 MethodType） |
| 自动装箱 | 有（参数和返回值） | 无 |
| JIT 内联 | 困难（需要 Profile Pollution） | 支持完全内联 |
| 安全检查 | 每次都做 | 第一次做，后续跳过 |
| 性能 | 慢 10-50 倍 | 接近直接调用（热路径 1-3 倍） |

```java
// JMH 基准测试结论：
// MethodHandle.invokeExact：接近直接调用的 120% 性能
// LambdaMetaFactory：等于直接调用的 100% 性能
// Method.invoke：直接调用的 300%~500% 性能
```

### 2.3 VarHandle：直接内存屏障操作

VarHandle 提供对字段的 volatile、CAS、有序读写的统一接口：

```java
import java.lang.invoke.*;

class Counter {
    private volatile int value;

    private static final VarHandle VALUE;

    static {
        try {
            VALUE = MethodHandles.lookup()
                .findVarHandle(Counter.class, "value", int.class);
        } catch (ReflectiveOperationException e) {
            throw new ExceptionInInitializerError(e);
        }
    }

    public int increment() {
        // CAS 原子递增
        int prev;
        do {
            prev = (int) VALUE.getVolatile(this);
        } while (!VALUE.compareAndSet(this, prev, prev + 1));
        return prev + 1;
    }

    public int getValue() {
        return (int) VALUE.getVolatile(this); // volatile 读
    }

    public void setValue(int v) {
        VALUE.setVolatile(this, v); // volatile 写
    }
}
```

### 2.4 LambdaMetaFactory：将 MethodHandle 转为 Lambda

这是最高性能的动态方法调用方案，常用于框架生成 getter/setter：

```java
import java.lang.invoke.*;
import java.util.function.Function;

// 将 getter 方法转为 Function lambda
var lookup = MethodHandles.lookup();
var getterHandle = lookup.findVirtual(Person.class, "getName",
    MethodType.methodType(String.class));
var factory = LambdaMetafactory.metafactory(
    lookup,
    "apply",
    MethodType.methodType(Function.class),          // 工厂方法类型
    MethodType.methodType(Object.class, Object.class), // 函数式接口签名（擦除后）
    getterHandle,
    getterHandle.type()                              // 实际签名
);
@SuppressWarnings("unchecked")
Function<Person, String> getNameFunc = (Function<Person, String>)
    factory.getTarget().invokeExact();
var name = getNameFunc.apply(new Person("Alice")); // 直接调用级别性能！
```

## 三、JPMS 模块系统

### 3.1 module-info.java 关键指令

```java
// module-info.java 示例
module com.example.ai.agent {
    // 引入其他模块
    requires spring.context;          // 编译和运行时都需要
    requires static lombok;           // 仅编译时需要（可选依赖）
    requires transitive ai.sdk;       // 依赖传递：依赖本模块的模块自动获得 ai.sdk

    // 导出包
    exports com.example.ai.agent.api; // 对外暴露的 API
    exports com.example.ai.agent.dto to com.example.ai.gateway; // 仅对特定模块暴露

    // 反射开放
    opens com.example.ai.agent.model to spring.beans; // Spring 需要反射访问实体类
    opens com.example.ai.agent.config; // 对反射完全开放

    // SPI（Service Provider Interface）
    uses com.example.ai.spi.ToolProvider;       // 声明使用服务
    provides com.example.ai.spi.ToolProvider    // 声明提供服务实现
        with com.example.ai.tool.WebSearchTool;
}
```

### 3.2 模块化下的反射访问

JPMS 的强封装对反射有严格限制：

```java
// 公开导出的包：反射正常使用
var exportedClass = Class.forName("com.example.ai.agent.api.AgentService");

// 未导出的包：默认会被拒绝
try {
    var internalClass = Class.forName("com.example.ai.agent.internal.AgentEngine");
    // 抛出 InaccessibleObjectException！
} catch (InaccessibleObjectException e) {
    System.err.println("模块未开放反射访问: " + e.getMessage());
}

// 解决方案：
// 1. 在 module-info.java 中使用 opens 声明
// 2. JVM 参数：--add-opens module/package=ALL-UNNAMED
// 3. 使用 VarHandle 绕过（Spring 的做法）
```

### 3.3 ServiceLoader 模块化

```java
// 定义服务接口（在 API 模块中）
public interface Tool {
    String name();
    String execute(String input);
}

// 模块化声明
// 使用方
// module com.example.app {
//     requires com.example.tool.api;
//     uses Tool;
// }

// 提供方
// module com.example.tool.websearch {
//     requires com.example.tool.api;
//     provides Tool with com.example.tool.websearch.WebSearchTool;
// }

// 运行时加载
var tools = ServiceLoader.load(Tool.class);
for (var tool : tools) {
    System.out.println("Found tool: " + tool.name());
}
```

## 四、类加载机制

### 4.1 双亲委派模型

```java
// 类加载器层次
Bootstrap ClassLoader          ← 加载 rt.jar / java.base（JVM 实现，C++）
    └─ Platform ClassLoader    ← 加载 java.sql, java.xml 等（JDK 内部）
        └─ Application ClassLoader ← 加载 classpath 中的应用类

// 双亲委派流程（loadClass 源码）
protected Class<?> loadClass(String name, boolean resolve) {
    synchronized (getClassLoadingLock(name)) {
        // 1. 检查是否已加载
        Class<?> c = findLoadedClass(name);
        if (c == null) {
            // 2. 委托父加载器加载
            if (parent != null) {
                c = parent.loadClass(name, false);
            } else {
                c = findBootstrapClassOrNull(name);
            }
        }
        if (c == null) {
            // 3. 父加载器无法加载，自己尝试
            c = findClass(name);
        }
        return resolve ? resolveClass(c) : c;
    }
}
```

**打破双亲委派：** Tomcat 的 WebappClassLoader 和 Spring Boot 的 LaunchedURLClassLoader 都采用了"先自己尝试，自己搞不定再让父加载器加载"的策略，以实现应用隔离。

### 4.2 模块化下的类加载变化（Module Layer）

```java
// 模块化类加载使用 ModuleLayer 和 ModuleFinder
var finder = ModuleFinder.of(Path.of("modules"));
var parentLayer = ModuleLayer.boot();
var configuration = parentLayer.configuration()
    .resolve(finder, ModuleFinder.of(), Set.of("my.module"));

// 创建新的 Module Layer（类似 ClassLoader 的隔离效果）
var controller = ModuleLayer.defineModulesWithOneLoader(
    configuration,
    List.of(parentLayer),
    ClassLoader.getSystemClassLoader()
);

var myModule = controller.layer().findModule("my.module").orElseThrow();
var clazz = Class.forName(myModule, "com.example.MyClass");
```

## 五、Spring 中的反射

### 5.1 @Autowired 注入

Spring 通过反射实现依赖注入：

```java
// Spring 底层大致流程：
// 1. 扫描 @Autowired/@Inject 注解的字段
// 2. field.setAccessible(true)
// 3. 从 BeanFactory 获取依赖的 Bean
// 4. field.set(bean, dependency)
```

### 5.2 AOP 代理选择

Spring AOP 的代理策略：
- **如果目标类实现了接口**：默认使用 JDK 动态代理
- **如果目标类没有接口**：使用 CGLIB 生成子类代理
- **Spring Boot 4.x 默认行为**：`spring.aop.proxy-target-class=true`，强制 CGLIB

```java
@Service
public class UserService {
    @Transactional
    public void createUser(UserDto dto) { /* ... */ }
}

// Spring 创建代理后的调用链：
// caller → UserService$$SpringCGLIB$$0.createUser()
//        → TransactionInterceptor.invoke()
//        → 开启事务 → target.createUser() → 提交/回滚事务
```

### 5.3 Bean 实例化

Spring 通过反射创建 Bean 实例，支持多种方式：
1. 无参构造 + setter 注入（传统）
2. 构造函数注入（推荐）
3. 工厂方法（@Bean 注解）

## 六、AI 场景中的应用

### 6.1 动态 Tool 注册（反射扫描 @Tool 注解）

```java
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
@interface Tool {
    String name();
    String description();
}

class ToolRegistry {
    private final Map<String, Method> tools = new ConcurrentHashMap<>();
    private final Map<String, Object> instances = new ConcurrentHashMap<>();

    // 扫描并注册所有带 @Tool 注解的方法
    public void scanPackage(String basePackage) {
        var scanner = new ClassPathScanningCandidateComponentProvider(false);
        scanner.addIncludeFilter(new AnnotationTypeFilter(Component.class));
        for (var beanDef : scanner.findCandidateComponents(basePackage)) {
            try {
                var clazz = Class.forName(beanDef.getBeanClassName());
                for (var method : clazz.getDeclaredMethods()) {
                    var toolAnno = method.getAnnotation(Tool.class);
                    if (toolAnno != null) {
                        method.setAccessible(true);
                        tools.put(toolAnno.name(), method);
                        instances.put(toolAnno.name(),
                            clazz.getDeclaredConstructor().newInstance());
                    }
                }
            } catch (ReflectiveOperationException e) {
                throw new RuntimeException("Failed to register tools", e);
            }
        }
    }

    // 通过名称调用工具
    public String execute(String toolName, String input) {
        var method = tools.get(toolName);
        var instance = instances.get(toolName);
        try {
            return (String) method.invoke(instance, input);
        } catch (ReflectiveOperationException e) {
            throw new RuntimeException("Tool execution failed: " + toolName, e);
        }
    }
}
```

### 6.2 JSON Schema 自动生成（反射提取参数类型）

```java
// 使用反射从工具方法自动生成 JSON Schema
public class JsonSchemaGenerator {

    public String generateSchema(Method method) {
        var schema = new HashMap<String, Object>();
        schema.put("type", "object");

        var properties = new HashMap<String, Object>();
        var required = new ArrayList<String>();

        for (var param : method.getParameters()) {
            var paramSchema = new HashMap<String, Object>();
            var type = mapToJsonType(param.getType());
            paramSchema.put("type", type);
            if (param.isAnnotationPresent(NotNull.class)) {
                required.add(param.getName());
            }
            properties.put(param.getName(), paramSchema);
        }

        schema.put("properties", properties);
        if (!required.isEmpty()) {
            schema.put("required", required);
        }

        return new ObjectMapper().writeValueAsString(schema);
    }

    private String mapToJsonType(Class<?> javaType) {
        if (javaType == String.class) return "string";
        if (javaType == int.class || javaType == Integer.class) return "integer";
        if (javaType == double.class || javaType == Double.class) return "number";
        if (javaType == boolean.class || javaType == Boolean.class) return "boolean";
        if (javaType.isArray() || Collection.class.isAssignableFrom(javaType)) return "array";
        return "object";
    }
}
```

## 常见问题

**Q: setAccessible(true) 有什么安全风险？**
A: 绕过了 Java 的访问控制检查，可能暴露内部实现细节。JDK 17+ 默认对 `java.*` 类的 `setAccessible` 有限制（需要 `--add-opens` JVM 参数）。生产环境中应避免对 JDK 内部类使用 `setAccessible`。

**Q: MethodHandle 什么时候优于反射？**
A: 当方法被高频调用时（如框架的核心路径），MethodHandle 的性能优势才会显现。对于一次性调用（如启动时的配置读取），反射完全够用。

**Q: 模块化一定比 classpath 好吗？**
A: 对于大型单体应用和 JDK 本身，模块化的强封装、可靠配置和更好的性能（JLink 裁剪 JRE）是显著优势。但对小型应用和遗留系统，classpath 更加灵活，迁移成本高。

**Q: 反射在模块化系统中还能用吗？**
A: 可以，但受限于 `opens` 声明。Spring 框架通过大量 `--add-opens` 参数和内置的 `ReflectionUtils` 来适配模块化环境。
