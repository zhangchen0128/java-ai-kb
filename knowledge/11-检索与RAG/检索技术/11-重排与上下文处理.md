# 重排与上下文处理：从Cross-Encoder到Lost in the Middle

## 概述

混合检索返回的Top-20结果中，通常只有前5条真正相关。重排（Reranking）使用更精确的模型对检索结果重新打分，是提升RAG质量最具性价比的步骤。本文从Cross-Encoder与Bi-Encoder的架构差异出发，深入剖析重排的数学原理，覆盖Cohere Rerank、BGE-Reranker等主流模型，并探讨上下文压缩、去重、排序优化等关键处理策略。

---

## 一、重排的必要性

### 1.1 检索与重排的性能鸿沟

| 阶段 | 模型 | 准确度(MRR) | 速度 | 规模 |
|------|------|-------------|------|------|
| 检索(Retrieval) | Bi-Encoder | 0.70-0.80 | 1-10ms | 百万级 |
| 重排(Reranking) | Cross-Encoder | 0.85-0.95 | 50-200ms | Top-20/50 |

**关键数据**：向量检索Top-20的MRR约0.75，经过Cross-Encoder重排后Top-5的MRR提升到0.90+。

### 1.2 为什么重排是性价比最高的步骤

```
成本对比（单次查询）：
- 检索 100万文档 × Embedding(768维): ~0.01 USD
- 重排 Top-20 × Cross-Encoder: ~0.0001 USD
- LLM生成 1K tokens: ~0.002 USD (GPT-4o-mini级)

效果提升（MRR）：
- 纯检索: 0.75
- +重排: 0.90 (+20%)
- +高级RAG模式: 0.93 (+3%)
```

**结论**：在检索和LLM生成之间插入重排，成本增加可忽略，效果提升显著。

## 二、Cross-Encoder vs Bi-Encoder 原理对比

### 2.1 架构差异

**Bi-Encoder（检索阶段）**：
```
Query  → Encoder → q_vec ─┐
                            ├─ cosine_sim → score
Doc    → Encoder → d_vec ─┘
```
- Query和Document**独立编码**
- 相似度计算：$cos(q, d) = \frac{q \cdot d}{|q||d|}$
- 时间复杂度：编码 $O(n+m)$（n=query数, m=doc数）
- 可以预先计算所有文档的向量并索引

**Cross-Encoder（重排阶段）**：
```
[Query, Document] → Encoder → [CLS] → Linear → score
```
- Query和Document**联合编码**
- 通过Attention机制实现Query-Document的词级交互
- 时间复杂度：$O(n \times m)$，每个query-document对都需要前向传播
- 无法预计算，必须实时推理

### 2.2 Cross-Encoder为何更准确

1. **全注意力交叉**：Query的每个Token与Document的每个Token计算Attention，捕获细粒度的语义匹配
2. **联合语义理解**：模型看到完整的`[CLS] query [SEP] document [SEP]`输入，而非分离的向量
3. **可学习的交互模式**：训练时学习到"什么构成相关"而不仅是"语义相似"

**数学本质**：
- Bi-Encoder: $score = f(q) \cdot f(d)$ — 点积的线性可分性有限
- Cross-Encoder: $score = g([q, d])$ — g可以是任意复杂函数（通过Transformer建模）

### 2.3 为什么不能全量Cross-Encoder

假设10万文档，100 token/query，500 token/doc：
- Bi-Encoder检索：预计算10万个768维向量，查询时1次前向传播 + 1次ANNS ≈ 10ms
- Cross-Encoder全量：10万次前向传播 ≈ $10^5 \times 100$ms = 10000秒 ≈ 2.8小时

**两阶段检索的必要性**：Bi-Encoder粗筛 → Cross-Encoder精排。

## 三、主流Reranker模型

### 3.1 Cohere Rerank（API）

```java
import java.net.URI;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;
import java.util.List;

public class CohereReranker {

    private final HttpClient client = HttpClient.newHttpClient();
    private final String apiKey;
    private final String apiUrl = "https://api.cohere.com/v2/rerank";

    public CohereReranker(String apiKey) {
        this.apiKey = apiKey;
    }

    public record RerankResult(int index, double relevanceScore,
                                String document) {}

    /**
     * Cohere Rerank v2 API 调用
     * @param query 查询文本
     * @param documents 待重排的文档列表（Top-20/50的检索结果）
     * @param topN 返回前N个结果
     * @param model 模型名："rerank-v3.5" | "rerank-multilingual-v3.0"
     */
    public List<RerankResult> rerank(String query, List<String> documents,
                                      int topN, String model) throws Exception {
        var jsonBody = """
            {
                "model": "%s",
                "query": "%s",
                "documents": %s,
                "top_n": %d,
                "return_documents": true
            }
            """.formatted(model, escapeJson(query), toJsonArray(documents), topN);

        var request = HttpRequest.newBuilder()
            .uri(URI.create(apiUrl))
            .header("Content-Type", "application/json")
            .header("Authorization", "Bearer " + apiKey)
            .header("Accept", "application/json")
            .POST(HttpRequest.BodyPublishers.ofString(jsonBody))
            .build();

        var response = client.send(request, HttpResponse.BodyHandlers.ofString());

        if (response.statusCode() != 200) {
            throw new RuntimeException("Cohere Rerank API error: " + response.body());
        }

        return parseResponse(response.body());
    }

    private List<RerankResult> parseResponse(String json) throws Exception {
        var mapper = new com.fasterxml.jackson.databind.ObjectMapper();
        var root = mapper.readTree(json);
        var results = root.get("results");

        var list = new java.util.ArrayList<RerankResult>();
        for (var result : results) {
            list.add(new RerankResult(
                result.get("index").asInt(),
                result.get("relevance_score").asDouble(),
                result.has("document") ? result.get("document").get("text").asText() : ""
            ));
        }
        return list;
    }

    private String escapeJson(String text) {
        return text.replace("\\", "\\\\").replace("\"", "\\\"")
                   .replace("\n", "\\n").replace("\r", "\\r");
    }

    private String toJsonArray(List<String> docs) {
        var mapper = new com.fasterxml.jackson.databind.ObjectMapper();
        try {
            return mapper.writeValueAsString(docs);
        } catch (Exception e) {
            throw new RuntimeException(e);
        }
    }
}
```

**Cohere Rerank性能数据**：

- 定价：$2/1M searches（约$0.00004/次，20个文档）

## 四、完整重排流程

```java
public class RerankingPipeline {

    private final CohereReranker cohereReranker;
    private final BgeRerankerClient bgeClient;

    // 双层层叠Reranker（可选）：先用快速Reranker缩减到20，再用精确Reranker
    public record RerankedChunk(
        String chunkId,
        String content,
        double relevanceScore,
        int originalRank,       // 在检索结果中的排名
        int rerankedRank,       // 重排后的排名
        double originalScore,   // 原始检索分数
        Map<String, Object> metadata
    ) {}

    /**
     * 标准重排流程：检索Top-50 → Reranker打分 → 取Top-10
     */
    public List<RerankedChunk> rerankPipeline(
            String query,
            List<HybridSearchService.RankedResult> retrievalResults,
            int rerankTopN) {

        // 1. 提取前50条的内容（50是经验值：平衡延迟和召回）
        var topNResults = retrievalResults.stream()
            .limit(50)
            .toList();

        var documents = topNResults.stream()
            .map(r -> r.content())
            .toList();

        // 2. 调用Reranker
        List<CohereReranker.RerankResult> rerankResults;
        try {
            // 优先使用Cohere（多语言支持好）
            rerankResults = cohereReranker.rerank(
                query, documents, rerankTopN, "rerank-multilingual-v3.0"
            );
        } catch (Exception e) {
            // Fallback到本地BGE-Reranker
            try {
                var bgeResults = bgeClient.rerank(query, documents);
                rerankResults = bgeResults.stream()
                    .map(r -> new CohereReranker.RerankResult(r.index(), r.score(), r.text()))
                    .toList();
            } catch (Exception ex) {
                // 最终Fallback：信任原始检索排序
                return topNResults.stream()
                    .limit(rerankTopN)
                    .map(r -> new RerankedChunk(
                        r.chunkId(), getContent(r.chunkId()),
                        1.0 - (double) topNResults.indexOf(r) / topNResults.size(),
                        topNResults.indexOf(r) + 1, topNResults.indexOf(r) + 1,
                        r.score(), Map.of()
                    ))
                    .toList();
            }
        }

        // 3. 构建带重排分数和原始检索分数的结果
        var reranked = new java.util.ArrayList<RerankedChunk>();
        for (int i = 0; i < rerankResults.size(); i++) {
            var rr = rerankResults.get(i);
            var original = topNResults.get(rr.index());
            reranked.add(new RerankedChunk(
                original.chunkId(),
                rr.document(),
                rr.relevanceScore(),
                rr.index() + 1,
                i + 1,
                original.score(),
                Map.of()
            ));
        }

        return reranked;
    }

    /**
     * 相关性阈值过滤：Reranker分数 < threshold 的结果丢弃
     * 防止不相关内容进入LLM上下文窗口
     */
    public List<RerankedChunk> filterByThreshold(
            List<RerankedChunk> results, double threshold) {
        return results.stream()
            .filter(r -> r.relevanceScore() >= threshold)
            .toList();
    }

    private String getContent(String chunkId) { return ""; }
}
```

### 4.1 重排的延迟优化

```java
/**
 * 并行重排：将20个文档分为多组并行调用Reranker
 * 适用于本地Cross-Encoder模型（独立推理，非batch模式）
 */
public class ParallelReranker {

    private final BgeRerankerClient bgeClient;

    public List<RerankedChunk> parallelRerank(
            String query, List<String> documents, int batchSize) {

        var batches = new java.util.ArrayList<List<String>>();
        for (int i = 0; i < documents.size(); i += batchSize) {
            batches.add(documents.subList(i,
                Math.min(i + batchSize, documents.size())));
        }

        // 使用Virtual Threads并行处理
        var results = new java.util.concurrent.ConcurrentLinkedQueue<RerankedChunk>();

        try (var executor = java.util.concurrent.Executors.newVirtualThreadPerTaskExecutor()) {
            var futures = batches.stream()
                .map(batch -> executor.submit(() -> {
                    try {
                        var batchResults = bgeClient.rerank(query, batch);
                        return batchResults;
                    } catch (Exception e) {
                        return List.<BgeRerankerClient.RerankResult>of();
                    }
                }))
                .toList();

            for (var future : futures) {
                try {
                    for (var r : future.get(10, java.util.concurrent.TimeUnit.SECONDS)) {
                        results.add(new RerankedChunk(
                            "", r.text(), r.score(), r.index(), r.index(), 0, Map.of()
                        ));
                    }
                } catch (Exception e) {
                    // 超时或失败，跳过该批
                }
            }
        }

        return results.stream()
            .sorted((a, b) -> Double.compare(b.relevanceScore(), a.relevanceScore()))
            .toList();
    }
}
```

## 五、上下文处理策略

### 5.1 Lost in the Middle 现象

**核心发现（Liu et al., 2023）**：LLM在生成长上下文答案时，对开头和结尾的信息利用最好，对中间部分的信息利用最差。

```
LLM信息利用率曲线：
  ↑
100%│  ████
    │  █  █
 85%│  █  █  █
    │  █  █  █  █
 60%│  █  █  █  █  █████
    │  █  █  █  █  █  █  ████
    └──┴──┴──┴──┴──┴──┴──┴──┴──→ 上下文位置
     开头                   结尾
```

**应对策略**：将最重要的检索结果放在Prompt的开头和结尾。

```java
/**
 * 上下文排序优化器：对抗 Lost in the Middle
 */
public class ContextArranger {

    /**
     * 最佳排列策略：
     * - 最高相关度的放在开头（模型最先看到）
     * - 次高相关度的放在结尾（模型最后看到，短期记忆最强）
     * - 中等相关度的放在中间
     *
     * 排列模式：[Best, Good4, Good5, ..., Good2, Good3, Better]
     */
    public List<RerankedChunk> arrangeForLlm(List<RerankedChunk> chunks) {
        if (chunks.size() <= 2) return chunks;

        var sorted = chunks.stream()
            .sorted((a, b) -> Double.compare(b.relevanceScore(), a.relevanceScore()))
            .toList();

        var arranged = new java.util.ArrayList<RerankedChunk>();

        // 最重要的放第一个
        arranged.add(sorted.get(0));

        // 中等相关的顺序不变
        for (int i = sorted.size() - 1; i >= 2; i--) {
            arranged.add(sorted.get(i));
        }

        // 第二重要的放最后一个
        if (sorted.size() >= 2) {
            arranged.add(sorted.get(1));
        }

        return arranged;
    }
}
```

### 5.2 上下文压缩（LLMLingua思想）

```java
/**
 * 轻量级上下文压缩器
 * 基于提示词感知的token级别压缩
 * 不依赖LLM，使用简单的启发式规则
 */
public class LightweightContextCompressor {

    private final int maxContextTokens;  // 上下文窗口预算
    private final double compressionRatio; // 目标压缩率

    public LightweightContextCompressor(int maxContextTokens, double compressionRatio) {
        this.maxContextTokens = maxContextTokens;
        this.compressionRatio = compressionRatio;
    }

    /**
     * 压缩上下文：在保留关键信息的前提下减少token数
     * 策略：
     * 1. 去掉重复句子
     * 2. 合并相似内容
     * 3. 保留高信息密度句子
     */
    public String compress(List<RerankedChunk> chunks, String query) {
        var totalTokens = chunks.stream().mapToInt(c -> c.content().length() / 2).sum();
        if (totalTokens <= maxContextTokens) {
            // 不需要压缩
            return buildContext(chunks);
        }

        // 按相关性权重压缩：高相关chunk保留更多内容，低相关chunk压缩更多
        var builder = new StringBuilder();
        var budget = maxContextTokens;

        for (var chunk : chunks) {
            var estimatedTokens = chunk.content().length() / 2;
            var allocatedTokens = (int) (budget * chunk.relevanceScore()
                / chunks.stream().mapToDouble(RerankedChunk::relevanceScore).sum());

            if (allocatedTokens >= estimatedTokens) {
                // 预算充足，保留完整内容
                builder.append(chunk.content()).append("\n\n");
                budget -= estimatedTokens;
            } else {
                // 需要压缩：提取关键句
                var compressed = extractKeySentences(chunk.content(), query, allocatedTokens);
                builder.append(compressed).append("\n\n");
                budget -= allocatedTokens;
            }
        }

        return builder.toString();
    }

    /**
     * 提取关键句子：基于与Query的词汇重叠
     * 更精确的做法是使用Cross-Encoder计算句子级相关性
     */
    private String extractKeySentences(String text, String query, int maxTokens) {
        var queryWords = new java.util.HashSet<>(
            java.util.Arrays.asList(query.toLowerCase().split("\\s+"))
        );

        // 按句子拆分
        var sentences = text.split("(?<=[。！？.!?])");
        record ScoredSentence(String text, double score) {}

        var scored = java.util.Arrays.stream(sentences)
            .map(s -> {
                var words = s.toLowerCase().split("\\s+");
                var overlap = java.util.Arrays.stream(words)
                    .filter(queryWords::contains)
                    .count();
                var density = words.length > 0 ? (double) overlap / words.length : 0;
                return new ScoredSentence(s.trim(), density);
            })
            .sorted((a, b) -> Double.compare(b.score(), a.score()))
            .toList();

        var result = new StringBuilder();
        int tokenCount = 0;
        for (var s : scored) {
            var estTokens = s.text().length() / 2;
            if (tokenCount + estTokens > maxTokens) break;
            result.append(s.text());
            tokenCount += estTokens;
        }

        return result.toString();
    }

    private String buildContext(List<RerankedChunk> chunks) {
        return chunks.stream()
            .map(RerankedChunk::content)
            .collect(java.util.stream.Collectors.joining("\n\n"));
    }
}
```

### 5.3 去重处理

```java
/**
 * 检索结果去重
 */
public class ContextDeduplicator {

    /**
     * 基于Jaccard相似度去重
     * 当两个chunk的Jaccard相似度超过阈值时，保留相关性更高的
     */
    public List<RerankedChunk> deduplicate(
            List<RerankedChunk> chunks, double threshold) {
        var result = new java.util.ArrayList<RerankedChunk>();

        for (var chunk : chunks) {
            var isDuplicate = false;
            for (var existing : result) {
                var jaccard = jaccardSimilarity(chunk.content(), existing.content());
                if (jaccard > threshold) {
                    isDuplicate = true;
                    // 如果新chunk相关性更高，替换旧的
                    if (chunk.relevanceScore() > existing.relevanceScore()) {
                        result.set(result.indexOf(existing), chunk);
                    }
                    break;
                }
            }
            if (!isDuplicate) {
                result.add(chunk);
            }
        }

        return result;
    }

    private double jaccardSimilarity(String a, String b) {
        var wordsA = new java.util.HashSet<>(
            java.util.Arrays.asList(a.toLowerCase().split("\\s+"))
        );
        var wordsB = new java.util.HashSet<>(
            java.util.Arrays.asList(b.toLowerCase().split("\\s+"))
        );

        var intersection = new java.util.HashSet<>(wordsA);
        intersection.retainAll(wordsB);

        var union = new java.util.HashSet<>(wordsA);
        union.addAll(wordsB);

        return union.isEmpty() ? 0 : (double) intersection.size() / union.size();
    }
}
```

```java
    ) {}

    /**
     * 为LLM响应添加引用标记
     * 策略：在LLM的Prompt中要求使用 [1], [2] 格式引用来源
     * LLM响应后，从响应中提取引用编号并关联到具体的chunk
     */
    public String buildCitationPrompt(List<RerankedChunk> chunks) {
        var builder = new StringBuilder();
        builder.append("请根据以下参考资料回答问题，并在答案中使用 [1], [2] 等编号标注信息来源。\n\n");

        for (int i = 0; i < chunks.size(); i++) {
            var chunk = chunks.get(i);
            builder.append("参考资料 [%d]:\n".formatted(i + 1));
            if (chunk.metadata().get("section_path") != null) {
                builder.append("来源: %s\n".formatted(chunk.metadata().get("section_path")));
            }
            builder.append(chunk.content()).append("\n\n");
        }

        return builder.toString();
    }

    /**
     * 从LLM响应中提取引用编号并验证
     */
    public List<Citation> extractCitations(String llmResponse,
                                            List<RerankedChunk> chunks) {
        var citations = new java.util.ArrayList<Citation>();
        var pattern = java.util.regex.Pattern.compile("\\[(\\d+)\\]");
        var matcher = pattern.matcher(llmResponse);
        var seen = new java.util.HashSet<Integer>();

        while (matcher.find()) {
            var num = Integer.parseInt(matcher.group(1));
            if (!seen.contains(num) && num > 0 && num <= chunks.size()) {
                seen.add(num);
                var chunk = chunks.get(num - 1);
                citations.add(new Citation(
                    num, chunk.chunkId(),
                    (String) chunk.metadata().getOrDefault("title", "未知文档"),
                    (String) chunk.metadata().getOrDefault("section_path", ""),
                    (int) chunk.metadata().getOrDefault("page_number", 0),
                    chunk.content().substring(0, Math.min(200, chunk.content().length())),
                    0, Math.min(200, chunk.content().length())
                ));
            }
        }

        return citations;
    }
}
```

## 七、完整RerankerService

```java
import org.springframework.stereotype.Service;
import java.util.List;

@Service
public class RerankerService {

    private final CohereReranker primaryReranker;
    private final BgeRerankerClient fallbackReranker;
    private final ContextDeduplicator deduplicator;
    private final ContextArranger arranger;

    public RerankerService(
            CohereReranker primaryReranker,
            BgeRerankerClient fallbackReranker) {
        this.primaryReranker = primaryReranker;
        this.fallbackReranker = fallbackReranker;
        this.deduplicator = new ContextDeduplicator();
        this.arranger = new ContextArranger();
    }

    /**
     * 完整的检索后处理管道：
     * 检索结果 → 去重 → 重排打分 → 阈值过滤 → Lost-in-Middle排序 → 返回
     */
    public List<RerankedChunk> processRetrievalResults(
            String query,
            List<HybridSearchService.RankedResult> retrievalResults) {

        // 1. 重排打分
        var pipeline = new RerankingPipeline(primaryReranker, fallbackReranker);
        var reranked = pipeline.rerankPipeline(query, retrievalResults, 10);

        // 2. 去重
        reranked = deduplicator.deduplicate(reranked, 0.85);

        // 3. 相关性阈值过滤（低于0.1的结果基本不相关）
        reranked = pipeline.filterByThreshold(reranked, 0.1);

        // 4. Lost-in-Middle排序优化
        reranked = arranger.arrangeForLlm(reranked);

        return reranked;
    }
}
```

## 八、最佳实践

1. **默认启用重排**：成本极低（<5%总成本），效果提升显著（+15-20% MRR）
2. **检索50条，重排后取10条**：经验值，平衡延迟和召回
3. **优先使用Cohere Rerank（多语言）或BGE-Reranker（本地）**：前者省心，后者省钱
4. **添加相关性阈值**：<0.1的结果直接丢弃，减少上下文噪音
5. **对抗Lost in the Middle**：最重要内容放开头和结尾
6. **引用规范化**：统一使用`[1]`、`[2]`格式，确保可追溯

## 九、反模式

- **跳过重排直接喂LLM**：浪费上下文窗口，答案质量差
- **重排时传入全部检索结果（100+）**：延迟线性增长，20-50条是最佳平衡点
- **只依赖Reranker分数不设阈值**：低分chunk可能误导LLM
- **Cross-Encoder batch size设为1**：大部分模型支持batch推理，batch=20比batch=1快5倍
