# 向量检索与混合检索：从HNSW到RRF融合

## 概述

检索是RAG系统的核心环节。现代检索系统通常结合两种范式：稠密向量检索（语义匹配）和稀疏关键词检索（精确匹配）。本文从向量检索的底层索引结构（HNSW、IVFFlat）出发，推导BM25的数学原理，最终构建完整的混合检索+RRF融合方案，并提供在PostgreSQL pgvector和Elasticsearch上的完整Java实现。

---

## 一、向量检索原理

### 1.1 ANN vs KNN

**KNN (K-Nearest Neighbors)**：
- 精确检索：扫描所有向量，计算距离，返回Top-K
- 复杂度：O(N×D)，N为向量数量，D为维度
- 百万级向量 → 秒级延迟 → 不可接受

**ANN (Approximate Nearest Neighbors)**：
- 近似检索：牺牲少量精度换取数量级的速度提升
- 典型精度损失：<1%（召回率99%+）
- 百万级向量 → 毫秒级延迟

### 1.2 pgvector支持的索引类型对比

| 特性 | IVFFlat | HNSW |
|------|---------|------|
| 构建时间 | 快 | 较慢 |
| 查询速度 | 较慢 | 快 |
| 内存占用 | 低 | 高（需要存储图结构） |
| 召回率 | 95-99% | 99%+ |
| 构建参数 | lists | m, ef_construction |
| 查询参数 | probes | ef_search |
| 增量更新 | 需要重建 | 支持 |
| 适用规模 | 100K-10M | 10K-100M |

## 二、HNSW索引深入

### 2.1 图结构

HNSW (Hierarchical Navigable Small World) 构建一个多层图：

```
Layer 2:  ●──────●        （最顶层，节点最少，长距离连接）
         /        \
Layer 1: ●──●──●──●──●    （中间层）
        / \/ \/ \/ \/ \
Layer 0: ●─●─●─●─●─●─●─●  （底层，所有节点，短距离连接）
```

**关键参数**：
- **M (max_connections)**：每个节点每层的最大连接数。典型值16-64。更大的M → 更高召回率 + 更多内存。
- **ef_construction**：构建索引时的动态候选列表大小。典型值128-512。更大的值 → 更高质量的图 + 更长的构建时间。
- **ef_search**：搜索时的动态候选列表大小。典型值64-256。更大的值 → 更高召回率 + 更多搜索延迟。

### 2.2 插入算法

```
function INSERT(new_element, HNSW_graph):
    L = random_level()  // 随机选择层级（指数衰减分布）
    entry_point = get_entry_point()
    
    for lc from max_level down to L+1:
        // 在高层找到最近的入口点
        entry_point = greedy_search(new_element, entry_point, 1, lc)
    
    for lc from min(L, max_level) down to 0:
        // 在当前层搜索ef_construction个最近邻
        candidates = search_layer(new_element, entry_point, ef_construction, lc)
        // 启发式邻居选择：挑选多样化的邻居
        neighbors = select_neighbors_heuristic(new_element, candidates, M, lc)
        // 添加双向连接
        for neighbor in neighbors:
            connect(new_element, neighbor)
            // 裁剪：如果neighbor的连接数超过M，剪掉最远的
            if |neighbor.connections(lc)| > M:
                prune_neighbors(neighbor, lc)
```

### 2.3 搜索算法

```
function SEARCH(query, k, ef_search):
    entry_point = get_entry_point()
    
    // 从顶层开始，逐层下降
    for lc from max_level down to 1:
        entry_point = greedy_search(query, entry_point, 1, lc)
    
    // 在底层做精细搜索
    candidates = search_layer(query, entry_point, ef_search, 0)
    
    // 从candidates中取前k个作为结果
    return top_k(candidates, k)
```

## 三、IVFFlat索引

### 3.1 工作原理

IVFFlat (Inverted File with Flat compression) 将向量空间划分为K个聚类区域：

1. **训练阶段**：对数据集的子集运行K-means聚类，得到K个聚类中心
2. **索引阶段**：将每个向量分配到最近的聚类中心，构建倒排列表
3. **查询阶段**：找到距离查询向量最近的`nprobe`个聚类中心，只在这些聚类中搜索

```
向量空间划分：
    Cluster 1: [v11, v12, v13, ...]  ← 倒排列表 1
    Cluster 2: [v21, v22, ...]       ← 倒排列表 2
    ...
    Cluster K: [vK1, vK2, ...]       ← 倒排列表 K

查询过程：
    query → 计算与K个聚类中心的距离
         → 选最近的nprobe个聚类
         → 在这nprobe个聚类的所有向量中精确搜索
```

### 3.2 pgvector IVFFlat配置

```sql
-- 创建IVFFlat索引（需要先有数据用于训练）
CREATE INDEX ON chunk_embeddings
    USING ivfflat (embedding vector_cosine_ops)
    WITH (lists = 100);  -- 聚类数K，典型值：rows/1000

-- 查询时设置探测数
SET ivfflat.probes = 10; -- 探测最近的nprobe个聚类，典型值：sqrt(lists)
```

**IVFFlat vs HNSW选择建议**：

```
数据量 < 100K + 需要频繁增量更新 → HNSW
数据量 > 10M + 内存受限 → IVFFlat
召回率要求 > 99% → HNSW
构建时间敏感 → IVFFlat
```

## 四、BM25稀疏检索

### 4.1 从TF-IDF到BM25的演变

**TF-IDF的缺陷**：
1. 词频线性增长：一个词出现10次的文档权重是出现1次的10倍，不符合实际
2. 无文档长度归一化：长文档天然有更高的匹配机会
3. 参数不可调：无法针对场景优化

**BM25的改进**：引入词频饱和函数和文档长度归一化参数。

### 4.2 BM25公式分解

$$BM25(D, Q) = \sum_{i=1}^{n} IDF(q_i) \times \frac{f(q_i, D) \times (k_1 + 1)}{f(q_i, D) + k_1 \times (1 - b + b \times \frac{|D|}{avgdl})}$$

其中：
- $IDF(q_i)$：逆文档频率，衡量词$q_i$的稀有度
- $f(q_i, D)$：词$q_i$在文档$D$中的频率
- $|D|$：文档长度
- $avgdl$：所有文档的平均长度
- $k_1$：词频饱和参数（典型值1.2-2.0）。$k_1=0$时退化为二值（出现/不出现）
- $b$：文档长度归一化参数（典型值0.75）。$b=0$时不归一化，$b=1$时完全归一化

**IDF的具体公式（Lucene/ES使用）**：
$$IDF(q_i) = \ln\left(1 + \frac{N - n(q_i) + 0.5}{n(q_i) + 0.5}\right)$$

其中$N$为文档总数，$n(q_i)$为包含词$q_i$的文档数。

### 4.3 Elasticsearch BM25实现

```java
import co.elastic.clients.elasticsearch.ElasticsearchClient;
import co.elastic.clients.elasticsearch.core.SearchResponse;
import co.elastic.clients.elasticsearch.core.search.Hit;
import co.elastic.clients.json.jackson.JacksonJsonpMapper;
import co.elastic.clients.transport.rest_client.RestClientTransport;
import org.elasticsearch.client.RestClient;

public class ElasticsearchBm25Search {

    private final ElasticsearchClient esClient;

    public ElasticsearchBm25Search(String esUrl) {
        var restClient = RestClient.builder(
            java.net.http.HttpClient.newHttpClient()  // 简化示例
        );
        // 实际项目中使用RestClient.builder(HttpHost.create(esUrl)).build()
        this.esClient = null; // 实际初始化
    }

    /**
     * BM25检索
     */
    public record SearchResult(String chunkId, String content,
                                double score, Map<String, Object> highlights) {}

    public List<SearchResult> bm25Search(String query, String indexName, int size) throws Exception {
        var response = esClient.search(s -> s
            .index(indexName)
            .query(q -> q
                .match(m -> m
                    .field("content")
                    .query(query)
                )
            )
            .size(size)
            .highlight(h -> h
                .fields("content", hf -> hf
                    .fragmentSize(150)
                    .numberOfFragments(3)
                )
            )
            .explain(true), // 开启explain查看BM25计算细节
            Map.class
        );

        return response.hits().hits().stream()
            .map(hit -> new SearchResult(
                (String) hit.source().get("chunk_id"),
                (String) hit.source().get("content"),
                hit.score() != null ? hit.score() : 0.0,
                hit.highlight() != null ? hit.highlight() : Map.of()
            ))
            .toList();
    }

    /**
     * 使用explain API查看BM25打分细节（调试用）
     */
    public String explainScore(String query, String documentId, String indexName) throws Exception {
        var response = esClient.explain(e -> e
            .index(indexName)
            .id(documentId)
            .query(q -> q.match(m -> m.field("content").query(query)))
        );
        return response.explanation().toString();
    }
}
```

## 五、混合检索与RRF融合

### 5.1 稠密+稀疏的互补性

| 特性 | 稠密检索（向量） | 稀疏检索（BM25） |
|------|-----------------|-----------------|
| 匹配方式 | 语义相似度 | 关键词精确匹配 |
| 优势 | 同义词、改写、语义理解 | 专有名词、代码、术语精确匹配 |
| 劣势 | 对罕见词不敏感 | 对语义改写不敏感 |
| 适合Query类型 | 自然语言问句 | 关键词搜索、实体查询 |

**核心洞察**：两种检索方式的错误模式不同，融合后可以互补。

### 5.2 RRF (Reciprocal Rank Fusion)

RRF是当前最常用的融合策略，不依赖分数的绝对值（向量相似度与BM25分数的量纲不同）。

$$RRF(d) = \sum_{r \in R} \frac{1}{k + rank_r(d)}$$

其中：
- $R$：参与融合的排序列表集合
- $rank_r(d)$：文档$d$在排序列表$r$中的排名（从1开始）
- $k$：平滑参数，经典默认值60。$k \to 0$时排名差距越大权重差异越大

**RRF计算示例**：

```
文档A: 向量检索排名1, BM25排名3
  RRF(A) = 1/(60+1) + 1/(60+3) = 0.01639 + 0.01587 = 0.03226

文档B: 向量检索排名2, BM25排名1
  RRF(B) = 1/(60+2) + 1/(60+1) = 0.01613 + 0.01639 = 0.03252

B排在A前面，虽然A的向量排名更高
```

### 5.3 Java实现 — RRF融合算法

```java
import java.util.*;
import java.util.stream.Collectors;

public class HybridSearchService {

    /**
     * 混合检索结果
     */
    public record HybridSearchResult(
        String chunkId,
        String content,
        double rrfScore,
        double vectorScore,    // 原始向量相似度
        double bm25Score,      // 原始BM25分数
        int vectorRank,
        int bm25Rank,
        Map<String, Object> metadata
    ) {}

    /**
     * 执行混合检索 + RRF融合
     */
    public List<HybridSearchResult> hybridSearch(
            String query, float[] queryEmbedding,
            String tenantId, List<String> accessLevels,
            int topK) {

        // 1. 向量检索（pgvector）
        var vectorResults = vectorSearch(queryEmbedding, tenantId, accessLevels, topK * 2);

        // 2. BM25检索（Elasticsearch或PostgreSQL ts_rank）
        var bm25Results = bm25Search(query, tenantId, accessLevels, topK * 2);

        // 3. RRF融合
        return rrfFusion(vectorResults, bm25Results, 60, topK);
    }

    /**
     * RRF融合核心算法
     * @param k RRF平滑参数，默认60
     */
    public List<HybridSearchResult> rrfFusion(
            List<RankedResult> vectorResults,
            List<RankedResult> bm25Results,
            int k, int topK) {

        // 构建 chunkId → RRF累积分数 的映射
        var rrfScores = new HashMap<String, RrfAccumulator>();

        // 处理向量检索结果
        for (int i = 0; i < vectorResults.size(); i++) {
            var r = vectorResults.get(i);
            var acc = rrfScores.computeIfAbsent(r.chunkId(), id -> new RrfAccumulator());
            acc.addVectorScore(r.score(), i + 1, k);
        }

        // 处理BM25检索结果
        for (int i = 0; i < bm25Results.size(); i++) {
            var r = bm25Results.get(i);
            var acc = rrfScores.computeIfAbsent(r.chunkId(), id -> new RrfAccumulator());
            acc.addBm25Score(r.score(), i + 1, k);
        }

        // 按RRF分数排序，取Top-K
        return rrfScores.entrySet().stream()
            .map(e -> {
                var acc = e.getValue();
                return new HybridSearchResult(
                    e.getKey(),
                    getContent(e.getKey()),
                    acc.getRrfScore(),
                    acc.vectorScore,
                    acc.bm25Score,
                    acc.vectorRank,
                    acc.bm25Rank,
                    getMetadata(e.getKey())
                );
            })
            .sorted((a, b) -> Double.compare(b.rrfScore(), a.rrfScore()))
            .limit(topK)
            .toList();
    }

    /**
     * 加权分数融合（Weighted Sum）— RRF的替代方案
     * 需要对向量相似度和BM25分数做归一化（Min-Max或Softmax）
     */
    public List<HybridSearchResult> weightedFusion(
            List<RankedResult> vectorResults,
            List<RankedResult> bm25Results,
            double vectorWeight, // 典型值0.7
            double bm25Weight,   // 典型值0.3
            int topK) {

        // Min-Max归一化
        if (vectorResults.isEmpty() || bm25Results.isEmpty()) {
            return List.of();
        }

        var vMax = vectorResults.getFirst().score();
        var vMin = vectorResults.getLast().score();
        var bMax = bm25Results.getFirst().score();
        var bMin = bm25Results.getLast().score();

        var scores = new HashMap<String, Double>();

        for (var r : vectorResults) {
            var normalized = vMax == vMin ? 1.0
                : (r.score() - vMin) / (vMax - vMin);
            scores.merge(r.chunkId(), normalized * vectorWeight, Double::sum);
        }

        for (var r : bm25Results) {
            var normalized = bMax == bMin ? 1.0
                : (r.score() - bMin) / (bMax - bMin);
            scores.merge(r.chunkId(), normalized * bm25Weight, Double::sum);
        }

        return scores.entrySet().stream()
            .sorted(Map.Entry.<String, Double>comparingByValue().reversed())
            .limit(topK)
            .map(e -> new HybridSearchResult(
                e.getKey(), getContent(e.getKey()),
                e.getValue(), 0, 0, 0, 0, getMetadata(e.getKey())
            ))
            .toList();
    }

    // --- 辅助类型 ---
    public record RankedResult(String chunkId, double score) {}

    private static class RrfAccumulator {
        double vectorScore = 0;
        double bm25Score = 0;
        int vectorRank = -1;
        int bm25Rank = -1;

        void addVectorScore(double score, int rank, int k) {
            this.vectorScore = score;
            this.vectorRank = rank;
        }

        void addBm25Score(double score, int rank, int k) {
            this.bm25Score = score;
            this.bm25Rank = rank;
        }

        double getRrfScore() {
            double sum = 0;
            if (vectorRank > 0) sum += 1.0 / (60 + vectorRank);
            if (bm25Rank > 0) sum += 1.0 / (60 + bm25Rank);
            return sum;
        }
    }

    // --- 占位方法 ---
    private List<RankedResult> vectorSearch(float[] embedding, String tenantId,
                                             List<String> accessLevels, int limit) {
        // 调用pgvector进行向量检索
        return List.of();
    }

    private List<RankedResult> bm25Search(String query, String tenantId,
                                           List<String> accessLevels, int limit) {
        // 调用Elasticsearch进行BM25检索
        return List.of();
    }

    private String getContent(String chunkId) { return ""; }
    private Map<String, Object> getMetadata(String chunkId) { return Map.of(); }
}
```

### 5.4 Elasticsearch混合检索（BM25 + kNN + RRF）

Elasticsearch 8.12+原生支持混合检索：

```java
/**
 * Elasticsearch原生混合检索 — BM25 + kNN + RRF
 */
public List<SearchResult> esHybridSearch(
        ElasticsearchClient esClient,
        String query, float[] queryEmbedding,
        String indexName, int topK) throws Exception {

    var response = esClient.search(s -> s
        .index(indexName)
        .size(topK)
        // BM25子查询
        .query(q -> q.bool(b -> b
            .should(sq -> sq.match(m -> m
                .field("content")
                .query(query)
                .boost(1.0f)
            ))
        ))
        // kNN子查询
        .knn(k -> k
            .field("embedding")
            .queryVector(Arrays.stream(queryEmbedding)
                .boxed().toList())
            .k(topK * 2)
            .numCandidates(topK * 4)
        )
        // RRF融合
        .rank(r -> r.rrf(rrf -> rrf
            .windowSize(topK * 2)
            .rankConstant(60)
        )),
        Map.class
    );

    return response.hits().hits().stream()
        .map(hit -> new SearchResult(
            (String) hit.source().get("chunk_id"),
            (String) hit.source().get("content"),
            hit.score() != null ? hit.score() : 0.0,
            Map.of()
        ))
        .toList();
}
```

### 5.5 PostgreSQL混合检索（ts_rank + pgvector + RRF）

```sql
-- PostgreSQL混合检索完整SQL
WITH vector_results AS (
    SELECT c.chunk_id, c.content,
           1 - (e.embedding <=> :query_vector::vector) AS vector_score,
           ROW_NUMBER() OVER (ORDER BY e.embedding <=> :query_vector::vector) AS vector_rank
    FROM chunk_embeddings e
    JOIN chunks c ON e.chunk_id = c.chunk_id
    WHERE c.status = 'active'
      AND c.tenant_id = :tenant_id
    ORDER BY e.embedding <=> :query_vector::vector
    LIMIT :limit
),
bm25_results AS (
    SELECT c.chunk_id, c.content,
           ts_rank(to_tsvector('chinese', c.content),
                   plainto_tsquery('chinese', :query_text)) AS bm25_score,
           ROW_NUMBER() OVER (ORDER BY
               ts_rank(to_tsvector('chinese', c.content),
                       plainto_tsquery('chinese', :query_text)) DESC
           ) AS bm25_rank
    FROM chunks c
    WHERE to_tsvector('chinese', c.content) @@ plainto_tsquery('chinese', :query_text)
      AND c.status = 'active'
      AND c.tenant_id = :tenant_id
    ORDER BY bm25_score DESC
    LIMIT :limit
),
combined AS (
    SELECT
        COALESCE(v.chunk_id, b.chunk_id) AS chunk_id,
        COALESCE(v.content, b.content) AS content,
        COALESCE(v.vector_score, 0) AS vector_score,
        COALESCE(b.bm25_score, 0) AS bm25_score,
        COALESCE(v.vector_rank, :fallback_rank) AS vector_rank,
        COALESCE(b.bm25_rank, :fallback_rank) AS bm25_rank
    FROM vector_results v
    FULL OUTER JOIN bm25_results b ON v.chunk_id = b.chunk_id
)
SELECT chunk_id, content, vector_score, bm25_score,
       (1.0 / (60 + vector_rank) + 1.0 / (60 + bm25_rank)) AS rrf_score
FROM combined
ORDER BY rrf_score DESC
LIMIT :top_k;
```

## 六、元数据过滤策略

### 6.1 Pre-filtering vs Post-filtering

**Pre-filtering（先过滤再检索）**：
```sql
-- pgvector: WHERE子句在ORDER BY之前执行
SELECT c.chunk_id, c.content,
       1 - (e.embedding <=> :query_vector) AS similarity
FROM chunk_embeddings e
JOIN chunks c ON e.chunk_id = c.chunk_id
WHERE c.tenant_id = :tenant_id           -- 过滤
  AND c.access_level IN (:access_levels)  -- 过滤
  AND c.created_at > :since               -- 过滤
ORDER BY e.embedding <=> :query_vector
LIMIT 10;
```

- **优点**：精确控制返回数量
- **缺点**：可能排除了语义相关但不满足过滤条件的文档（更安全的选择）

**Post-filtering（先检索再过滤）**：
```sql
-- 先检索更多，再在应用层过滤
SELECT ... LIMIT 50  -- 取更多
-- 然后在Java代码中过滤
```

- **优点**：不会因过滤条件漏掉潜在相关文档
- **缺点**：返回数量不可控

**最佳实践**：Pre-filtering + 适当扩大检索范围（`limit * 1.5 ~ 2`）。

### 6.2 Java实现

```java
public class FilteredSearchService {

    /**
     * Pre-filtering策略：在SQL/ES层面完成过滤
     */
    public List<HybridSearchResult> searchWithFilters(
            float[] queryEmbedding, String query,
            FilterCriteria criteria, int topK) {

        var expandedLimit = (int) (topK * 2.0); // 扩大检索范围
```

## 八、最佳实践

1. **默认使用HNSW**：召回率和速度综合最优
2. **混合检索作为标配**：BM25 + 向量 + RRF

6. **定期ANALYZE向量索引**：索引膨胀后需要维护

## 九、反模式

- **仅用向量检索**：丢失精确匹配能力
- **混合检索不融合直接拼接**：向量Top-10 + BM25 Top-10 = 20个结果缺乏统一排序
- **在应用层做元数据过滤**：检索后只剩3条，用户看不到完整结果
- **盲目增大ef_search追求召回率**：ef_search=500时延迟可能是100的5倍

## 向量数据生命周期管理

向量数据不是"一次写入、永久使用"的静态资产。从索引构建到在线查询、过期检测再到重索引，向量数据经历完整的生命周期。随着业务文档持续进入系统，必须建立增量更新 pipeline：新文档到达后触发 CDC（Change Data Capture）事件，消息队列将变更推送给 Embedding 服务重新向量化，最后通过 upsert 操作更新向量索引。pgvector 的 HNSW 索引支持增量插入，但频繁插入会导致图结构退化——节点的邻居关系逐渐偏离最优，检索性能逐步下降。

因此需要设计索引维护窗口：在业务低峰期（如凌晨 2-4 点），对 HNSW 索引执行 REINDEX CONCURRENTLY 重建，恢复最优图结构。更大的挑战是 Embedding 模型版本迁移——当 text-embedding-3-small 升级到 text-embedding-3-large 时，新旧模型产生的向量不可混用（维度可能不同，语义空间已偏移）。推荐**双写+灰度切换**方案：新模型向量写入独立索引，查询时按租户灰度比例同时查询新旧两套索引，通过 RRF 融合返回结果；待新索引覆盖全量历史数据后，逐步将流量切至 100%，最后安全下线旧索引。

```java
// JDK 25 + Spring Boot 4.x — 向量数据生命周期管理
import javax.sql.DataSource;
import java.time.*;
import java.util.*;
import java.util.concurrent.*;
import java.util.concurrent.atomic.AtomicInteger;

public class VectorLifecycleManager {

    private final DataSource dataSource;
    private final EmbeddingService embeddingService;
    private final ScheduledExecutorService scheduler =
        Executors.newSingleThreadScheduledExecutor();

    /** 模型版本定义 */
    public record ModelVersion(String name, int version,
                                String indexName, int dimension) {}

    /** 灰度流量占比：新模型当前承接的流量百分比 (0-100) */
    private final AtomicInteger newModelTrafficPercent = new AtomicInteger(0);
    private volatile ModelVersion oldModel;
    private volatile ModelVersion newModel;

    public VectorLifecycleManager(DataSource dataSource,
                                   EmbeddingService embeddingService) {
        this.dataSource = dataSource;
        this.embeddingService = embeddingService;
    }

    /**
     * 增量更新：CDC事件 → 重新Embedding → upsert向量索引
     */
    public void handleDocumentChange(String chunkId, String newContent) {
        var model = getActiveModel();
        var embedding = embeddingService.embed(newContent, model.name());

        try (var conn = dataSource.getConnection();
             var stmt = conn.prepareStatement("""
                 INSERT INTO chunk_embeddings (chunk_id, embedding, model_name, version)
                 VALUES (?::uuid, ?::vector, ?, ?)
                 ON CONFLICT (chunk_id, model_name)
                 DO UPDATE SET embedding = EXCLUDED.embedding, updated_at = now()
                 """)) {
            stmt.setString(1, chunkId);
            stmt.setArray(2, conn.createArrayOf("float4", toObjectArray(embedding)));
            stmt.setString(3, model.name());
            stmt.setInt(4, model.version());
            stmt.executeUpdate();
        } catch (Exception e) {
            throw new RuntimeException("向量更新失败: " + chunkId, e);
        }
    }

    /**
     * Embedding 模型版本迁移 — 双写 + 灰度切换
     */
    public void startModelMigration(ModelVersion newModelVersion,
                                      int initialTrafficPercent) {
        this.oldModel = getActiveModel();
        this.newModel = newModelVersion;

        // 步骤1: 创建新索引（在低峰期异步执行）
        scheduler.execute(() -> {
            createNewIndex(newModelVersion);
            // 步骤2: 存量数据回填 — 分批读取旧索引数据，用新模型重新Embedding
            backfillToNewIndex(newModelVersion);
            System.out.println("[迁移] 存量数据回填完成");
        });

        // 步骤3: 逐步提升新模型流量占比
        setNewModelTraffic(initialTrafficPercent);
    }

    /** 灰度流量控制 */
    public void setNewModelTraffic(int percent) {
        if (percent < 0 || percent > 100) {
            throw new IllegalArgumentException("流量占比必须在0-100之间");
        }
        newModelTrafficPercent.set(percent);
        System.out.printf("[灰度] 新模型 %s 流量占比更新为 %d%%%n",
            newModel.name(), percent);
    }

    /** 按灰度比例路由检索请求 */
    public List<SearchHit> searchWithGrayscale(float[] queryEmbedding,
                                                int topK) {
        var percent = newModelTrafficPercent.get();

        if (percent == 0 || newModel == null) {
            return searchIndex(queryEmbedding, oldModel.indexName(), topK);
        }
        if (percent >= 100) {
            return searchIndex(
                embeddingService.embed(lastQuery, newModel.name()),
                newModel.indexName(), topK);
        }

        // 灰度期间：同时查两个索引，按比例加权融合
        var oldResults = searchIndex(queryEmbedding, oldModel.indexName(), topK * 2);
        var newQueryEmb = embeddingService.embed(lastQuery, newModel.name());
        var newResults = searchIndex(newQueryEmb, newModel.indexName(), topK * 2);

        // 加权分数融合
        var newWeight = percent / 100.0;
        var oldWeight = 1.0 - newWeight;
        return weightedFusion(oldResults, oldWeight, newResults, newWeight, topK);
    }

    /**
     * 索引维护窗口：每日低峰期重建 HNSW 索引
     */
    public void scheduleRebuild(LocalTime maintenanceTime) {
        var now = LocalTime.now();
        var delaySeconds = ChronoUnit.SECONDS.between(now, maintenanceTime);
        if (delaySeconds < 0) {
            delaySeconds += Duration.ofDays(1).toSeconds();
        }

        scheduler.scheduleAtFixedRate(() -> {
            System.out.println("[维护窗口] 开始重建 HNSW 索引...");
            try (var conn = dataSource.getConnection();
                 var stmt = conn.createStatement()) {
                stmt.execute("REINDEX INDEX CONCURRENTLY idx_chunk_embeddings_hnsw");
                System.out.println("[维护窗口] HNSW 索引重建完成");
            } catch (Exception e) {
                System.err.println("[维护窗口] 重建失败: " + e.getMessage());
            }
        }, delaySeconds, Duration.ofDays(1).toSeconds(), TimeUnit.SECONDS);
    }

    // --- 辅助方法 ---
    private ModelVersion getActiveModel() {
        return new ModelVersion("text-embedding-3-small", 1,
            "idx_embeddings_v1", 1536);
    }

    private void createNewIndex(ModelVersion model) {
        // 执行: CREATE INDEX idx_embeddings_v2 ON chunk_embeddings
        //       USING hnsw ((embedding::vector(3072)) vector_cosine_ops)
    }

    private void backfillToNewIndex(ModelVersion model) {
        // 分批: SELECT * FROM chunks WHERE id NOT IN (new_index)
        //       → embeddingService.embed(content, newModel.name())
        //       → INSERT INTO new_index
    }

    private List<SearchHit> searchIndex(float[] embedding,
                                          String indexName, int topK) {
        return List.of(); // pgvector similarity search
    }

    private List<SearchHit> weightedFusion(
            List<SearchHit> oldResults, double oldWeight,
            List<SearchHit> newResults, double newWeight, int topK) {
        var scores = new HashMap<String, Double>();
        for (var h : oldResults) scores.merge(h.id(), h.score() * oldWeight, Double::sum);
        for (var h : newResults) scores.merge(h.id(), h.score() * newWeight, Double::sum);
        return scores.entrySet().stream()
            .sorted(Map.Entry.<String, Double>comparingByValue().reversed())
            .limit(topK).map(e -> new SearchHit(e.getKey(), e.getValue())).toList();
    }

    public record SearchHit(String id, double score) {}

    private String lastQuery = "";
    private Object[] toObjectArray(float[] arr) {
        var obj = new Object[arr.length];
        for (int i = 0; i < arr.length; i++) obj[i] = arr[i];
        return obj;
    }

    public interface EmbeddingService {
        float[] embed(String text, String modelName);
    }
}
```

## 生产混合检索优化

在生产环境中，混合检索的核心矛盾是检索质量与延迟之间的权衡。HNSW 的 `ef_search` 参数是关键调优旋钮：`ef_search=40` 时延迟约 3ms 但召回率仅 92%；`ef_search=200` 时召回率可达 99% 但延迟升至 15ms。推荐对 Query 做分类决策——简单关键词查询使用低 ef_search（保证高吞吐），复杂语义查询使用高 ef_search（保证高召回）。在 Spring Boot 中可以通过 Filter 或 AOP 拦截查询请求，自动检测 Query 特征并动态选择参数。

工业级混合检索采用**三阶段 Pipeline** 将召回与精排解耦。第一阶段：并行执行 BM25 稀疏检索和向量稠密检索，各自取 `topK*3` 个候选文档。第二阶段：RRF 或加权分数融合，将两路结果合并为一个有序列表，截断至 `topK*2`。第三阶段：引入 Cross-Encoder 重排模型（如 bge-reranker-v2-m3）对候选文档逐对计算语义相关性，输出精确的 Top-K。三阶段设计的优势在于各环节可独立扩缩容——召回层用 CPU 密集型 pgvector，重排层部署在 GPU 推理服务上。

缓存策略对高频场景至关重要。采用**分层缓存**：L1 本地 Caffeine 精确匹配缓存（命中 <1ms），适合短时重复的相同 Query；L2 Redis 向量语义缓存（命中 3-5ms），以 Query 向量为 key 存储 Top-K 结果，相似度阈值设为 0.92。通过离线分析每日 Query 日志识别高频查询并预热至 L1，可将 P50 延迟降低 60% 以上。

```java
// JDK 25 + Spring Boot 4.x — 三阶段混合检索 Pipeline
import com.github.benmanes.caffeine.cache.*;
import java.time.Duration;
import java.util.*;
import java.util.concurrent.*;

public class ProductionHybridSearchPipeline {

    /** 检索参数：根据 Query 复杂度自适应调整 */
    public record SearchConfig(int efSearch, int candidateMultiplier) {}

    public record PipelineResult(List<ScoredDoc> finalResults,
                                  long recallMs, long fusionMs,
                                  long rerankMs, boolean cacheHit) {}

    public record ScoredDoc(String docId, String content, double score) {}

    // L1: 热门 Query 精确匹配缓存
    private final Cache<String, List<ScoredDoc>> exactMatchCache =
        Caffeine.newBuilder()
            .maximumSize(5_000)
            .expireAfterWrite(Duration.ofMinutes(30))
            .recordStats()
            .build();

    // L2: 向量语义缓存（简化实现）
    private final Cache<String, String> semanticCache =
        Caffeine.newBuilder()
            .maximumSize(20_000)
            .expireAfterWrite(Duration.ofHours(2))
            .build();

    private final VectorSearchService vectorSearch;
    private final Bm25SearchService bm25Search;
    private final RerankerService reranker;

    public ProductionHybridSearchPipeline(
            VectorSearchService vectorSearch,
            Bm25SearchService bm25Search,
            RerankerService reranker) {
        this.vectorSearch = vectorSearch;
        this.bm25Search = bm25Search;
        this.reranker = reranker;
    }

    /**
     * 三阶段检索 Pipeline:
     *   阶段1: 并行召回 (BM25 + 向量)
     *   阶段2: RRF 融合
     *   阶段3: Cross-Encoder 精排
     */
    public PipelineResult search(String query, int topK) {
        // L1 精确缓存检查
        var cached = exactMatchCache.getIfPresent(query);
        if (cached != null) {
            return new PipelineResult(cached, 0, 0, 0, true);
        }

        var config = adaptConfig(query);
        var candidateSize = topK * config.candidateMultiplier();

        try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
            // === 阶段1: 并行召回 ===
            long t0 = System.currentTimeMillis();
            var vectorFuture = executor.submit(() ->
                vectorSearch.search(query, candidateSize, config.efSearch()));
            var bm25Future = executor.submit(() ->
                bm25Search.search(query, candidateSize));

            var vectorResults = vectorFuture.get(800, TimeUnit.MILLISECONDS);
            var bm25Results = bm25Future.get(800, TimeUnit.MILLISECONDS);
            long recallMs = System.currentTimeMillis() - t0;

            // === 阶段2: RRF 融合 ===
            long t1 = System.currentTimeMillis();
            var fused = rrfFusion(vectorResults, bm25Results, 60, topK * 2);
            long fusionMs = System.currentTimeMillis() - t1;

            // === 阶段3: Cross-Encoder 精排 ===
            long t2 = System.currentTimeMillis();
            var docs = fused.stream().map(ScoredDoc::content).toList();
            var finalResults = reranker.rerank(query, docs, topK);
            long rerankMs = System.currentTimeMillis() - t2;

            System.out.printf("[Pipeline] 召回:%dms 融合:%dms 精排:%dms%n",
                recallMs, fusionMs, rerankMs);

            return new PipelineResult(finalResults, recallMs, fusionMs, rerankMs, false);
        } catch (Exception e) {
            throw new RuntimeException("混合检索 pipeline 失败", e);
        }
    }

    /** 自适应检索参数：根据 Query 长度和复杂度动态调整 */
    private SearchConfig adaptConfig(String query) {
        if (query.length() < 10 && !query.contains(" ")) {
            return new SearchConfig(40, 3);   // 短关键词：低efSearch高吞吐
        } else if (query.length() > 50) {
            return new SearchConfig(200, 3);  // 长语义：高efSearch高召回
        }
        return new SearchConfig(100, 3);      // 默认配置
    }

    /** RRF 融合算法 */
    private List<ScoredDoc> rrfFusion(
            List<ScoredDoc> vecResults, List<ScoredDoc> bm25Results,
            int k, int topK) {
        var scores = new HashMap<String, Double>();
        var docMap = new HashMap<String, ScoredDoc>();

        for (int i = 0; i < vecResults.size(); i++) {
            var d = vecResults.get(i);
            scores.merge(d.docId(), 1.0 / (k + i + 1), Double::sum);
            docMap.putIfAbsent(d.docId(), d);
        }
        for (int i = 0; i < bm25Results.size(); i++) {
            var d = bm25Results.get(i);
            scores.merge(d.docId(), 1.0 / (k + i + 1), Double::sum);
            docMap.putIfAbsent(d.docId(), d);
        }

        return scores.entrySet().stream()
            .sorted(Map.Entry.<String, Double>comparingByValue().reversed())
            .limit(topK)
            .map(e -> new ScoredDoc(e.getKey(),
                docMap.get(e.getKey()).content(), e.getValue()))
            .toList();
    }

    /** 预热热门 Query 到 L1 缓存 */
    public void warmupHotQueries(List<String> hotQueries) {
        for (var q : hotQueries) {
            CompletableFuture.runAsync(() -> {
                var res = search(q, 10);
                if (!res.cacheHit()) {
                    exactMatchCache.put(q, res.finalResults());
                }
            });
        }
        System.out.printf("[预热] %d 个热门 Query 已缓存%n", hotQueries.size());
    }

    // --- 服务接口 ---
    interface VectorSearchService {
        List<ScoredDoc> search(String query, int topK, int efSearch);
    }
    interface Bm25SearchService {
        List<ScoredDoc> search(String query, int topK);
    }
    interface RerankerService {
        List<ScoredDoc> rerank(String query, List<String> docs, int topK);
    }
}
```
