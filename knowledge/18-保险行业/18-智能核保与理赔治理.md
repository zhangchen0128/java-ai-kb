# 智能核保与理赔治理案例

## 定位

本案例是演示架构，不代表任何保险机构的真实生产流程。模型只提供信息抽取、材料核对和辅助建议，不直接替代核保、理赔或反欺诈人员作出最终决定。

## 数据流

```text
材料接收
  → 病毒扫描与格式校验
  → 敏感字段识别和最小化
  → OCR/文档结构化
  → 规则与模型并行分析
  → 证据引用和置信度
  → 人工复核
  → 核心系统执行
  → 全链路审计
```

身份、联系方式、健康信息、财务信息和影像材料应按业务目的分别授权和保存。检索索引必须带租户、案件和权限过滤；不得仅依赖 Prompt 告诉模型“不要查看其他案件”。

## 核保辅助

模型适合执行：

- 从材料中提取结构化事实并标注页码。
- 检查必填项、材料一致性和缺失项。
- 将事实映射到已经批准的规则条款。
- 生成供人工审核的摘要与问题清单。

模型不应自行修改费率、承保规则、除外责任或最终核保结论。任何建议都要显示来源证据、规则版本和模型版本。

## 理赔辅助

理赔流程需要显式覆盖：

- 材料无法解析或内容冲突。
- 检索无结果、低置信度或证据不足。
- 模型超时、限流或供应商不可用。
- 重复提交和重复支付风险。
- 涉及拒赔、争议、高金额或疑似欺诈的人工升级。

## 审计事件

每次辅助决策至少记录案件关联 ID、数据版本、规则版本、模型与 Prompt 版本、引用证据、策略结果、人工复核人、最终业务结果和时间。日志中不得保存不必要的完整原文或秘密。

## 上线门禁

- 使用脱敏且经过授权的数据完成离线评测。
- 按险种、渠道和关键人群检查失败样本。
- 验证人工兜底的处理能力和服务级别。
- 演练模型不可用、错误建议和数据泄露场景。
- 由法律、合规、安全和业务负责人共同确认边界。
