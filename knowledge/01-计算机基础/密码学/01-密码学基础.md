# 密码学基础

## 概述

密码学是现代软件系统的安全基石。从网络通信的 TLS 加密，到用户密码的安全存储，再到 API 令牌的签名验证，密码学无处不在。在 AI 应用场景中，模型 API 密钥的管理、Agent 工具调用的授权令牌验证、知识库文档的加密存储，都需要扎实的密码学基础。

本条目系统梳理密码学的五大核心领域：对称加密、非对称加密、哈希与消息认证、数字签名和 PKI 公钥基础设施，并给出 JDK 25 + Spring Boot 4.x 风格的可运行代码示例。**核心原则：永远不要自己实现加密算法，使用经过安全审计的标准库和经过验证的最佳实践。**

## 一、对称加密：AES-256-GCM

### 1.1 原理概述

对称加密使用同一把密钥进行加密和解密。AES（Advanced Encryption Standard）是最广泛使用的对称加密算法，支持 128/192/256 位密钥长度。

**AES-256-GCM** 是当前推荐的对称加密模式，它同时提供：
- **机密性**：数据被加密，无法被未授权方读取
- **完整性/认证**：GCM（Galois/Counter Mode）自带认证标签（Authentication Tag），可以检测数据是否被篡改
- **高性能**：GCM 支持硬件加速（AES-NI 指令集），性能远超 CBC+HMAC 组合

**关键概念：**
- **IV/Nonce**：初始化向量，必须每次加密都随机生成（建议 12 字节）。重复使用 IV 会严重破坏 GCM 的安全性
- **认证标签（Tag）**：GCM 生成的 128 位 MAC 值，解密时必须验证，防止密文篡改
- **关联数据（AAD）**：可选的附加认证数据（如协议头、用户 ID），不加密但参与认证

### 1.2 Java 实现

```java
import javax.crypto.Cipher;
import javax.crypto.KeyGenerator;
import javax.crypto.SecretKey;
import javax.crypto.spec.GCMParameterSpec;
import javax.crypto.spec.SecretKeySpec;
import java.security.SecureRandom;

public class AesGcmExample {

    private static final String ALGORITHM = "AES/GCM/NoPadding";
    private static final int GCM_TAG_LENGTH = 128; // bits
    private static final int GCM_IV_LENGTH = 12;   // bytes (96 bits, recommended)

    // 生成 AES-256 密钥
    public static SecretKey generateKey() throws Exception {
        var keyGen = KeyGenerator.getInstance("AES");
        keyGen.init(256); // AES-256
        return keyGen.generateKey();
    }

    // 加密：返回 IV + 密文（IV 不需要保密，但必须随机且唯一）
    public static byte[] encrypt(byte[] plaintext, SecretKey key, byte[] aad) throws Exception {
        var cipher = Cipher.getInstance(ALGORITHM);
        var iv = new byte[GCM_IV_LENGTH];
        SecureRandom.getInstanceStrong().nextBytes(iv); // 使用强随机源

        var spec = new GCMParameterSpec(GCM_TAG_LENGTH, iv);
        cipher.init(Cipher.ENCRYPT_MODE, key, spec);

        if (aad != null) {
            cipher.updateAAD(aad); // 设置关联数据
        }

        var ciphertext = cipher.doFinal(plaintext);

        // 返回 IV || 密文（密文末尾已包含认证标签）
        var result = new byte[GCM_IV_LENGTH + ciphertext.length];
        System.arraycopy(iv, 0, result, 0, GCM_IV_LENGTH);
        System.arraycopy(ciphertext, 0, result, GCM_IV_LENGTH, ciphertext.length);
        return result;
    }

    // 解密：自动验证认证标签，失败抛出 AEADBadTagException
    public static byte[] decrypt(byte[] encrypted, SecretKey key, byte[] aad) throws Exception {
        var cipher = Cipher.getInstance(ALGORITHM);

        // 分离 IV 和密文
        var iv = new byte[GCM_IV_LENGTH];
        System.arraycopy(encrypted, 0, iv, 0, GCM_IV_LENGTH);
        var ciphertext = new byte[encrypted.length - GCM_IV_LENGTH];
        System.arraycopy(encrypted, GCM_IV_LENGTH, ciphertext, 0, ciphertext.length);

        var spec = new GCMParameterSpec(GCM_TAG_LENGTH, iv);
        cipher.init(Cipher.DECRYPT_MODE, key, spec);

        if (aad != null) {
            cipher.updateAAD(aad);
        }

        return cipher.doFinal(ciphertext); // 如果认证失败，抛出 AEADBadTagException
    }
}
```

**安全要点：**
- 永远使用 `SecureRandom.getInstanceStrong()` 生成 IV
- GCM 的 IV 重复使用会导致灾难性安全漏洞（认证密钥泄露）
- GCM 认证标签长度至少 128 位
- 密文长度 = 明文长度 + 16 字节（认证标签）

### 1.3 密钥管理（Key Management）

生产环境中，加密密钥**绝对不能硬编码**。推荐方案：

**开发环境**：使用 Java KeyStore（JCEKS/PKCS12 格式）加密存储密钥。

**生产环境**：使用密钥管理服务（KMS）：
- 云服务：AWS KMS、Azure Key Vault、Google Cloud KMS
- 自建方案：HashiCorp Vault（Spring Cloud Vault 集成）

## 二、非对称加密：RSA 与 ECC

### 2.1 RSA 原理与应用

RSA 基于大整数分解难题。使用一对密钥：公钥加密，私钥解密；或私钥签名，公钥验签。

**密钥长度建议：**
- RSA 2048：最低安全标准，适用于 2030 年前
- RSA 4096：更高安全级别，但性能开销大

```java
import java.security.*;

public class RsaExample {

    public static KeyPair generateKeyPair() throws Exception {
        var keyGen = KeyPairGenerator.getInstance("RSA");
        keyGen.initialize(4096, SecureRandom.getInstanceStrong());
        return keyGen.generateKeyPair();
    }

    public static byte[] encrypt(byte[] data, PublicKey publicKey) throws Exception {
        var cipher = Cipher.getInstance("RSA/ECB/OAEPWithSHA-256AndMGF1Padding");
        cipher.init(Cipher.ENCRYPT_MODE, publicKey);
        return cipher.doFinal(data);
    }

    public static byte[] decrypt(byte[] data, PrivateKey privateKey) throws Exception {
        var cipher = Cipher.getInstance("RSA/ECB/OAEPWithSHA-256AndMGF1Padding");
        cipher.init(Cipher.DECRYPT_MODE, privateKey);
        return cipher.doFinal(data);
    }
}
```

**重要提示：RSA 不适合直接加密大量数据。** 实际应用中，RSA 用于加密对称密钥（如 AES 密钥），然后使用对称密钥加密实际数据。这就是混合加密方案，也是 TLS 的核心工作原理。

### 2.2 ECC（椭圆曲线密码学）

ECC 提供与 RSA 同等的安全性，但密钥更短、计算更快。推荐曲线：P-256（secp256r1）用于常规场景，P-521 用于更高安全需求。

```java
public class EccExample {

    public static KeyPair generateKeyPair() throws Exception {
        var keyGen = KeyPairGenerator.getInstance("EC");
        keyGen.initialize(256, SecureRandom.getInstanceStrong()); // P-256
        return keyGen.generateKeyPair();
    }
}
```

### 2.3 ECDH 密钥交换

ECDH（Elliptic Curve Diffie-Hellman）允许双方在不安全的信道上协商出共享密钥：

```java
import javax.crypto.KeyAgreement;

public class EcdhExample {

    public static SecretKey deriveSharedSecret(PrivateKey myPrivateKey,
                                                PublicKey peerPublicKey) throws Exception {
        var keyAgreement = KeyAgreement.getInstance("ECDH");
        keyAgreement.init(myPrivateKey);
        keyAgreement.doPhase(peerPublicKey, true);
        var sharedSecret = keyAgreement.generateSecret(); // 原始共享密钥
        // 使用 HKDF 派生实际使用的 AES 密钥（推荐）
        return deriveKeyWithHkdf(sharedSecret);
    }

    private static SecretKey deriveKeyWithHkdf(byte[] sharedSecret) {
        // 实际项目中应使用 HKDF（如 BouncyCastle 的实现）
        // 简化为直接 SHA-256 哈希（仅供演示）
        var digest = MessageDigest.getInstance("SHA-256");
        return new SecretKeySpec(digest.digest(sharedSecret), "AES");
    }
}
```

**RSA vs ECC 选型：**
| 场景 | 推荐 | 原因 |
|------|------|------|
| TLS 证书 | ECC (P-256) | 更快、更短的握手 |
| 旧系统兼容 | RSA 2048 | 更广泛的生态支持 |
| 数字签名 | Ed25519 | 安全性、性能均优于 ECDSA |
| 密钥封装（KEM） | Kyber | 后量子密码学，抵抗量子计算攻击 |

## 三、哈希与消息认证

### 3.1 加密哈希函数

哈希函数将任意长度的数据映射为固定长度的摘要。加密哈希要求：单向性（不可逆）、抗碰撞性（难以找到两个不同输入产生相同哈希值）。

**推荐算法：**
- SHA-256：256 位输出，适合大多数场景
- SHA-512：512 位输出，用于更高安全需求

```java
import java.security.MessageDigest;

public class HashExample {
    public static byte[] sha256(byte[] data) throws Exception {
        var digest = MessageDigest.getInstance("SHA-256");
        return digest.digest(data);
    }

    public static String sha256Hex(String data) throws Exception {
        var digest = MessageDigest.getInstance("SHA-256");
        var hash = digest.digest(data.getBytes());
        var hexString = new StringBuilder();
        for (byte b : hash) {
            hexString.append(String.format("%02x", b));
        }
        return hexString.toString();
    }
}
```

**不推荐的算法：** MD5 和 SHA-1 已被证明存在碰撞攻击风险，绝对不要在新系统中使用。

### 3.2 HMAC：消息认证码

HMAC（Hash-based Message Authentication Code）结合哈希函数和密钥，同时提供数据完整性和消息来源认证。

```java
import javax.crypto.Mac;
import javax.crypto.spec.SecretKeySpec;

public class HmacExample {
    private static final String HMAC_SHA256 = "HmacSHA256";

    public static byte[] sign(byte[] message, byte[] key) throws Exception {
        var mac = Mac.getInstance(HMAC_SHA256);
        mac.init(new SecretKeySpec(key, HMAC_SHA256));
        return mac.doFinal(message);
    }

    public static boolean verify(byte[] message, byte[] key, byte[] expectedSignature)
            throws Exception {
        var actualSignature = sign(message, key);
        return MessageDigest.isEqual(actualSignature, expectedSignature);
        // 注意：使用 MessageDigest.isEqual 进行常数时间比较，防止时序攻击
    }
}
```

**AI 场景应用：** Webhook 回调验证（如 OpenAI/Anthropic 的 webhook 签名验证）、API 请求签名。

### 3.3 密码哈希：bcrypt 与 Argon2

密码哈希与加密哈希有本质区别：密码哈希必须是缓慢的（计算密集型），以抵抗暴力破解和彩虹表攻击。

**bcrypt**：基于 Blowfish 算法，自适应（可调整轮数），自动处理盐值。

**Argon2**：2015 年密码哈希竞赛冠军，有三种模式：
- Argon2i：抵抗侧信道攻击
- Argon2d：抵抗 GPU 攻击
- Argon2id：混合模式（推荐）

```java
// Spring Security PasswordEncoder 集成
import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;
import org.springframework.security.crypto.argon2.Argon2PasswordEncoder;

public class PasswordHashingConfig {

    // bcrypt — 成熟稳定，生态最广泛
    public BCryptPasswordEncoder bcryptEncoder() {
        return new BCryptPasswordEncoder(12); // 12 rounds（推荐生产环境）
    }

    // Argon2 — 更现代，抗 GPU/ASIC 攻击
    public Argon2PasswordEncoder argon2Encoder() {
        return new Argon2PasswordEncoder(
                16,         // salt length: 16 bytes
                32,         // hash length: 32 bytes
                1,          // parallelism: single thread
                65536,      // memory cost: 64MB
                3           // iterations
        );
    }
}

// 使用示例
@Service
public class UserService {
    private final PasswordEncoder encoder;

    public UserService(PasswordEncoder encoder) {
        this.encoder = encoder;
    }

    public void register(String rawPassword) {
        var hashed = encoder.encode(rawPassword); // 自动生成盐值
        // 存储 hashed 到数据库
    }

    public boolean login(String rawPassword, String storedHash) {
        return encoder.matches(rawPassword, storedHash);
    }
}
```

**核心原则：** 永远不要对密码使用 SHA-256 等快速哈希。始终使用 bcrypt 或 Argon2。

## 四、数字签名：ECDSA 与 Ed25519

### 4.1 签名原理

数字签名提供三个属性：
1. **身份认证**：验证消息确实来自声称的发送方
2. **完整性**：消息未被篡改
3. **不可否认性**：发送方不能否认发送过消息

### 4.2 ECDSA 实现

ECDSA 是目前最广泛的椭圆曲线签名算法，广泛用于 JWT 签名和 TLS 证书。

```java
import java.security.Signature;

public class EcdsaExample {

    public static KeyPair generateKeyPair() throws Exception {
        var keyGen = KeyPairGenerator.getInstance("EC");
        keyGen.initialize(256);
        return keyGen.generateKeyPair();
    }

    public static byte[] sign(byte[] data, PrivateKey privateKey) throws Exception {
        var sig = Signature.getInstance("SHA256withECDSA");
        sig.initSign(privateKey);
        sig.update(data);
        return sig.sign();
    }

    public static boolean verify(byte[] data, byte[] signature, PublicKey publicKey)
            throws Exception {
        var sig = Signature.getInstance("SHA256withECDSA");
        sig.initVerify(publicKey);
        sig.update(data);
        return sig.verify(signature);
    }
}
```

### 4.3 Ed25519 — 下一代签名算法

Ed25519 基于 Edwards 曲线，具有以下优势：
- 比 ECDSA P-256 更快（签名生成和验证都快数倍）
- 确定性签名（不依赖随机数质量，彻底避免 ECDSA 的 nonce 重用问题）
- 密钥和签名更小（32 字节密钥，64 字节签名）

```java
public class Ed25519Example {

    // JDK 15+ 原生支持 Ed25519
    public static KeyPair generateKeyPair() throws Exception {
        var keyGen = KeyPairGenerator.getInstance("Ed25519");
        return keyGen.generateKeyPair();
    }

    public static byte[] sign(byte[] data, PrivateKey privateKey) throws Exception {
        var sig = Signature.getInstance("Ed25519");
        sig.initSign(privateKey);
        sig.update(data);
        return sig.sign();
    }

    public static boolean verify(byte[] data, byte[] signature, PublicKey publicKey)
            throws Exception {
        var sig = Signature.getInstance("Ed25519");
        sig.initVerify(publicKey);
        sig.update(data);
        return sig.verify(signature);
    }
}
```

**选型推荐：** 新系统中默认使用 Ed25519，除非需要兼容仅支持 ECDSA 的系统。

## 五、PKI：公钥基础设施

### 5.1 X.509 证书

X.509 是 PKI 的核心标准，定义了证书格式。证书包含：主体（Subject）、签发者（Issuer）、有效期、公钥、数字签名。

### 5.2 Keystore 与 Truststore

| 概念 | 用途 | 内容 |
|------|------|------|
| **Keystore** | 存储自己的私钥/证书 | 服务端 SSL 证书 |
| **Truststore** | 存储信任的 CA 证书 | 验证对方的证书链 |

```java
// 加载 PKCS12 Keystore
var keyStore = KeyStore.getInstance("PKCS12");
try (var is = new FileInputStream("keystore.p12")) {
    keyStore.load(is, "keystore-password".toCharArray());
}

// 从 Keystore 中获取私钥
var privateKey = (PrivateKey) keyStore.getKey("my-alias", "key-password".toCharArray());
var certificate = keyStore.getCertificate("my-alias");
```

### 5.3 证书链验证

浏览器/客户端验证服务器证书的过程：

```
1. 检查证书是否过期
2. 检查证书是否被吊销（CRL/OCSP）
3. 用签发者的公钥验证证书签名
4. 递归验证签发者证书，直到根 CA
5. 验证根 CA 是否在 Truststore 中
```

### 5.4 TLS 1.3 握手与 PKI 的关系

TLS 1.3 握手流程（简化版）：

```
Client                          Server
  |                                |
  |--- ClientHello --------------->|  (支持的密码套件、密钥共享)
  |<-- ServerHello + EncryptedExt -|  (选定密码套件、服务器密钥共享、证书)
  |   + Certificate + CertVerify   |
  |   + Finished                   |
  |                                |
  |--- Finished ------------------>|  (加密的)
  |                                |
  |<===== 加密通道建立 ============>|
```

关键点：
- 服务器发送 X.509 证书给客户端
- 客户端用 Truststore 中的 CA 证书验证服务器证书
- TLS 1.3 仅支持 AEAD 密码套件（如 AES-256-GCM、ChaCha20-Poly1305）
- RSA 密钥交换已被移除（仅保留前向安全的 (EC)DHE 密钥交换）

## 六、Java 密码学最佳实践

### 6.1 绝对不要自己实现加密算法

密码学领域有一个铁律：**不要自己发明密码学算法，不要自己实现已知算法，除非你是一个密码学专家并且你的实现经过了广泛的安全审计。**

始终使用：
- JDK 内置的 JCA/JCE
- BouncyCastle（当 JDK 不支持某些算法时）
- Spring Security 提供的密码学抽象

### 6.2 随机数生成

始终使用 `SecureRandom` 而不是 `java.util.Random`：

```java
// 正确：加密场景使用 SecureRandom
var secureRandom = SecureRandom.getInstanceStrong();
byte[] iv = new byte[12];
secureRandom.nextBytes(iv);

// 错误：永远不要在密码学中使用 java.util.Random
// var random = new java.util.Random(); // 不安全！可预测！
```

### 6.3 密钥管理战略

密钥的生命周期管理是整个密码学系统的核心：

```
密钥生成 → 安全存储 → 轮换 → 撤销 → 销毁
```

| 存储方式 | 安全级别 | 适用场景 |
|----------|----------|----------|
| 环境变量 | 低 | 仅限本地开发 |
| Java KeyStore (JCEKS) | 中 | 单体应用 |
| Spring Cloud Config (加密) | 中 | 微服务配置 |
| HashiCorp Vault | 高 | 企业级密钥管理 |
| 云 KMS (AWS/Azure/GCP) | 高 | 云原生应用（推荐） |

### 6.4 密码套件选择

**TLS 1.3（推荐）：**
- TLS_AES_256_GCM_SHA384
- TLS_AES_128_GCM_SHA256
- TLS_CHACHA20_POLY1305_SHA256（移动端友好）

**已淘汰（绝不使用）：** SSLv3、TLS 1.0、TLS 1.1、RSA 密钥交换、CBC 模式、RC4。

### 6.5 AI 场景应用

在 AI 应用中，密码学的典型用途：

1. **API Key 加密存储**：使用 AES-256-GCM 加密存储 OpenAI/Anthropic API Key
2. **MCP 工具调用授权**：使用 HMAC 验证工具调用的来源和完整性
3. **知识库文档加密**：使用 AES-GCM 加密敏感知识库文档
4. **模型网关 mTLS**：服务间通信使用双向 TLS 确保端到端安全
5. **JWT Token 签名**：使用 Ed25519 签名 API 认证令牌

## 常见问题

**Q: AES-256-GCM 和 AES-256-CBC+HMAC 如何选择？**
A: GCM 是绝对首选。GCM 内置认证、支持硬件加速、性能更优。CBC 模式需要额外添加 HMAC，实现复杂且容易出错（如 padding oracle 攻击）。

**Q: 什么时候需要用到非对称加密？**
A: 密钥交换、数字签名、身份认证。实际数据加密应使用对称加密（性能好 3-5 个数量级），用非对称加密保护对称密钥。

**Q: bcrypt vs Argon2 用户密码存储选哪个？**
A: 新项目直接使用 Argon2id。如果已有 bcrypt 基础设施且升级成本高，bcrypt 仍然安全（参数合理的情况下）。

**Q: 如何检测密码系统是否被破解？**
A: 关注 NIST、BSI、ANSSI 等权威机构的算法推荐更新。当量子计算机商用化时，RSA/ECDSA 将被淘汰，需要迁移到后量子密码学。
