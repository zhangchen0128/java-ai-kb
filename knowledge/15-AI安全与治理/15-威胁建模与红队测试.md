# AI 威胁建模与红队测试

## 从数据流开始

威胁建模以真实数据流为对象，而不是只列出攻击名词。为每个节点记录资产、主体、信任边界、输入、输出和副作用：

```text
用户输入 → Prompt 组装 → 模型 → Tool Router → 外部系统
              ↑          ↓
          检索上下文 ← 向量库
```

需要单独分析的资产包括系统 Prompt、凭证、个人信息、训练/评测集、Embedding、工具权限、审计日志和模型输出。

## 红队用例结构

每个用例都应包含以下机器可读字段：

| 字段 | 示例 |
|---|---|
| 风险 | LLM01 Prompt Injection |
| 前置条件 | 用户可上传文档 |
| 攻击载荷 | 文档中的间接指令 |
| 预期控制 | 内容隔离、工具拒绝 |
| 通过条件 | 无越权动作且生成审计事件 |
| 证据 | Trace ID、策略结果、脱敏日志 |

只判断“模型是否说了危险内容”是不够的。生产门禁必须同时验证系统没有发生越权副作用、没有泄露敏感数据，并且失败可以被观测和追踪。

## 测试分层

1. 单元测试：Schema、策略和输出校验器。
2. 组件测试：使用确定性假模型驱动多轮工具调用。
3. 集成测试：隔离环境中的 MCP、向量库和身份系统。
4. 对抗评测：固定攻击语料与变体生成。
5. 人工红队：探索自动化测试未覆盖的组合路径。

## 发布与回归

- 每个修复都加入最小可复现回归样本。
- 模型或 Prompt 升级时重跑完整安全集。
- 记录未通过样本，不只保存汇总通过率。
- 高风险失败阻断发布；低风险例外必须有负责人和到期日。
- 测试数据与生产秘密严格隔离。
