# 机器学习基础

## 概述

面向 Java 后端工程师的机器学习基础知识体系。目标不是成为算法专家，而是建立足够理解 LLM、RAG、Agent 等 AI 应用所需的核心概念，为后续学习 AI 框架和模型接入打下基础。

Java 开发者可以将机器学习类比为"通过数据自动推导业务规则"的过程：传统开发中，我们手动编写 if-else 规则处理各种 case；机器学习则是让算法从标注数据中自动学习这些规则。两者都追求对未见过的输入做出正确判断——单元测试确保代码正确性，验证集确保模型泛化能力。

## 一、学习范式

### 1.1 监督学习 (Supervised Learning)

监督学习是从"有答案的练习题"中学习。训练数据中的每条样本都包含特征向量和对应的标签（正确答案）。

```
训练数据格式: (特征向量 X, 标签 y)

示例 — 垃圾邮件分类:
X₁ = [词频向量: "免费"=3, "中奖"=2, "点击"=1, ...], y₁ = "垃圾"
X₂ = [词频向量: "会议"=2, "报告"=1, "附件"=1, ...], y₂ = "正常"
X₃ = [词频向量: "优惠"=2, "限时"=1, "抢购"=2, ...], y₃ = "垃圾"
```

**分类 (Classification)**：预测离散类别标签。

| 场景 | 输入 | 输出 |
|------|------|------|
| 垃圾邮件检测 | 邮件文本/特征 | {垃圾, 正常} |
| 情感分析 | 用户评论 | {正面, 负面, 中性} |
| 图像分类 | 图片像素矩阵 | {猫, 狗, 鸟, ...} |
| 意图识别 | 用户 Query | {投保咨询, 理赔查询, 产品对比} |

**回归 (Regression)**：预测连续数值。

| 场景 | 输入 | 输出 |
|------|------|------|
| 房价预测 | 面积/楼层/地段/房龄 | 预测价格（如 350,000 元） |
| 温度预测 | 历史温度/湿度/气压/风速 | 预测温度（如 23.7°C） |
| 保费估算 | 年龄/职业/保额/险种 | 预测保费（如 5,200 元/年） |

**与 Java 的类比**：监督学习类似带预期输出的单元测试——给定输入，我们已知期望输出，学习过程就是不断调整内部逻辑（模型参数）使实际输出逼近期望值。

### 1.2 无监督学习 (Unsupervised Learning)

训练数据没有标签，算法自行发现数据中的结构、模式或分布规律。

**聚类 (Clustering)**：将数据点划分到自然形成的组中。

```
K-Means 核心思路：
1. 随机初始化 K 个簇中心
2. 将每个点分配到最近的簇中心
3. 重新计算每个簇的中心（均值）
4. 重复步骤 2-3 直到收敛

算法     | 特点
K-Means  | 简单快速，需预设 K 值，对球形簇效果好
DBSCAN   | 基于密度，自动发现簇数，可识别噪声点
层次聚类 | 生成树状结构，可灵活选择簇数
```

**降维 (Dimensionality Reduction)**：将高维数据映射到低维空间，同时尽可能保留数据结构。

- **PCA（主成分分析）**：线性投影，找到方差最大的方向（主成分）。计算协方差矩阵的特征值和特征向量，选取前 k 个最大特征值对应的特征向量作为投影方向
- **t-SNE**：非线性降维，专为可视化设计（2D/3D），保留局部邻域结构。注意：不能用于特征工程预处理（概率分布依赖全量数据）
- **UMAP**：比 t-SNE 更快，同时保留全局结构，也可用于监督降维

**典型应用**：用户分群（聚类）、异常检测（发现离群点）、文档主题发现（LDA）、高维 Embedding 可视化（降维）。

### 1.3 半监督学习与强化学习

**半监督学习 (Semi-Supervised)**：少量标注数据 + 大量未标注数据。现实场景中标注成本高（如需要医生标注影像），利用少量标签引导 + 大量无标签数据的分布信息提升模型效果。常见方法：自训练（用模型预测未标注数据，将高置信度预测作为伪标签）、协同训练（多个视角的模型互相标注）。

**强化学习 (Reinforcement Learning)**：Agent 在环境 (Environment) 中采取行动 (Action)，环境返回奖励 (Reward)，Agent 学习最大化累积奖励的策略。这是 RLHF (Reinforcement Learning from Human Feedback) 的基础——先训练 Reward Model 模拟人类偏好，再用 PPO 等算法优化语言模型的生成策略。

```
关键概念：
State (状态)  →  Agent 对环境的观察（如棋盘状态、对话历史）
Action (动作) →  Agent 可执行的操作（如落子位置、生成的下一个 token）
Reward (奖励) →  环境对动作的反馈（如赢棋 +1、人类评分 0.8）
Policy (策略)  →  从状态到动作的映射函数 π(a|s)
Value Function → 从状态出发的预期累积奖励 V(s)
```

## 二、核心概念

### 2.1 过拟合 (Overfitting / High Variance)

模型在训练集上表现极好（99% 准确率），但在测试集上表现糟糕（60% 准确率）。本质是模型"记住了"训练数据的噪声和特例，而非学到通用规律。

**诊断信号**：
```
Epoch 1-10:   训练 loss ↓   验证 loss ↓    ← 正常学习
Epoch 11-50:  训练 loss ↓   验证 loss ↑    ← 开始过拟合！
Epoch 51+:    训练 loss →0  验证 loss ↗    ← 严重过拟合
```

**与 Java 的类比**：一个方法用 100 个 if-else 精准覆盖训练集中的每条数据，但输入任何训练样本外的 case 就返回错误结果。好的代码应该抽象出通用逻辑，而非穷举硬编码。

**常见原因**：模型复杂度过高（参数量远多于样本量）、训练数据量太少、训练迭代过多、数据噪声大。

### 2.2 欠拟合 (Underfitting / High Bias)

模型过于简单，无法捕捉数据中的潜在模式。训练集和测试集表现都不好。类比：只用一个 if-else 就想处理所有复杂业务场景。

### 2.3 偏差-方差权衡 (Bias-Variance Tradeoff)

这是理解模型泛化能力的核心框架。总泛化误差可分解为：

$$\text{Total Error} = \text{Bias}^2 + \text{Variance} + \text{Irreducible Error}$$

```
术语     | 含义                    | 直观理解
偏差 Bias | 模型预测平均值偏离真值的程度 | "瞄得准不准"
方差 Var  | 不同训练集上模型预测的波动  | "打得稳不稳"
```

用打靶场景直观理解四种情况：

```
低偏差 + 低方差：子弹集中靶心        → 理想模型
高偏差 + 低方差：子弹集中偏离靶心    → 欠拟合（所有预测都偏了）
低偏差 + 高方差：子弹围绕靶心但分散  → 过拟合（大方向对但不稳定）
高偏差 + 高方差：子弹偏离靶心且分散  → 最差情况
```

**实践指南**：训练初期偏差高方差低（欠拟合）→ 增加模型复杂度；训练后期偏差低方差高（过拟合）→ 增加正则化/更多数据。

### 2.4 正则化 (Regularization)

限制模型复杂度以防止过拟合的技术集合。

**L1 / Lasso**：

$$\text{Loss}_{L1} = \text{Loss}_{original} + \lambda \sum_i |w_i|$$

- 权重绝对值之和作为惩罚项
- 产生稀疏解：大量权重被压缩到精确的 0
- 自带特征选择效果（权重为 0 的特征相当于被排除）
- λ 越大 → 权重越稀疏

**L2 / Ridge（权重衰减）**：

$$\text{Loss}_{L2} = \text{Loss}_{original} + \lambda \sum_i w_i^2$$

- 权重平方和作为惩罚项
- 权重趋于接近 0 但不精确为 0
- 防止单个权重过大主导预测
- λ 越大 → 所有权重越接近于 0

**ElasticNet**：L1 和 L2 的组合，既有稀疏性又有平滑性。

**Dropout**：训练时以概率 p 随机"丢弃"神经元（输出置零），推理时所有神经元参与但输出乘以保留概率 (1-p)。视为隐式的模型集成（ensemble）——每次 Dropout 相当于训练一个不同的子网络，推理时相当于对指数级数量的子网络取平均。

```java
// Dropout 的概念模拟（非生产实现）
public class Dropout {
    private final double keepProb; // 保留概率，如 0.5
    private final Random rng = new Random();

    public float[] forward(boolean training, float[] input) {
        var output = new float[input.length];
        for (int i = 0; i < input.length; i++) {
            if (training) {
                // 训练时：以概率 keepProb 保留
                output[i] = (rng.nextDouble() < keepProb)
                    ? (float) (input[i] / keepProb)  // 除以 keepProb 保持期望一致
                    : 0.0f;
            } else {
                output[i] = input[i];  // 推理时不丢弃（权重已在训练中缩放）
            }
        }
        return output;
    }
}
```

**Early Stopping**：验证集 loss 不再下降（反而开始上升）时提前终止训练。简单有效，几乎零额外成本。

### 2.5 交叉验证 (Cross-Validation)

将数据分成训练集和验证集的系统化方法，用于评估模型的泛化能力和选择超参数。

**k-fold 交叉验证**：

```
将数据均分成 k 份 → 循环 k 次：
  第 1 次：折 1 作验证，折 2~k 作训练 → 得到 score₁
  第 2 次：折 2 作验证，折 1+3~k 作训练 → 得到 score₂
  ...
  第 k 次：折 k 作验证，折 1~k-1 作训练 → 得到 scoreₖ

最终得分 = mean(scores)
```

**变体选择**：

| 方法 | 适用场景 |
|------|----------|
| 标准 k-fold (k=5/10) | 通用，各类别均衡 |
| Stratified k-fold | 类别不均衡时保持每折的类别比例 |
| 留一法 (LOOCV) | 小数据集，计算成本高 (k=n) |
| 时间序列交叉验证 | 时序数据，防止"用未来数据验证过去" |

**关键原则：绝不使用测试集做任何决策**（模型选择、超参数调优等都应在验证集上完成），测试集仅在最终确认阶段使用一次。

## 三、特征工程

特征工程是将原始数据转换为模型可理解输入的过程。Andrew Ng 说："应用机器学习本质上是特征工程。"虽然深度学习降低了对特征工程的依赖，但在结构化数据（表格数据）场景中，好的特征仍然是性能的关键。

### 3.1 数值特征

**标准化 (Standardization, Z-score)**：

$$x_{scaled} = \frac{x - \mu}{\sigma}$$

使特征均值为 0、方差为 1。适用于假设数据符合正态分布的模型（如线性回归、逻辑回归、SVM）。对异常值相对敏感（μ 和 σ 受异常值影响）。

**Min-Max 归一化**：

$$x_{scaled} = \frac{x - x_{min}}{x_{max} - x_{min}}$$

将数据缩放到 [0, 1] 区间。适用于有明确边界的场景（如图像像素值 0-255）。对异常值极为敏感。

**分桶 (Bucketing / Binning)**：将连续值映射到离散区间。例如年龄 0-18 → 0, 18-30 → 1, 30-50 → 2, 50+ → 3。减少异常值影响，引入非线性表达能力（单个连续特征在模型中只有一种线性关系，分桶后每个桶可以有独立的权重）。

```java
// 标准化示例
double[] standardize(double[] values) {
    double mean = Arrays.stream(values).average().orElse(0);
    double std = Math.sqrt(Arrays.stream(values)
        .map(v -> (v - mean) * (v - mean)).average().orElse(1));
    return Arrays.stream(values)
        .map(v -> (v - mean) / std).toArray();
}

// 分桶示例
int bucketize(double value, double[] boundaries) {
    // boundaries = [18, 30, 50] → 4个桶: (-∞,18], (18,30], (30,50], (50,+∞)
    for (int i = 0; i < boundaries.length; i++) {
        if (value <= boundaries[i]) return i;
    }
    return boundaries.length;
}
```

### 3.2 类别特征

**One-Hot Encoding**：N 个类别 → N 维稀疏向量（仅一个位置为 1，其余为 0）。优点是简单直观，不引入虚假的序关系；缺点是类别数多时维度爆炸（如 10 万个城市 → 10 万维）。

```
类别: {中国, 美国, 日本} → One-Hot:
  中国 = [1, 0, 0]
  美国 = [0, 1, 0]
  日本 = [0, 0, 1]
```

**Label Encoding**：类别 → 整数（1, 2, 3, ...）。仅适用于有序类别（如好评/中评/差评 → 0/1/2）。滥用问题：模型会认为"日本(3) > 美国(2) > 中国(1)"，引入不存在的序关系。

**Embedding**：高维稀疏的 One-Hot 向量 → 低维稠密向量。这是理解 Word Embedding 和现代 NLP 的基础。核心思想：语义相近的类别在向量空间中距离接近。

```
One-Hot 维度:   vocab_size (如 50000)
Embedding 维度: d_model (如 128/768/4096)

表示: E ∈ R^{vocab_size × d_model}
查找: embedding["猫"] → [0.23, -0.45, 0.67, ...]
```

### 3.3 文本特征

| 方法 | 原理 | 优势 | 局限 |
|------|------|------|------|
| 词袋 (BoW) | 统计每个词出现的次数 | 简单、可解释 | 忽略词序和语义 |
| TF-IDF | 词频 × 逆文档频率 | 降低常见词权重，提升区分度 | 仍忽略词序 |
| N-gram | 连续 N 个词的组合 | 捕获局部上下文 | 维度随 N 指数增长 |

**TF-IDF 公式**：

$$TF(t, d) = \frac{\text{词 t 在文档 d 中出现次数}}{\text{文档 d 总词数}}$$

$$IDF(t) = \log\frac{\text{语料库文档总数}}{\text{包含词 t 的文档数} + 1}$$

TF-IDF(t, d) = TF(t, d) × IDF(t)。高频但无区分力的词（"的""是""在"）IDF 低；低频但高度特异的词（"核保""精算"）IDF 高。

### 3.4 特征选择

**三种策略**：

```
过滤法 (Filter)：      统计指标 → 排序 → 选 top-k
                      独立于模型，速度快，可能错过特征组合

包裹法 (Wrapper)：     候选特征子集 → 训练模型 → 评估 → 迭代
                      考虑特征交互，计算成本高

嵌入法 (Embedded)：    训练过程中自动选择（L1正则、树模型特征重要性）
                      效率和效果兼顾，最为常用
```

**常用的过滤指标**：
- **方差过滤**：去除低方差特征（大部分值相同 → 无区分力）
- **Pearson 相关系数**：衡量特征与目标的线性相关性 (-1 到 +1)
- **互信息 (Mutual Information)**：衡量特征与目标的非线性关系，不假设线性

## 四、评估指标

选择合适的指标比模型本身还关键——错误的指标会导致模型在错误的方向上"精进"。

### 4.1 分类指标

**混淆矩阵 (Confusion Matrix)**：

```
                    实际
                正类      负类
预测  正类    TP(真阳)   FP(假阳)
      负类    FN(假阴)   TN(真阴)
```

**准确率 (Accuracy)** = (TP + TN) / Total。在类别不均衡时极具欺骗性：某罕见病的发病率 1%，一个永远预测"没病"的模型准确率高达 99%，但完全无用。

**精确率 (Precision)** = TP / (TP + FP)："预测为正中，有多少是真的？"关注误报 (FP) 的代价。场景：垃圾邮件检测——把正常邮件判为垃圾的用户体验代价高。

**召回率 (Recall)** = TP / (TP + FN)："实际为正的，有多少被找出？"关注漏报 (FN) 的代价。场景：疾病筛查——漏掉一个病人代价极高。

**F1-Score** = 2 × P × R / (P + R)，精确率和召回率的调和平均：

```
P=0.9, R=0.9 → F1=0.9    (平衡)
P=0.1, R=0.9 → F1=0.18   (高召回低精确拉低 F1)
P=0.9, R=0.1 → F1=0.18   (对称，反之亦然)
```

**AUC-ROC**：ROC 曲线下的面积。横轴 FPR (1-Specificity)，纵轴 TPR (Recall)。AUC = 0.5 相当于抛硬币；AUC = 1.0 完美分类。关键优势：衡量模型的排序能力而非绝对阈值，不受类别不均衡影响（因为两个轴都是比率）。

```
AUC 解读:
  0.9-1.0  优秀
  0.8-0.9  良好
  0.7-0.8  一般
  0.5-0.7  差
  <0.5     比随机还差（可能标签反了）
```

### 4.2 回归指标

| 指标 | 公式 | 特点 |
|------|------|------|
| MSE | (1/n)Σ(ŷᵢ - yᵢ)² | 对大误差平方惩罚，对异常值极敏感 |
| MAE | (1/n)Σ\|ŷᵢ - yᵢ\| | 对异常值鲁棒，更直观 |
| R² | 1 - SS_res/SS_tot | 1=完美, 0=不如直接用均值预测 |

MSE 比 MAE 对大误差的惩罚呈平方级增长，因此：需要严格控制极端值用 MSE，更关注整体平均水平用 MAE。

### 4.3 聚类指标

- **轮廓系数 (Silhouette Score)**：[-1, 1]，越大越好。衡量簇内紧密程度（avg intra-cluster distance）和簇间分离程度（min inter-cluster distance）的平衡。
- **Davies-Bouldin Index**：越小越好。计算每个簇与其他簇的最大相似度（簇内距离/簇间距离）的平均值。

## 五、优化器

优化器决定了模型参数如何根据训练误差进行更新。深度学习时代，优化器的选择直接影响训练的收敛速度、稳定性和最终效果。

### 5.1 梯度下降家族

**SGD (随机梯度下降)**：每次随机取一个样本计算梯度并更新参数。

```
θ_{t+1} = θ_t - η · ∇L(θ_t; x_i, y_i)
```
噪声大（单样本梯度是无偏但高方差的估计），但更新快，其噪声有时能帮助跳出局部最小值。

**Mini-batch SGD**：每次取一小批样本（batch_size = 32/64/128）计算平均梯度。在单样本的高方差和全量数据的高计算成本之间平衡，同时利用 GPU 并行能力。

| Batch Size | 优点 | 缺点 |
|------------|------|------|
| 1 | 噪声可能帮助泛化 | 收敛不稳定，GPU 利用率低 |
| 32-128 | 良好平衡，默认选择 | — |
| 全量 | 梯度精确 | 内存爆炸，陷入局部最优 |

**Momentum**：在梯度下降中加入"惯性"——累积历史梯度作为动量项：

```
v_t = β · v_{t-1} + (1-β) · ∇L(θ_t)
θ_{t+1} = θ_t - η · v_t
```

β 通常取 0.9。效果：加速在平坦方向的收敛，减轻在陡峭方向的震荡——类似球滚下山坡时惯性让它越过小坑。

### 5.2 Adam 与变体

**Adam (Adaptive Moment Estimation)**：结合 Momentum（一阶矩估计）和 RMSProp（二阶矩估计），为每个参数自适应调整学习率。当前深度学习的事实默认优化器。

```
m_t = β₁ · m_{t-1} + (1-β₁) · g_t         ← 一阶矩（梯度均值）
v_t = β₂ · v_{t-1} + (1-β₂) · g_t²        ← 二阶矩（梯度方差）
m̂_t = m_t / (1-β₁ᵗ)                        ← 偏差校正
v̂_t = v_t / (1-β₂ᵗ)
θ_t = θ_{t-1} - η · m̂_t / (√v̂_t + ε)       ← 自适应步长
```

默认超参：η=0.001, β₁=0.9, β₂=0.999, ε=1e-8。

**AdamW (Adam with Decoupled Weight Decay)**：将 L2 正则化（权重衰减）从 Adam 的自适应学习率中解耦出来。这在标准 Adam 中，权重衰减与自适应学习率耦合，导致大梯度参数的正则化不足。AdamW 是当前 Transformer 训练的标准优化器（LLaMA、GPT 等均使用）。

**为什么 Adam 比 SGD 更好用？**
1. 每个参数有独立的自适应学习率——对稀疏特征（出现频率低）自动给更大学习率
2. 对超参数不那么敏感——通常默认值就够用
3. 收敛更快——尤其在训练初期
4. 坏处：泛化能力有时不如调参良好的 SGD + Momentum（Adam 的"自适应"可能导致过拟合训练数据特征）

### 5.3 学习率调度

学习率是机器学习中最重要的超参数——太大了不收敛，太小了收敛太慢。

```
调度策略        | 行为                        | 使用场景
Step Decay     | 每 N step 学习率 × γ(如0.1)  | 经典 CV 任务
Cosine         | 平滑余弦衰减，从 η₀ → η_min   | Transformer 训练标配
Warmup         | 前 N step 线性增长至目标 η    | Transformer 前几百步必须
ReduceLROnPlateau | 验证 loss 停滞时降低      | 通用训练
```

**Warmup 对 Transformer 至关重要**：训练初期，随机初始化的注意力权重可能导致梯度不稳定；warmup 让模型在一片"混乱"中先走一小步，避免参数被初期的大梯度炸飞。

## 六、反向传播 (Backpropagation)

反向传播是神经网络训练的核心算法——计算损失函数对每个参数的梯度，使得优化器能够更新参数。

### 6.1 链式法则

复合函数的导数 = 各层导数的连乘：

$$\frac{\partial L}{\partial W^{(l)}} = \frac{\partial L}{\partial a^{(L)}} \cdot \frac{\partial a^{(L)}}{\partial a^{(L-1)}} \cdot ... \cdot \frac{\partial a^{(l+1)}}{\partial W^{(l)}}$$

计算过程：

```
前向传播 (Forward Pass)：
  输入 x → 层1 → 层2 → ... → 层L → 输出 ŷ → 计算 Loss

反向传播 (Backward Pass)：
  ∂L/∂ŷ → 逐层向前传递梯度 → ∂L/∂Wₗ → 更新 Wₗ
```

**与 Java 的类比**：类似递归回溯——从输出层开始，沿着计算图反向"回溯"梯度，每到一个节点就计算该节点对最终 loss 的贡献。

### 6.2 梯度消失与梯度爆炸

这是深层网络训练的核心挑战。

**梯度消失 (Vanishing Gradient)**：深层网络中梯度逐层衰减到接近零 → 前面的层几乎学不到任何东西。根源：Sigmoid/Tanh 激活函数的导数最大值仅 0.25/1.0，多层连乘后指数衰减。

**梯度爆炸 (Exploding Gradient)**：梯度逐层放大 → 参数更新巨大 → 训练崩溃（loss → NaN）。解决：梯度裁剪 (Gradient Clipping) — 限制梯度向量的最大范数。

**残差连接 (Residual Connection)** 是解决梯度消失的关键创新：将层的输出改为 F(x) + x（跨层直接连接）。梯度可通过恒等路径直接回传，不会因深层乘法而消失。Transformer 的每一层都使用了残差连接。

```
无残差:  x → Layer → F(x)      ∂F(x)/∂x 可能很小
有残差:  x → Layer → F(x) + x  ∂(F(x)+x)/∂x = ∂F(x)/∂x + 1 ≥ 1
                                                              ↑
                                                    恒等梯度永远不会消失
```

## 七、Java 中的 ML

虽然 Python 是 ML/AI 生态的绝对主导语言，但 JVM 生态中仍有几个成熟的 ML 库，适合在 Java 项目中嵌入轻量级 ML 任务。

### 7.1 Smile (Statistical Machine Intelligence & Learning Engine)

纯 Java 实现，无外部依赖，API 简洁。包含分类、回归、聚类、特征选择、可视化等完整功能栈。

```java
import smile.classification.KNN;
import smile.data.DataFrame;
import smile.data.formula.Formula;
import smile.io.Read;

// 使用 Smile 进行 KNN 分类（Iris 数据集）
void knnOnIris() throws Exception {
    // 1. 加载 Iris 数据集
    var iris = Read.arff("data/iris.arff");

    // 2. 转换为特征数组和标签数组
    double[][] X = iris.select(0, 1, 2, 3).toArray(); // 4个特征列
    int[] y = iris.column("class").toIntArray();         // 类别标签

    // 3. 训练 KNN 分类器 (k=3)
    var knn = KNN.fit(X, y, 3);

    // 4. 预测新样本
    double[] newFlower = {5.1, 3.5, 1.4, 0.2}; // 花萼长/宽, 花瓣长/宽
    int predictedClass = knn.predict(newFlower);
    System.out.println("预测类别: " + predictedClass);
}
```

Smile 适合 JVM 内嵌的轻量级 ML 任务（如表格数据的分类/回归/聚类），不涉及深度学习。

### 7.2 Tribuo (Oracle Labs)

Oracle 开源的 Java ML 库，强调类型安全和生产就绪。核心抽象使用强类型泛型——`Feature<T>` 编译时保证类型安全，`Dataset<T>` 泛型在标签类型上。

```java
import org.tribuo.*;
import org.tribuo.classification.Label;
import org.tribuo.classification.sgd.linear.LinearSGDTrainer;
import org.tribuo.data.csv.CSVLoader;
import org.tribuo.evaluation.TrainTestSplitter;

import java.nio.file.Path;

// 使用 Tribuo 进行文本特征提取+逻辑回归分类
void textClassification() throws Exception {
    // 1. 加载 CSV 数据（假设列: "text" + "label"）
    var csvLoader = new CSVLoader<>(new LabelFactory());
    var csvPath = Path.of("data/sentiment.csv");
    var textExtractor = csvLoader.getRowExtractor("text");
    var labelExtractor = csvLoader.getRowExtractor("label");
    var dataSource = new SimpleDataSource<>(csvPath, labelExtractor,
        new String[]{"text"});

    // 2. 训练-测试切分 (80/20)
    var splitter = new TrainTestSplitter<>(dataSource, 0.8, 1L);
    var trainData = new MutableDataset<>(splitter.getTrain());
    var testData = new MutableDataset<>(splitter.getTest());

    // 3. 训练逻辑回归分类器
    var trainer = new LinearSGDTrainer();
    var model = trainer.train(trainData);

    // 4. 评估
    var evaluation = (LabelEvaluation) model.evaluate(testData);
    System.out.println("准确率: " + evaluation.accuracy());
    System.out.println("F1: " + evaluation.f1());
}
```

Tribuo 集成 ONNX Runtime、XGBoost、TensorFlow，适合需要生产级 ML Pipeline 的 Java 项目。

### 7.3 JDK 25 Vector API (Incubator) — 向量相似度

JDK 16+ 引入的 Vector API（孵化中）允许在 Java 中编写跨平台的 SIMD 向量化计算，可用于高性能向量相似度计算。

```java
import jdk.incubator.vector.FloatVector;
import jdk.incubator.vector.VectorSpecies;

// 使用 Vector API 计算余弦相似度（SIMD加速）
float cosineSimilarityVectorApi(float[] a, float[] b) {
    var species = FloatVector.SPECIES_PREFERRED;
    int length = species.length();

    // 使用 Vector API 并行计算 dot(a, b), ||a||², ||b||²
    float dot = 0, normA = 0, normB = 0;
    int i = 0;
    for (; i < species.loopBound(a.length); i += length) {
        var va = FloatVector.fromArray(species, a, i);
        var vb = FloatVector.fromArray(species, b, i);
        dot += va.mul(vb).reduceLanesToLong();
        normA += va.mul(va).reduceLanesToLong();
        normB += vb.mul(vb).reduceLanesToLong();
    }

    // 处理尾部元素
    for (; i < a.length; i++) {
        dot += a[i] * b[i];
        normA += a[i] * a[i];
        normB += b[i] * b[i];
    }

    return dot / (float) (Math.sqrt(normA) * Math.sqrt(normB));
}
```

> ⚠️ 技术雷达注意：JDK Vector API 当前为 Incubator 状态（`jdk.incubator.vector`），需要 `--add-modules jdk.incubator.vector` 编译选项，不建议直接用于生产。对于向量检索，推荐使用 pgvector、Redis Vector Search 等成熟方案。

### 7.4 DeepLearning4j

JVM 深度学习框架，支持 GPU 训练（通过 ND4J 后端）。适合需要深度学习模型且必须留在 JVM 生态的项目。但社区活跃度和模型生态远不及 PyTorch/TensorFlow。建议：训练用 Python，推理用 ONNX Runtime Java 或 DJL。

## 八、常见问题

**Q1: 如何检测和处理过拟合？**

检测：监控训练 loss 和验证 loss 的走势。验证 loss 开始上升而训练 loss 继续下降时，过拟合已经开始。解决（按优先级排序）：(1) 增加训练数据（最有效）；(2) 降低模型复杂度（减少层数/参数量）；(3) 增加正则化（L2/Dropout/Early Stopping）；(4) 数据增强（对图像旋转/裁剪，对文本回译/同义词替换）。在 LLM 时代，过拟合通常不是首要问题——模型太大、数据太多，欠拟合反而更常见。

**Q2: 为什么 Adam 比 SGD 更好用？**

Adam 为每个参数维护独立的自适应学习率，对稀疏特征自动给更大步长，对频繁特征自动给更小步长。这意味着：(1) 不需要精细调参，默认值就工作得很好；(2) 对参数尺度不敏感（不同层的参数可能差几个数量级）；(3) 收敛更快，尤其在大 batch 训练时。但注意：Adam 泛化能力在某些经典 CV 任务上可能不如调参良好的 SGD + Momentum。对于 Transformer 训练，AdamW 是当前标准选择。

**Q3: 特征工程的优先级？**

在表格数据场景中，特征工程对效果的影响往往大于模型选择。优先级：数据清洗（缺失值/异常值）> 特征创建（基于领域知识构造新特征）> 特征转换（标准化/分桶/编码）> 特征选择（去冗余）。对于 NLP 场景（使用预训练模型时），手工特征工程的重要性大幅下降——模型自己从原始文本中学到特征。但在召回/排序等检索任务中，手工特征（如 BM25 分数、点击率）仍然很有价值。

**Q4: 分类问题选 AUC-ROC 还是 F1？**

AUC-ROC 衡量模型的排序能力——对正负样本的整体区分度，不受具体阈值影响。适用场景：不关心具体阈值，只需要"正样本排在负样本前面"，且类别相对均衡。F1 衡量在特定阈值下的精确率和召回率平衡。适用场景：需要做出具体的"是/否"决策，且精确率和召回率都很重要。实际建议：看 AUC-ROC 了解模型整体质量，看 F1（或更细化的 P-R 曲线）做业务决策。

**Q5: Java ML 库选型建议？**

```
场景                                   | 推荐
只是表格数据的分类/回归（轻量）         | Smile（纯 Java，API 最简单）
需要完整的 ML Pipeline + 类型安全      | Tribuo（Oracle 维护，生态好）
需要在 JVM 上跑深度学习模型（推理）     | ONNX Runtime Java / DJL
需要训练深度学习模型                    | Python（PyTorch），别在 JVM 上折腾
做向量相似度计算                        | pgvector / Redis / 成熟向量数据库
```

核心原则：Java 适合 ML Pipeline 的工程化和部署，不适合模型的训练和实验。训练交给 Python 生态，推理时通过 ONNX Runtime Java 或 API 调用的方式回到 JVM。

**Q6: 机器学习中的 epoch、batch、iteration 有什么区别？**

假设有 1000 条训练数据，batch_size=100：
- 1 iteration = 处理 1 个 batch（100 条）的前向 + 反向传播
- 1 epoch = 遍历全部 1000 条训练数据一次 = 10 iterations
- N epochs = 遍历全部数据 N 次

Batch size 的选择是训练速度和梯度质量的权衡——太小噪声大，太大泛化能力可能下降。

**Q7: 标准化和归一化有什么区别，什么时候用哪个？**

标准化 (Z-score)：使数据符合标准正态分布 N(0,1)；适合假设正态分布的模型（线性回归、逻辑回归、SVM）。归一化 (Min-Max)：缩放到 [0,1]；适合需要固定输入范围的场景（如神经网络使用 Sigmoid 输出时）或数据本身有明确边界。对包含异常值的数据，优先使用 Robust Scaling（中位数 + IQR）而非上述两者。
