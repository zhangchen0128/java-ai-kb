# 缓存策略与多级缓存架构

> **性能数据声明：** 除非具体表格同时给出硬件、软件版本、数据规模、参数、

## 概述

缓存是提升分布式系统性能的核心手段。合理的缓存策略可以降低数据库负载、减少响应延迟、提高系统吞吐量。在 AI 应用中，语义缓存（Semantic Cache）作为新兴模式，通过相似度匹配复用 LLM 响应，显著降低 API 调用成本。

本文深入四大缓存模式原理、五大缓存问题的系统性解决方案、Caffeine + Redis 多级缓存架构、缓存一致性方案，以及 AI 语义缓存的实现。

## 一、缓存模式

### 1.1 Cache-Aside（旁路缓存）

最常用的缓存模式，应用代码直接控制缓存和数据库的读写。

```
读操作：
┌─────────┐  (1) GET    ┌──────────┐
│ 应用代码  │ ──────────▶ │  Cache    │
│         │ ◀── miss ── │          │
│         │             └──────────┘
│         │  (2) query   ┌──────────┐
│         │ ──────────▶ │  DB       │
│         │ ◀── data ── │          │
│         │             └──────────┘
│         │  (3) SET    ┌──────────┐
│         │ ──────────▶ │  Cache    │
└─────────┘             └──────────┘

写操作：
┌─────────┐  (1) UPDATE ┌──────────┐
│ 应用代码  │ ──────────▶ │  DB       │
│         │             └──────────┘
│         │  (2) DELETE ┌──────────┐
│         │ ──────────▶ │  Cache    │
└─────────┘             └──────────┘
```

```java
@Service
public class CacheAsideUserService {

    private final UserRepository userRepo;
    private final StringRedisTemplate redis;

    public User getUser(Long userId) {
        // 1. 查缓存
        var cached = redis.opsForValue().get("user:" + userId);
        if (cached != null) {
            return JsonUtils.fromJson(cached, User.class);
        }

        // 2. 查数据库
        var user = userRepo.findById(userId)
                .orElseThrow(() -> new NotFoundException("用户不存在"));

        // 3. 写缓存（设置随机 TTL 防止雪崩）
        var ttl = Duration.ofMinutes(30 + ThreadLocalRandom.current().nextInt(10));
        redis.opsForValue().set("user:" + userId,
                JsonUtils.toJson(user), ttl);

        return user;
    }

    public void updateUser(Long userId, UserDto dto) {
        // 1. 更新数据库
        userRepo.update(userId, dto);

        // 2. 删除缓存（而非更新，避免并发时序问题）
        redis.delete("user:" + userId);
    }
}
```

### 1.2 Read/Write Through

缓存层充当数据库的代理，应用代码只与缓存交互。

```java
// Spring Cache 抽象实现 Read/Write Through
// 应用代码只操作缓存，缓存层负责和 DB 同步

@Service
public class ReadThroughUserService {

    @Cacheable(value = "users", key = "#userId",
               unless = "#result == null")
    public User getUser(Long userId) {
        // 缓存未命中时此方法被调用，结果自动写入缓存
        return userRepo.findById(userId).orElse(null);
    }

    @CachePut(value = "users", key = "#user.id")
    public User updateUser(User user) {
        userRepo.save(user);
        return user;
    }

    @CacheEvict(value = "users", key = "#userId")
    public void deleteUser(Long userId) {
        userRepo.deleteById(userId);
    }
}
```

### 1.3 Write Behind（异步写回）

写入先记到缓存，异步批量写入数据库。

```java
@Service
public class WriteBehindService {

    private final StringRedisTemplate redis;
    private final UserRepository userRepo;
    private final ScheduledExecutorService scheduler = Executors.newSingleThreadScheduledExecutor();

    private final ConcurrentHashMap<Long, User> writeBuffer = new ConcurrentHashMap<>();

    public WriteBehindService() {
        // 每 5 秒批量刷入数据库
        scheduler.scheduleAtFixedRate(this::flushToDb, 5, 5, TimeUnit.SECONDS);
    }

    public void updateUser(User user) {
        // 1. 立即更新缓存
        redis.opsForValue().set("user:" + user.getId(),
                JsonUtils.toJson(user), Duration.ofHours(1));

        // 2. 加入写缓冲（异步批量刷 DB）
        writeBuffer.put(user.getId(), user);
    }

    private void flushToDb() {
        if (writeBuffer.isEmpty()) return;

        var batch = new HashMap<>(writeBuffer);
        writeBuffer.clear();

        // 批量更新数据库
        try {
            userRepo.batchUpdate(batch.values());
        } catch (Exception e) {
            // 失败回写入缓冲区等待重试
            writeBuffer.putAll(batch);
        }
    }
}
```

**风险提示：** Write Behind 在缓存掉电/崩溃时会丢失未刷入数据库的数据。仅在数据可丢失（如统计数据、日志计数）时使用，或配合持久化消息队列。

### 1.4 Refresh Ahead（提前刷新）

热点 Key 在过期前自动异步刷新，避免缓存击穿。

```java
@Configuration
public class RefreshAheadCacheConfig {

    @Bean
    public CacheManager cacheManager() {
        var caffeine = Caffeine.newBuilder()
                .maximumSize(10_000)
                .expireAfterWrite(30, TimeUnit.MINUTES)
                .refreshAfterWrite(25, TimeUnit.MINUTES) // TTL 前 5 分钟异步刷新
                .scheduler(Scheduler.systemScheduler())
                .build();

        var cacheManager = new CaffeineCacheManager();
        cacheManager.setCaffeine(caffeine);
        return cacheManager;
    }
}

@Service
public class HotDataService {

    @Cacheable(value = "hot-products", key = "#productId")
    public Product getHotProduct(Long productId) {
        return productRepo.findById(productId).orElse(null);
    }

    // 结合 @Cacheable + CacheLoader 实现自动刷新
    public Product getWithAutoRefresh(Long productId) {
        var cache = Caffeine.newBuilder()
                .expireAfterWrite(30, TimeUnit.MINUTES)
                .refreshAfterWrite(25, TimeUnit.MINUTES)
                .build(productIdKey -> {
                    log.info("Async refreshing product: {}", productIdKey);
                    return productRepo.findById((Long) productIdKey).orElse(null);
                });

        return cache.get(productId);
    }
}
```

## 二、缓存问题与解决方案

### 2.1 缓存穿透（Cache Penetration）

**问题：** 查询不存在的数据，缓存无记录，每次请求直达数据库。

```
解决方案矩阵：
┌──────────────────┬──────────┬──────────┬───────────────┐
│ 方案              │ 复杂度   │ 可靠性   │ 适用场景       │
├──────────────────┼──────────┼──────────┼───────────────┤
│ 布隆过滤器         │ 中       │ 高       │ 大量不存在的Key │
│ 空对象缓存         │ 低       │ 中       │ 少数不存在的Key │
│ 参数校验           │ 低       │ 高       │ 格式固定的Key   │
│ 黑名单             │ 低       │ 中       │ 恶意攻击       │
└──────────────────┴──────────┴──────────┴───────────────┘
```

**布隆过滤器实现：**

```java
@Service
public class BloomFilterGuard {

    private final BloomFilter<String> bloomFilter;
    private final StringRedisTemplate redis;

    // 使用 Redis 布隆过滤器模块（redisson 也有实现）
    public User getUser(String userId) {
        // 1. 布隆过滤器快速判断（不存在则 100% 确定不存在）
        var exists = redis.opsForValue()
                .getOperations().execute((RedisCallback<Boolean>) conn ->
                        conn.execute("BF.EXISTS",
                                "user:bloom".getBytes(), userId.getBytes()));

        if (Boolean.FALSE.equals(exists)) {
            return null; // 一定不存在
        }

        // 2. 走正常缓存+数据库查询
        return queryWithCache(userId);
    }

    // 数据写入时更新布隆过滤器
    public void onUserCreated(User user) {
        userRepo.save(user);
        redis.opsForValue()
                .getOperations().execute((RedisCallback<Void>) conn -> {
                    conn.execute("BF.ADD",
                            "user:bloom".getBytes(),
                            String.valueOf(user.getId()).getBytes());
                    return null;
                });
    }
}
```

**空对象缓存（简单方案）：**

```java
public User getUserWithNullCache(Long userId) {
    var key = "user:" + userId;
    var cached = redis.opsForValue().get(key);
    if (cached != null) {
        return "NULL".equals(cached) ? null : JsonUtils.fromJson(cached, User.class);
    }

    var user = userRepo.findById(userId).orElse(null);

    if (user == null) {
        // 缓存空对象（短 TTL）
        redis.opsForValue().set(key, "NULL", Duration.ofMinutes(5));
        return null;
    }

    redis.opsForValue().set(key, JsonUtils.toJson(user), Duration.ofMinutes(30));
    return user;
}
```

### 2.2 缓存击穿（Hotspot Invalid）

**问题：** 热点 Key 在过期瞬间，大量请求穿透到数据库。

**方案一：互斥锁**

```java
public User getHotUserWithMutex(Long userId) {
    var key = "user:" + userId;
    var cached = redis.opsForValue().get(key);
    if (cached != null) return JsonUtils.fromJson(cached, User.class);

    var lockKey = "lock:user:" + userId;
    try {
        // 尝试获取锁（SET NX PX）
        if (redis.opsForValue().setIfAbsent(lockKey, "1", Duration.ofSeconds(10))) {
            // Double Check
            cached = redis.opsForValue().get(key);
            if (cached != null) return JsonUtils.fromJson(cached, User.class);

            // 查 DB 并写缓存
            var user = userRepo.findById(userId)
                    .orElseThrow(() -> new NotFoundException("用户不存在"));
            redis.opsForValue().set(key, JsonUtils.toJson(user), Duration.ofMinutes(30));
            return user;
        } else {
            // 获取锁失败 → 等待 + 重试
            Thread.sleep(50);
            return getHotUserWithMutex(userId); // 递归重试
        }
    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();
        throw new RuntimeException(e);
    } finally {
        redis.delete(lockKey);
    }
}
```

**方案二：逻辑过期（永不过期 + 异步更新）**

```java
public record CachedValue<T>(T data, LocalDateTime expireAt) {}

public User getHotUserWithLogicalExpire(Long userId) {
    var key = "user:" + userId;
    var cached = redis.opsForValue().get(key);
    if (cached == null) {
        return queryAndCache(userId);
    }

    var cachedValue = JsonUtils.fromJson(cached, CachedValue.class);
    if (cachedValue.expireAt().isAfter(LocalDateTime.now())) {
        // 未过期，直接返回
        return (User) cachedValue.data();
    }

    // 已逻辑过期 → 获取互斥锁，异步更新
    var lockKey = "lock:user:" + userId;
    if (redis.opsForValue().setIfAbsent(lockKey, "1", Duration.ofSeconds(10))) {
        try {
            Thread.startVirtualThread(() -> { // Virtual Thread 异步更新
                var user = userRepo.findById(userId).orElse(null);
                if (user != null) {
                    var newCached = new CachedValue<>(user,
                            LocalDateTime.now().plusMinutes(30));
                    redis.opsForValue().set(key, JsonUtils.toJson(newCached));
                }
                redis.delete(lockKey);
            });
        } catch (Exception e) {
            redis.delete(lockKey);
        }
    }

    // 返回旧数据（小幅过期可以接受）
    return (User) cachedValue.data();
}
```

**问题：** 大量缓存 Key 在同一时间段过期，导致数据库压力激增。

public String cacheWithRandomTTL(String key, Object value, Duration baseTTL) {

### 2.4 热点 Key 发现

<!-- code-id: hot-key-tracker -->
```java
import java.time.Duration;
import java.util.HashMap;
import java.util.Map;
import java.util.Objects;
import java.util.function.LongSupplier;

public final class HotKeyTracker {
    private static final int DEFAULT_MAX_TRACKED_KEYS = 10_000;

    @FunctionalInterface
    public interface PromotionListener {
        void promote(String key, int requestsInWindow);
    }

    public record Observation(
            int requestsInWindow,
            boolean promotedNow,
            boolean tracked) {}

    private final int threshold;
    private final long windowMillis;
    private final int maxTrackedKeys;
    private final LongSupplier clock;
    private final PromotionListener listener;
    private final Map<String, WindowCounter> counters = new HashMap<>();

    public HotKeyTracker(
            int threshold, Duration window, PromotionListener listener) {
        this(
            threshold,
            window,
            DEFAULT_MAX_TRACKED_KEYS,
            System::currentTimeMillis,
            listener
        );
    }

    HotKeyTracker(
            int threshold,
            Duration window,
            int maxTrackedKeys,
            LongSupplier clock,
            PromotionListener listener) {
        Objects.requireNonNull(window, "window");
        long resolvedWindowMillis = window.toMillis();
        if (threshold <= 0 || resolvedWindowMillis <= 0 || maxTrackedKeys <= 0) {
            throw new IllegalArgumentException(
                "threshold, millisecond window, and maxTrackedKeys must be positive"
            );
        }
        this.threshold = threshold;
        this.windowMillis = resolvedWindowMillis;
        this.maxTrackedKeys = maxTrackedKeys;
        this.clock = Objects.requireNonNull(clock, "clock");
        this.listener = Objects.requireNonNull(listener, "listener");
    }

    public Observation recordAccess(String key) {
        if (key == null || key.isBlank()) {
            throw new IllegalArgumentException("key must not be blank");
        }

        long windowId = Math.floorDiv(clock.getAsLong(), windowMillis);
        Observation observation;
        String keyToPromote = null;
        synchronized (this) {
            var counter = counters.get(key);
            if (counter == null) {
                counters.entrySet().removeIf(
                    entry -> entry.getValue().windowId != windowId
                );
                if (counters.size() >= maxTrackedKeys) {
                    return new Observation(0, false, false);
                }
                counter = new WindowCounter(windowId);
                counters.put(key, counter);
            } else if (counter.windowId != windowId) {
                counter = new WindowCounter(windowId);
                counters.put(key, counter);
            }

            counter.requests++;
            boolean promotedNow =
                counter.requests >= threshold && !counter.promoted;
            if (promotedNow) {
                counter.promoted = true;
                keyToPromote = key;
            }
            observation = new Observation(counter.requests, promotedNow, true);
        }

        // Redis/Caffeine 提升动作可能阻塞，不能占用计数表的内部锁
        if (keyToPromote != null) {
            listener.promote(keyToPromote, observation.requestsInWindow());
        }
        return observation;
    }

    private static final class WindowCounter {
        private final long windowId;
        private int requests;
        private boolean promoted;

        private WindowCounter(long windowId) {
            this.windowId = windowId;
        }
    }
}
```

`PromotionListener` 将热点判断与 Caffeine/Redis 提升动作解耦，回调在内部锁
之外执行。追踪表设置 10,000 个 Key 的默认上限，并在窗口轮换时清理过期项，
避免高基数输入耗尽内存；`tracked=false` 时调用方应采样、告警或降级。对应
实验验证阈值只触发一次、窗口轮换后重新计数、容量上限，以及 100 个并发
访问只产生一次提升事件。

## 三、多级缓存架构

### 3.1 Caffeine(L1) + Redis(L2) + DB(L3)

```
请求流程：
         ┌──────────────┐
         │   请求        │
         └──────┬───────┘
                ▼
         ┌──────────────┐
         │ L1: Caffeine  │ ← 命中 → 直接返回 (< 1µs)
         │ (JVM 本地)    │
         └──┬───────┬───┘
            miss    ▼
         ┌──────────────┐
         │ L2: Redis     │ ← 命中 → 返回 + 回写 L1
         │ (分布式缓存)   │
         └──┬───────┬───┘
            miss    ▼
         ┌──────────────┐
         │ L3: PostgreSQL│ ← 查询 → 写 L2 → 写 L1 → 返回
         └──────────────┘
```

```java
@Configuration
public class MultiLevelCacheConfig {

    @Bean
    public CacheManager cacheManager() {
        // Caffeine L1 配置
        var caffeine = Caffeine.newBuilder()
                .maximumSize(10_000)
                .expireAfterWrite(5, TimeUnit.MINUTES)
                .recordStats()
                .build();

        var cacheManager = new SimpleCacheManager();
        cacheManager.setCaches(List.of(
                new CaffeineCache("products", caffeine)
        ));
        return cacheManager;
    }
}

@Service
public class MultiLevelCacheService {

    private final CacheManager cacheManager;
    private final StringRedisTemplate redis;
    private final ProductRepository productRepo;

    public Product getProduct(Long productId) {
        var cacheName = "products";

        // L1: Caffeine
        var l1Cache = cacheManager.getCache(cacheName);
        if (l1Cache != null) {
            var cached = l1Cache.get(productId, Product.class);
            if (cached != null) return cached;
        }

        // L2: Redis
        var redisKey = "product:" + productId;
        var redisValue = redis.opsForValue().get(redisKey);
        if (redisValue != null) {
            var product = JsonUtils.fromJson(redisValue, Product.class);
            // 回写 L1
            if (l1Cache != null) l1Cache.put(productId, product);
            return product;
        }

        // L3: PostgreSQL + 互斥锁防击穿
        var lockKey = "lock:product:" + productId;
        try {
            if (redis.opsForValue().setIfAbsent(lockKey, "1", Duration.ofSeconds(10))) {
                var product = productRepo.findById(productId)
                        .orElseThrow(() -> new NotFoundException("商品不存在"));

                // 写 L2 + L1
                redis.opsForValue().set(redisKey,
                        JsonUtils.toJson(product),
                        Duration.ofMinutes(30 + ThreadLocalRandom.current().nextInt(5)));
                if (l1Cache != null) l1Cache.put(productId, product);

                return product;
            } else {
                Thread.sleep(50);
                return getProduct(productId); // 重试
            }
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            throw new RuntimeException(e);
        } finally {
            redis.delete(lockKey);
        }
    }
}
```

### 3.2 缓存更新广播（多实例同步）

public class CacheSyncListener {

    private final CacheManager cacheManager;

    @EventListener
    public void onCacheEvict(CacheEvictEvent event) {

        redis.convertAndSend("cache-sync", message);
    }
}

## 四、缓存一致性方案

### 4.1 Canal + Binlog 异步更新

```
MySQL Binlog → Canal Server → Kafka → 缓存更新消费者
```

```java
@Component
public class CanalCacheSync {

    private final StringRedisTemplate redis;
    private final CacheManager localCache;

    @KafkaListener(topics = "canal-product-changes", groupId = "cache-sync")
    public void onProductChanged(CanalMessage msg) {
        var productId = extractProductId(msg);
        var operation = msg.getType();

        switch (operation) {
            case "INSERT", "UPDATE" -> {
                // 更新 Redis
                redis.opsForValue().set("product:" + productId,
                        JsonUtils.toJson(msg.getAfter()),
                        Duration.ofMinutes(30));
                // 失效本地缓存
                var cache = localCache.getCache("products");
                if (cache != null) cache.evict(productId);
            }
            case "DELETE" -> {
                redis.delete("product:" + productId);
                var cache = localCache.getCache("products");
                if (cache != null) cache.evict(productId);
            }
        }
    }
}
```

- 商品信息：< 5s
- 用户配置：< 30s

## 五、AI 语义缓存（Semantic Cache）

```java
@Service
public class SemanticCacheService {

    private final EmbeddingModel embeddingModel;
    private final SemanticCacheIndex index;
    private static final double SIMILARITY_THRESHOLD = 0.92;

    public SemanticCacheService(EmbeddingModel embeddingModel, SemanticCacheIndex index) {
        this.embeddingModel = embeddingModel;
        this.index = index;
    }

    public Optional<String> findSimilarQuery(String userQuery) {
        var embedding = embeddingModel.embed(userQuery);
        return index.search(embedding, 5).stream()
            .filter(hit -> hit.similarity() >= SIMILARITY_THRESHOLD)
            .max(Comparator.comparingDouble(CacheHit::similarity))
            .map(CacheHit::response);
    }

    public void cacheQueryResponse(String query, String response) {
        var embedding = embeddingModel.embed(query);
        index.put(UUID.randomUUID().toString(), query, response, embedding);
    }
}

public record CacheHit(String response, double similarity) {}

/**
 * Redis Stack 适配器负责把 search 映射为 FT.SEARCH KNN，
 * 把 put 映射为 HSET；业务服务不依赖 Redis 命令字节协议。
 */
public interface SemanticCacheIndex {
    List<CacheHit> search(float[] embedding, int topK);
    void put(String id, String query, String response, float[] embedding);
}
```

## 常见问题

**Q: 数据更新后，删缓存还是更新缓存？**
A: 删除缓存。更新缓存可能导致并发时序问题，惰性加载（下次查询再写）更安全。

**Q: 缓存和数据不一致怎么办？**
A: 设计阶段就接受"最终一致性窗口"。通过 TTL 限制不一致持续时间。金融关键数据不依赖缓存。

**Q: Caffeine 和 Guava Cache 选哪个？**
A: Caffeine 是 Guava Cache 的后继者，使用 W-TinyLFU 淘汰策略，命中率更高。推荐 Caffeine。

**Q: 多级缓存的管理复杂度值得吗？**
A: 对于 QPS < 1000 的服务，单级 Redis 缓存足够。QPS > 10000 时，Caffeine L1 缓存可显著减少 Redis 网络开销。

**Q: 语义缓存的成本收益比？**
A: 如果模型 API 调用成本高（如 GPT-4），语义缓存可节省 20-40% 的调用。需要权衡 Embedding 计算成本 + Redis 向量存储成本。
