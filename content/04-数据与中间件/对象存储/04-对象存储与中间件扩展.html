对象存储、RabbitMQ 与中间件扩展

概述

对象存储是 AI 数据工程的基础设施，承载着从原始文档上传到向量索引的完整文件链路。RabbitMQ 作为传统消息中间件，在轻量级消息路由、死信队列、延迟消息等场景仍不可替代。

本文涵盖 MinIO 部署和集成、S3 兼容 API、AI 文档存储链路、RabbitMQ 核心概念与选型对比、对象存储安全最佳实践。

1.3 预签名 URL

预签名 URL 是对象存储的安全访问模式，允许临时授权而无需暴露访问密钥。

java
@Service
public class MinioPresignedUrlService {

    private final MinioClient minioClient;

    // 生成上传预签名 URL（PUT）
    public String generateUploadUrl(String objectName, Duration expiry) {
        try {
            var args = GetPresignedObjectUrlArgs.builder()
                    .method(Method.PUT)
                    .bucket("ai-documents")
                    .object(objectName)
                    .expiry((int) expiry.getSeconds())
                    .build();
            return minioClient.getPresignedObjectUrl(args);
        } catch (Exception e) {
            throw new StorageException("Failed to generate upload URL", e);
        }
    }

    // 生成下载预签名 URL（GET）
    public String generateDownloadUrl(String objectName, Duration expiry) {
        try {
            var args = GetPresignedObjectUrlArgs.builder()
                    .method(Method.GET)
                    .bucket("ai-documents")
                    .object(objectName)
                    .expiry((int) expiry.getSeconds())
                    .build();
            return minioClient.getPresignedObjectUrl(args);
        } catch (Exception e) {
            throw new StorageException("Failed to generate download URL", e);
        }
    }

    // 结合自定义响应头的预签名 URL
    public String generateDownloadUrlWithHeaders(String objectName,
                                                  String contentDisposition) {
        try {
            var reqParams = new HashMap<String, String>();
            reqParams.put("response-content-disposition",
                    "attachment; filename=\"" + contentDisposition + "\"");

            var args = GetPresignedObjectUrlArgs.builder()
                    .method(Method.GET)
                    .bucket("ai-documents")
                    .object(objectName)
                    .expiry(3600)
                    .extraQueryParams(reqParams)
                    .build();
            return minioClient.getPresignedObjectUrl(args);
        } catch (Exception e) {
            throw new StorageException("Failed to generate download URL", e);
        }
    }
}

二、S3 兼容 API

2.1 核心操作

java
@Service
public class S3DocumentService {

    private final MinioClient minio;
    private static final String BUCKET = "ai-documents";

    // PutObject
    public void uploadDocument(String key, InputStream data, long size,
                                String contentType, Map<String, String> metadata) {
        try {
            minio.putObject(PutObjectArgs.builder()
                    .bucket(BUCKET)
                    .object(key)
                    .stream(data, size, -1)
                    .contentType(contentType)
                    .userMetadata(metadata)  // 自定义元数据
                    .build());
        } catch (Exception e) {
            throw new StorageException("Upload failed: " + key, e);
        }
    }

    // GetObject
    public InputStream downloadDocument(String key) {
        try {
            return minio.getObject(GetObjectArgs.builder()
                    .bucket(BUCKET)
                    .object(key)
                    .build());
        } catch (Exception e) {
            throw new StorageException("Download failed: " + key, e);
        }
    }

    // DeleteObject
    public void deleteDocument(String key) {
        try {
            minio.removeObject(RemoveObjectArgs.builder()
                    .bucket(BUCKET)
                    .object(key)
                    .build());
        } catch (Exception e) {
            throw new StorageException("Delete failed: " + key, e);
        }
    }

    // HeadObject（获取元数据）
    public Map<String, String> getMetadata(String key) {
        try {
            var stat = minio.statObject(StatObjectArgs.builder()
                    .bucket(BUCKET)
                    .object(key)
                    .build());
            return stat.userMetadata();
        } catch (Exception e) {
            throw new StorageException("Stat failed: " + key, e);
        }
    }

    // ListObjects（带前缀过滤）
    public List<String> listDocuments(String prefix) {
        var keys = new ArrayList<String>();
        var results = minio.listObjects(ListObjectsArgs.builder()
                .bucket(BUCKET)
                .prefix(prefix)
                .recursive(true)
                .build());
        results.forEach(item -> {
            try {
                keys.add(item.get().objectName());
            } catch (Exception e) {
                throw new StorageException("List failed", e);
            }
        });
        return keys;
    }
}

2.2 分段上传（Multipart Upload）

大文件（>5MB）推荐使用分段上传，支持断点续传和并行上传。

java
public void uploadLargeFile(String key, Path filePath) {
    try {
        // 1. 初始化分段上传
        var uploadId = minio.createMultipartUpload(BUCKET, null, key, null, null);

        // 2. 上传各部分（每部分 >= 5MB，最多 10000 部分）
        var parts = new ArrayList<ComposeSource>();
        var partSize = 10 * 1024 * 1024; // 10MB
        var fileSize = Files.size(filePath);
        var partCount = (int) Math.ceil((double) fileSize / partSize);

        try (var fileStream = Files.newInputStream(filePath)) {
            for (int i = 0; i < partCount; i++) {
                long currentPartSize = Math.min(partSize, fileSize - (long) i * partSize);
                var part = minio.uploadPart(
                        BUCKET, null, key,
                        uploadId,
                        fileStream, currentPartSize,
                        i + 1, null, null);
                parts.add(part);
            }
        }

        // 3. 完成分段上传
        minio.completeMultipartUpload(BUCKET, null, key, uploadId, parts.toArray(new Part[0]));

    } catch (Exception e) {
        // 中止分段上传清理残留部分
        try {
            minio.abortMultipartUpload(BUCKET, null, key, uploadId);
        } catch (Exception ex) {
            log.error("Abort multipart upload failed", ex);
        }
        throw new StorageException("Large file upload failed: " + key, e);
    }
}

三、AI 场景：文档存储链路

3.1 完整文件链路

原始文件上传 → 预处理 → 切片 → 向量索引

详细路径：
1. 用户上传 PDF/Word/HTML
   存储路径: raw/{tenant_id}/{doc_id}/original.{ext}
   
2. Apache Tika 解析 → Markdown
   存储路径: processed/{tenant_id}/{doc_id}/content.md
   
3. 语义切片
   存储路径: chunks/{tenant_id}/{doc_id}/chunk_{seq}.txt
   元数据: {chunk_index, start_offset, end_offset, token_count}
   
4. Embedding 向量化
   存储: pgvector / Elasticsearch dense_vector
   关联: chunk_path → embedding → vector_id

3.2 Java 实现示例

java
@Service
public class DocumentPipelineService {

    private static final String RAW_PREFIX = "raw/";
    private static final String PROCESSED_PREFIX = "processed/";
    private static final String CHUNK_PREFIX = "chunks/";

    private final MinioClient minio;
    private final DocumentParser parser;      // Apache Tika
    private final ChunkingStrategy chunker;   // 语义切片
    private final EmbeddingService embedder;  // Embedding 生成
    private final VectorStore vectorStore;    // pgvector

    public record DocPipelineResult(String docId, int chunkCount, long totalTokens) {}

    public DocPipelineResult processDocument(String tenantId, String docId,
                                              InputStream content,
                                              String originalFilename) {
        // 1. 存储原始文件
        var rawKey = RAW_PREFIX + tenantId + "/" + docId + "/" + originalFilename;
        storeObject(rawKey, content);

        // 2. 解析为标准 Markdown
        var markdown = parser.parseToMarkdown(content, originalFilename);
        var processedKey = PROCESSED_PREFIX + tenantId + "/" + docId + "/content.md";
        storeObject(processedKey, new ByteArrayInputStream(markdown.getBytes(UTF_8)));

        // 3. 语义切片
        var chunks = chunker.chunk(markdown, Map.of(
                "tenantId", tenantId,
                "docId", docId,
                "source", originalFilename
        ));

        // 4. 存储切片文件 + 写入向量索引
        int totalTokens = 0;
        for (int i = 0; i < chunks.size(); i++) {
            var chunk = chunks.get(i);
            totalTokens += chunk.tokenCount();

            // 存储切片
            var chunkKey = CHUNK_PREFIX + tenantId + "/" + docId + "/chunk_" + i + ".txt";
            storeObject(chunkKey,
                    new ByteArrayInputStream(chunk.text().getBytes(UTF_8)));

            // 向量化 + 索引
            var embedding = embedder.embed(chunk.text());
            vectorStore.add(List.of(
                    Document.builder()
                            .id(docId + "_chunk_" + i)
                            .text(chunk.text())
                            .embedding(embedding)
                            .metadata(Map.of(
                                    "tenantId", tenantId,
                                    "docId", docId,
                                    "chunkIndex", String.valueOf(i),
                                    "sourceFile", originalFilename,
                                    "storageKey", chunkKey
                            ))
                            .build()
            ));
        }

        return new DocPipelineResult(docId, chunks.size(), totalTokens);
    }

    private void storeObject(String key, InputStream data) {
        try {
            minio.putObject(PutObjectArgs.builder()
                    .bucket("ai-documents")
                    .object(key)
                    .stream(data, data.available(), -1)
                    .build());
        } catch (Exception e) {
            throw new StorageException("Store failed: " + key, e);
        }
    }
}

四、RabbitMQ（简要）

4.1 Exchange 类型

类型 路由逻辑 示例
Direct Routing key 完全匹配 Binding key order.created → 订单队列
Topic Routing key 通配符匹配（. + */#） order.* 匹配 order.created, order.paid
Fanout 广播到所有绑定队列 配置刷新通知
Headers 根据消息 headers 匹配 属性匹配路由
java
@Configuration
public class RabbitMQConfig {

    @Bean
    public TopicExchange orderExchange() {
        return new TopicExchange("order.exchange");
    }

    @Bean
    public Queue orderCreatedQueue() {
        return QueueBuilder.durable("order.created.queue")
                .deadLetterExchange("order.dlx.exchange")
                .deadLetterRoutingKey("order.dlq")
                .ttl(30000)
                .maxLength(10000)
                .build();
    }

    @Bean
    public Binding orderCreatedBinding() {
        return BindingBuilder.bind(orderCreatedQueue())
                .to(orderExchange())
                .with("order.created");
    }
}

// DLQ 消费者：记录失败消息并发送告警
@RabbitListener(queues = "order.dlq")
public void handleDeadLetter(Message failedMessage) {
    var headers = failedMessage.getMessageProperties().getHeaders();
    var deathReason = headers.get("x-death");

    log.error("""
            Dead letter received:
            Original Queue: {}
            Reason: {}
            Body: {}
            """,
            headers.get("x-first-death-queue"),
            headers.get("x-first-death-reason"),
            new String(failedMessage.getBody()));

    // 存储到数据库供后续排查
    failedMessageRepository.save(new FailedMessage(
            failedMessage.getMessageProperties().getMessageId(),
            deathReason.toString(),
            new String(failedMessage.getBody()),
            Instant.now()
    ));
}

4.5 Kafka vs RabbitMQ 选型

维度 Kafka RabbitMQ
消息模型 日志（分区追加序） 队列（消费后删除）
吞吐量 百万级/秒 万级/秒
延迟 毫秒级（批量优化） 微秒级（单消息）
消息回溯 支持（按 offset 重新消费） 不支持（消费即删除）
路由灵活性 简单（仅分区路由） 丰富（Exchange 类型 + binding）
优先级 不支持 支持
延迟消息 需要额外设计 插件原生支持
运维复杂度 较高（ZK/KRaft + Broker） 较低（单节点即可）
典型场景 事件流/日志/CDC/大数据 任务分发/RPC/延迟消息/优先级

常见问题

Q: 预签名 URL 安全吗？ A: 预签名 URL 包含签名认证，在有效期内可被任何人使用。应设置短有效期（几分钟到几小时），并通过 HTTPS 传输。

Q: MinIO 的纠删码（Erasure Coding）如何工作？ A: 将数据分为 N 份数据 + M 份校验（EC:N+M），可容忍 M 个节点故障。默认 EC:4+2 可容忍 2 个节点故障。

Q: 何时用 RabbitMQ 而非 Kafka？ A: 需要复杂度由 Broker 端处理（延迟/优先级/路由）、微秒级延迟、任务分发场景。AI 场景中以 Kafka 为主，RabbitMQ 作为补充。

Q: 模型文件为什么要放对象存储而非直接打包到镜像？ A: 模型文件动辄数GB，打包进镜像会导致镜像臃肿、部署慢、版本管理困难。通过对象存储 + 启动时下载或挂载，可实现独立版本管理和快速切换。
