切片策略深度剖析：从固定窗口到语义感知

概述

切片（Chunking）是RAG系统中的关键决策点。切片质量直接决定了检索精度、Token成本和最终答案质量。一个好的切片策略需要回答三个核心问题：切多大、在哪切、切完如何组织。本文系统性地剖析8种切片策略，从最基础的固定大小切片到最前沿的Late Chunking和Contextual Retrieval，每种策略都附带可运行的Java实现。

一、切片的核心约束与权衡

1.1 三要素约束

在切片设计中，有三个相互制约的因素：

检索精度 ∝ chunk_size
检索噪音 ∝ chunk_size
Token成本 ∝ chunk_size × retrieval_top_k
上下文完整性 ∝ chunk_size

关键洞察：上下文完整性与检索噪音之间存在根本矛盾。大chunk包含更多上下文但引入噪音，小chunk精度高但可能丢失关键上下文。

1.2 推荐参数范围

参数 推荐值 说明
chunk_size 512-1024 tokens 对于中文约800-1500字符
overlap chunk_size × 10-20% 50-200 tokens
retrieval_top_k 5-20 根据chunk大小调整

1.3 Token vs 字符

中英文的Token化差异巨大：

  • 英文：1 token ≈ 0.75 词 ≈ 4 字符
  • 中文：1 token ≈ 1.5 汉字 ≈ 3 字符（使用BPE tokenizer）

推荐做法：切片大小以token为单位。中文场景可保守估计为字符数×0.6≈token数。

二、八种切片策略详解

2.1 固定大小切片 (Fixed-Size Chunking)

原理：将文档按固定窗口大小切分，窗口之间有重叠。

实现：

java
import java.util.ArrayList;
import java.util.List;

public class FixedSizeChunker {

    public record Chunk(String text, int startIndex, int endIndex,
                        java.util.Map<String, Object> metadata) {}

    /**
     * 固定大小切片
     * @param text 原始文本
     * @param chunkSize 窗口大小（字符数）
     * @param overlap 重叠大小（字符数）
     */
    public List<Chunk> chunk(String text, int chunkSize, int overlap) {
        var chunks = new ArrayList<Chunk>();
        int start = 0;
        int index = 0;

        while (start < text.length()) {
            int end = Math.min(start + chunkSize, text.length());
            var chunkText = text.substring(start, end);

            chunks.add(new Chunk(
                chunkText, start, end,
                java.util.Map.of("chunk_index", index++, "start", start, "end", end)
            ));

            start += (chunkSize - overlap);
        }

        return chunks;
    }
}

优点：实现简单、计算成本低、适合快速原型验证。

缺点：语义断裂是最致命的问题。一个句子或段落可能被切为两半，导致检索时匹配到不完整的语义单元。

适用场景：结构化文本（日志、代码diff）、快速原型、对语义完整性要求不高的场景。

2.2 段落切片 (Paragraph Chunking)

原理：以自然段落（\n\n）为边界切分。段落在自然语言中是最基本的语义单元。

实现：

java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

public class ParagraphChunker {

    public record Chunk(String text, int paragraphIndex,
                        java.util.Map<String, Object> metadata) {}

    /**
     * 按段落切分，带最大长度限制（长段落二次切分）
     */
    public List<Chunk> chunk(String text, int maxChunkSize) {
        var chunks = new ArrayList<Chunk>();
        var paragraphs = text.split("\n\n");
        int index = 0;

        for (int i = 0; i < paragraphs.length; i++) {
            var para = paragraphs[i].trim();
            if (para.isEmpty()) continue;

            if (para.length() <= maxChunkSize) {
                chunks.add(new Chunk(para, i, java.util.Map.of(
                    "chunk_index", index++,
                    "paragraph_index", i
                )));
            } else {
                // 长段落二次切分（在句子边界上切）
                var subChunks = splitLongParagraph(para, maxChunkSize);
                for (var sub : subChunks) {
                    chunks.add(new Chunk(sub, i, java.util.Map.of(
                        "chunk_index", index++,
                        "paragraph_index", i,
                        "is_sub_chunk", true
                    )));
                }
            }
        }

        return chunks;
    }

    private List<String> splitLongParagraph(String para, int maxSize) {
        var results = new ArrayList<String>();
        // 在句子边界（。！？\n）处切分，优先保持句子完整性
        var sentences = para.split("(?<=[。！？\\n])");
        var current = new StringBuilder();

        for (var sentence : sentences) {
            if (current.length() + sentence.length() > maxSize && !current.isEmpty()) {
                results.add(current.toString().trim());
                current = new StringBuilder();
            }
            current.append(sentence);
        }
        if (!current.isEmpty()) {
            results.add(current.toString().trim());
        }

        return results;
    }
}

优点：保持语义完整性、自然边界、大多数文档适用。

缺点：段落长度可能差异很大（一句 vs 一页），需要配合最大长度限制。

适用场景：通用文档、报告、文章——最常用的策略之一。

2.3 递归字符切片 (Recursive Character Chunking)

原理：LangChain的核心设计。按优先级逐步尝试分割符： \n\n → \n → 。 → . → → ``（逐字符）

每次尝试用当前分割符切分，如果某个chunk超过大小限制，则用下一级分割符对该chunk继续切分。

实现：

java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;
import java.util.function.Function;

public class RecursiveCharacterChunker {

    // 分割符优先级：从高到低
    private static final List<String> SEPARATORS = List.of(
        "\n\n",   // 段落
        "\n",     // 行
        "。",     // 中文句号
        "！",     // 中文感叹号
        "？",     // 中文问号
        ". ",     // 英文句号+空格
        "；",     // 中文分号
        "; ",     // 英文分号
        "，",     // 中文逗号
        ", ",     // 英文逗号
        " ",      // 空格
        ""        // 逐字符
    );

    public record Chunk(String text, int index, String strategy) {}

    /**
     * 递归切片主入口
     */
    public List<Chunk> splitText(String text, int chunkSize, int overlap) {
        return splitText(text, new ArrayList<>(), chunkSize, overlap, 0);
    }

    private List<Chunk> splitText(String text, List<String> separators,
                                   int chunkSize, int overlap, int depth) {
        var chunks = new ArrayList<Chunk>();

        if (text.length() <= chunkSize) {
            chunks.add(new Chunk(text, 0, "fits:%d".formatted(depth)));
            return chunks;
        }

        // 选择当前深度的分割符
        var separator = depth < separators.size()
            ? separators.get(depth)
            : ""; // 最后一级：逐字符

        var splits = separator.isEmpty()
            ? text.chars().mapToObj(c -> String.valueOf((char) c)).toList()
            : Arrays.asList(text.split(Pattern.quote(separator)));

        var goodSplits = new ArrayList<String>();
        for (var split : splits) {
            if (split.length() < chunkSize) {
                goodSplits.add(split);
            } else {
                // 当前分割符无法满足，递归使用更细粒度的分割符
                var subChunks = splitText(split, separators, chunkSize, overlap, depth + 1);
                for (var sub : subChunks) {
                    goodSplits.add(sub.text());
                }
            }
        }

        // 合并短片段到chunk_size上限，overlap衔接
        var currentChunk = new StringBuilder();
        var previousTail = ""; // 用于overlap
        int chunkIndex = 0;

        for (int i = 0; i < goodSplits.size(); i++) {
            var split = goodSplits.get(i);

            if (currentChunk.length() + split.length() > chunkSize && !currentChunk.isEmpty()) {
                var chunkText = currentChunk.toString();
                chunks.add(new Chunk(chunkText, chunkIndex++, "recursive:%d".formatted(depth)));

                // 保留overlap部分
                if (overlap > 0 && chunkText.length() > overlap) {
                    previousTail = chunkText.substring(chunkText.length() - overlap);
                    currentChunk = new StringBuilder(previousTail);
                } else {
                    currentChunk = new StringBuilder();
                }
            }

            currentChunk.append(split);
            if (!separator.isEmpty() && i < goodSplits.size() - 1) {
                currentChunk.append(separator); // 恢复分割符
            }
        }

        if (!currentChunk.isEmpty()) {
            chunks.add(new Chunk(currentChunk.toString(), chunkIndex, "recursive:%d".formatted(depth)));
        }

        return chunks;
    }
}

优点：平衡了语义完整性和chunk大小控制，是通用性最强的策略。

适用场景：通用文档处理，LangChain默认策略。

2.4 语义切片 (Semantic Chunking)

原理：利用Embedding向量判断句子之间的语义边界。当相邻句子/段落的嵌入向量相似度低于阈值时，在此处切分。

算法：

  1. 将文档按句子拆分
  2. 计算每个句子的Embedding向量
  3. 滑动窗口计算相邻句子组的相似度
  4. 相似度局部最小值处即为语义边界
  5. 在边界处切分

实现：

java
import java.util.ArrayList;
import java.util.List;
import java.util.stream.IntStream;

public class SemanticChunker {

    private final EmbeddingService embeddingService;
    private final double similarityThreshold; // 典型值: 0.6-0.8

    public SemanticChunker(EmbeddingService embeddingService, double similarityThreshold) {
        this.embeddingService = embeddingService;
        this.similarityThreshold = similarityThreshold;
    }

    public interface EmbeddingService {
        float[] embed(String text);
        default double cosineSimilarity(float[] a, float[] b) {
            double dot = 0, normA = 0, normB = 0;
            for (int i = 0; i < a.length; i++) {
                dot += (double) a[i] * b[i];
                normA += (double) a[i] * a[i];
                normB += (double) b[i] * b[i];
            }
            return dot / (Math.sqrt(normA) * Math.sqrt(normB));
        }
    }

    public record Chunk(String text, int sentenceStart, int sentenceEnd,
                        double boundaryScore) {}

    /**
     * 基于语义相似度的智能切片
     * @param text 原始文本
     * @param windowSize 滑动窗口大小（句子数），典型值3-5
     */
    public List<Chunk> chunk(String text, int windowSize) {
        // 1. 句子拆分（处理中英文）
        var sentences = splitSentences(text);
        if (sentences.size() <= windowSize) {
            return List.of(new Chunk(text, 0, sentences.size() - 1, 1.0));
        }

        // 2. 逐句Embedding
        var embeddings = sentences.stream()
            .map(embeddingService::embed)
            .toList();

        // 3. 滑动窗口计算语义边界分数
        // boundaryScore[i] = 窗口[i-windowSize, i]与窗口[i, i+windowSize]的相似度
        var boundaryScores = new double[sentences.size()];
        for (int i = windowSize; i < sentences.size() - windowSize; i++) {
            // 左边窗口的句子的平均Embedding
            var leftWindow = averageEmbedding(
                embeddings.subList(i - windowSize, i)
            );
            // 右边窗口的句子的平均Embedding
            var rightWindow = averageEmbedding(
                embeddings.subList(i, i + windowSize)
            );
            boundaryScores[i] = embeddingService.cosineSimilarity(leftWindow, rightWindow);
        }

        // 4. 找语义边界（局部最小值）
        var boundaries = new ArrayList<Integer>();
        boundaries.add(0);
        for (int i = windowSize; i < sentences.size() - windowSize; i++) {
            if (boundaryScores[i] < similarityThreshold) {
                // 确保不切得太密（至少3个句子）
                if (boundaries.isEmpty() || i - boundaries.getLast() >= 3) {
                    boundaries.add(i);
                }
            }
        }
        boundaries.add(sentences.size());

        // 5. 在边界处切分
        var chunks = new ArrayList<Chunk>();
        for (int i = 0; i < boundaries.size() - 1; i++) {
            var start = boundaries.get(i);
            var end = boundaries.get(i + 1);
            var chunkText = String.join("", sentences.subList(start, end));
            var avgScore = IntStream.range(start, end)
                .mapToDouble(j -> j < boundaryScores.length ? boundaryScores[j] : 1.0)
                .average().orElse(1.0);

            chunks.add(new Chunk(chunkText, start, end - 1, avgScore));
        }

        return chunks;
    }

    private float[] averageEmbedding(List<float[]> embs) {
        var dim = embs.getFirst().length;
        var avg = new float[dim];
        for (var emb : embs) {
            for (int i = 0; i < dim; i++) {
                avg[i] += emb[i] / embs.size();
            }
        }
        return avg;
    }

    private List<String> splitSentences(String text) {
        // 中英文混合句子切割正则
        var sentences = new ArrayList<String>();
        var matcher = java.util.regex.Pattern.compile(
            "[^。！？.!?\n]+[。！？.!?\n]?"
        ).matcher(text);

        while (matcher.find()) {
            var sentence = matcher.group().trim();
            if (!sentence.isEmpty()) {
                sentences.add(sentence);
            }
        }
        return sentences;
    }
}

优点：最高质量的语义保留、自适应不同内容密度。

缺点：计算成本高（每个句子都需要Embedding）、需要选择合适的Embedding模型。

适用场景：对检索质量要求极高的场景、学术文献、技术文档。

2.5 代码感知切片 (Code-Aware Chunking)

原理：利用AST（抽象语法树）按函数/类/方法边界切分，而非按行或字符。这是代码RAG的核心技术。

实现（Java AST解析）：

java
import com.github.javaparser.StaticJavaParser;
import com.github.javaparser.ast.CompilationUnit;
import com.github.javaparser.ast.body.MethodDeclaration;
import com.github.javaparser.ast.body.ClassOrInterfaceDeclaration;
import java.util.ArrayList;
import java.util.List;
import java.util.Optional;

public class CodeAwareChunker {

    public record CodeChunk(
        String code,
        String type,          // "class", "method", "field", "import"
        String name,          // 类/方法名
        int startLine,
        int endLine,
        String parentClass,   // 所属类名
        String signature,     // 方法签名
        List<String> annotations
    ) {}

    /**
     * 按方法和类边界切分Java源代码
     */
    public List<CodeChunk> chunkJava(String sourceCode) {
        var chunks = new ArrayList<CodeChunk>();
        var cu = StaticJavaParser.parse(sourceCode);

        // 提取导入语句
        cu.getImports().forEach(imp ->
            chunks.add(new CodeChunk(
                imp.toString(), "import", imp.getNameAsString(),
                imp.getBegin().map(p -> p.line).orElse(0),
                imp.getEnd().map(p -> p.line).orElse(0),
                null, null, List.of()
            ))
        );

        // 遍历类型声明
        cu.findAll(ClassOrInterfaceDeclaration.class).forEach(cls -> {
            var className = cls.getNameAsString();
            var annotations = cls.getAnnotations().stream()
                .map(a -> a.getNameAsString()).toList();

            // 类级别的chunk（包含字段）
            var classChunk = buildClassChunk(cls);
            chunks.add(classChunk);

            // 方法级别的chunk
            cls.getMethods().forEach(method -> {
                chunks.add(buildMethodChunk(method, className));
            });
        });

        // 顶层方法
        cu.findAll(MethodDeclaration.class).stream()
            .filter(m -> m.getParentNode()
                .filter(p -> p instanceof CompilationUnit).isPresent())
            .forEach(method -> {
                chunks.add(buildMethodChunk(method, null));
            });

        return chunks;
    }

    private CodeChunk buildClassChunk(ClassOrInterfaceDeclaration cls) {
        var fields = new StringBuilder();
        cls.getFields().forEach(f ->
            fields.append("  ").append(f.getVariable(0).getNameAsString())
                  .append(": ").append(f.getCommonType()).append(";\n")
        );

        var code = """
            %s
            class %s {
            %s
            // ... %d methods ...
            }
            """.formatted(
                cls.getAnnotations().stream()
                    .map(a -> "@" + a.getNameAsString())
                    .collect(java.util.stream.Collectors.joining("\n")),
                cls.getNameAsString(),
                fields,
                cls.getMethods().size()
            );

        return new CodeChunk(
            code, "class", cls.getNameAsString(),
            cls.getBegin().map(p -> p.line).orElse(0),
            cls.getEnd().map(p -> p.line).orElse(0),
            null, null,
            cls.getAnnotations().stream()
                .map(a -> a.getNameAsString()).toList()
        );
    }

    private CodeChunk buildMethodChunk(MethodDeclaration method, String parentClass) {
        return new CodeChunk(
            method.getTokenRange().map(t -> t.toString()).orElse(""),
            "method",
            method.getNameAsString(),
            method.getBegin().map(p -> p.line).orElse(0),
            method.getEnd().map(p -> p.line).orElse(0),
            parentClass,
            method.getDeclarationAsString(false, false, false),
            method.getAnnotations().stream()
                .map(a -> a.getNameAsString()).toList()
        );
    }
}

<dependency>

    <version>3.26.3</version>

优点：保持代码逻辑完整性、检索时能精确匹配函数/类。

缺点：语言特定、需要解析器支持每种语言。

适用场景：代码库RAG、API文档生成、代码问答。

2.6 文档结构感知切片 (Structure-Aware Chunking)

原理：利用文档自身的结构标记（Markdown标题、PDF目录/书签、HTML标题标签）作为切片边界，保持文档的层级结构。

实现（Markdown结构感知）：

java
import java.util.ArrayList;
import java.util.List;
import java.util.regex.Pattern;

public class StructureAwareChunker {

    public record StructuredChunk(
        String content,
        String sectionPath,      // "第1章 > 1.1节 > 1.1.2小节"
        int headingLevel,        // 1-6
        String headingTitle,     // "切片策略详解"
        List<StructuredChunk> children
    ) {}

    /**
     * 按Markdown标题层级切分
     * 每个chunk包含其标题路径的完整上下文
     */
    public List<StructuredChunk> chunkMarkdown(String markdown, int maxChunkSize) {
        var lines = markdown.split("\n");
        var root = new StructuredChunk("", "/", 0, "ROOT", new ArrayList<>());
        var pathStack = new java.util.Stack<StructuredChunk>();
        pathStack.push(root);

        var currentContent = new StringBuilder();

        for (var line : lines) {
            var matcher = Pattern.compile("^(#{1,6})\\s+(.+)").matcher(line);
            if (matcher.find()) {
                // 遇到新标题：保存前一个chunk内容
                if (!currentContent.isEmpty() && pathStack.size() > 1) {
                    var parent = pathStack.peek();
                    var chunk = new StructuredChunk(
                        currentContent.toString(),
                        buildPath(pathStack),
                        pathStack.size() - 1,
                        parent.headingTitle(),
                        new ArrayList<>()
                    );
                    parent.children().add(chunk);
                    currentContent = new StringBuilder();
                }

                // 调整层级栈
                var level = matcher.group(1).length();
                var title = matcher.group(2);

                while (pathStack.size() > level) {
                    pathStack.pop();
                }

                var newChunk = new StructuredChunk(
                    "", buildPath(pathStack) + " > " + title,
                    level, title, new ArrayList<>()
                );
                pathStack.peek().children().add(newChunk);
                pathStack.push(newChunk);
            } else {
                currentContent.append(line).append("\n");
            }

            // 内容超限时切分子chunk
            if (currentContent.length() >= maxChunkSize) {
                if (!pathStack.isEmpty()) {
                    var parent = pathStack.peek();
                    parent.children().add(new StructuredChunk(
                        currentContent.toString(), buildPath(pathStack),
                        pathStack.size(), parent.headingTitle(), new ArrayList<>()
                    ));
                    currentContent = new StringBuilder();
                }
            }
        }

        // 残留内容
        if (!currentContent.isEmpty() && pathStack.size() > 1) {
            pathStack.peek().children().add(new StructuredChunk(
                currentContent.toString(), buildPath(pathStack),
                pathStack.size(), pathStack.peek().headingTitle(), new ArrayList<>()
            ));
        }

        return flattenChunks(root);
    }

    private String buildPath(java.util.Stack<StructuredChunk> stack) {
        return stack.stream()
            .skip(1) // 跳过ROOT
            .map(StructuredChunk::headingTitle)
            .collect(java.util.stream.Collectors.joining(" > "));
    }

    private List<StructuredChunk> flattenChunks(StructuredChunk root) {
        var result = new ArrayList<StructuredChunk>();
        for (var child : root.children()) {
            result.add(child);
            result.addAll(flattenChunks(child));
        }
        return result;
    }
}

优点：保持文档逻辑结构、检索结果的章节上下文清晰。

适用场景：技术文档、API文档、知识库——有明确层级结构的文档。

2.7 Late Chunking vs Early Chunking

这是切片策略中最根本的范式区别：

Early Chunking（当前主流）：

文档 → 切片 → 每个Chunk独立Embedding → 索引 → 检索

问题：一个Chunk的Embedding只反映了该Chunk自身的语义，丢失了文档级的上下文信息。

Late Chunking (ColBERT风格)：

文档 → 整篇Embedding（Token级）→ 切片（在Token Embedding上操作）→ 加权检索

优势：每个Token的Embedding包含了整篇文档的上下文信息，即使切片后仍保留了更细粒度的语义。

Java实现 (Late Chunking模拟)：

java
import java.util.ArrayList;
import java.util.Comparator;
import java.util.List;

public class LateChunker {

    /**
     * 模拟Late Chunking：
     * 1. 先对整篇文档做Token级Embedding（这里简化为句子级）
     * 2. 切片时保留Token Embedding
     * 3. 检索时使用MaxSim（最大相似度）而非Chunk级余弦相似度
     */
    public record LateChunk(
        String text,
        float[][] tokenEmbeddings,  // 每个Token的Embedding向量
        List<Integer> tokenPositions
    ) {}

    public interface LateEmbeddingService {
        /**
         * 返回Token级别的Embedding矩阵 [numTokens × dim]
         */
        float[][] tokenEmbed(String text);
    }

    /**
     * MaxSim检索：查询与Chunk的相似度 = max(查询向量与Chunk内每个Token向量的相似度)
     * 这是ColBERT的核心思想
     */
    public double maxSimScore(float[] queryEmbedding, LateChunk chunk) {
        double maxScore = 0;
        for (var tokenEmb : chunk.tokenEmbeddings()) {
            var score = cosineSimilarity(queryEmbedding, tokenEmb);
            if (score > maxScore) {
                maxScore = score;
            }
        }
        return maxScore;
    }

    /**
     * SumMaxSim：查询与多个Chunk的交互式检索分数
     */
    public double sumMaxSimScore(float[] queryEmbedding, List<LateChunk> chunks) {
        return chunks.stream()
            .mapToDouble(chunk -> maxSimScore(queryEmbedding, chunk))
            .sum();
    }

    private double cosineSimilarity(float[] a, float[] b) {
        double dot = 0, normA = 0, normB = 0;
        for (int i = 0; i < a.length; i++) {
            dot += (double) a[i] * b[i];
            normA += (double) a[i] * a[i];
            normB += (double) b[i] * b[i];
        }
        return dot / (Math.sqrt(normA) * Math.sqrt(normB));
    }
}

Early Chunking (256) 0.74 0.83 1.5x

2.8 Contextual Retrieval

原理（Anthropic提出）：为每个Chunk自动生成一段"上下文描述"，描述该Chunk在原始文档中的位置和角色。

例如，原始Chunk：

计算方法是使用标准差进行标准化...

加上上下文描述后：

{文档标题: 机器学习入门, 章节: 第3章 特征工程, 上一节: 缺失值处理}
计算方法是使用标准差进行标准化...
java
public class ContextualChunker {

    public interface ContextGenerator {
        /**
         * 为chunk生成上下文描述
         * 可以用LLM生成，也可以用基于规则的元数据方法
         */
        String generateContext(String chunkText, String documentTitle,
                               String sectionPath, String previousChunkSummary);
    }

    public record ContextualChunk(
        String chunkContent,
        String contextDescription,
        String combinedText  // contextDescription + chunkContent
    ) {}

    /**
     * 规则式上下文生成（无需LLM，速度快）
     */
    public static class RuleBasedContextGenerator implements ContextGenerator {
        @Override
        public String generateContext(String chunkText, String documentTitle,
                                       String sectionPath, String previousChunkSummary) {
            var sb = new StringBuilder();
            if (documentTitle != null && !documentTitle.isEmpty()) {
                sb.append("文档: ").append(documentTitle).append("; ");
            }
            if (sectionPath != null && !sectionPath.isEmpty()) {
                sb.append("章节: ").append(sectionPath).append("; ");
            }
            if (previousChunkSummary != null && !previousChunkSummary.isEmpty()) {
                sb.append("上文概述: ").append(previousChunkSummary).append("; ");
            }
            return sb.toString();
        }
    }

    /**
     * LLM式上下文生成（质量高，成本较高）
     */
    public static class LlmContextGenerator implements ContextGenerator {
        private final ChatClient chatClient;

        public LlmContextGenerator(ChatClient chatClient) {
            this.chatClient = chatClient;
        }

        @Override
        public String generateContext(String chunkText, String documentTitle,
                                       String sectionPath, String previousChunkSummary) {
            var prompt = """
                请为以下文档片段生成一段简短的上下文描述（不超过50字）。
                描述应包含：该片段所属的文档主题、所在章节、与前文的关系。

                文档标题: %s
                章节路径: %s
                前文概述: %s

                片段内容:
                %s

                上下文描述:
                """.formatted(documentTitle, sectionPath, previousChunkSummary, chunkText);

            return chatClient.prompt().user(prompt).call().content();
        }
    }

    /**
     * 将Contextual Chunk用于索引和检索
     */
    public List<ContextualChunk> chunkWithContext(String documentText,
                                                   String documentTitle,
                                                   ContextGenerator contextGenerator) {
        var structureChunker = new StructureAwareChunker();
        var structuredChunks = structureChunker.chunkMarkdown(documentText, 1024);

        var contextualChunks = new ArrayList<ContextualChunk>();
        String previousSummary = null;

        for (var chunk : structuredChunks) {
            var context = contextGenerator.generateContext(
                chunk.content(), documentTitle, chunk.sectionPath(), previousSummary
            );

            var combined = """
                [上下文: %s]

                %s
                """.formatted(context, chunk.content());

            contextualChunks.add(new ContextualChunk(
                chunk.content(), context, combined
            ));

            // 用当前chunk的前50字作为下一chunk的上文概述
            previousSummary = chunk.content().length() > 50
                ? chunk.content().substring(0, 50) + "..."
                : chunk.content();
        }

        return contextualChunks;
    }
}

关键洞察：索引时使用combinedText（contextDescription + chunkContent）做Embedding，检索时能匹配到更多语义相关的chunk。这解决了传统切片中"chunk脱离文档上下文"的核心问题。

Anthropic的实验显示，Contextual Retrieval可以将检索失败率降低49%（相对于传统切片）。

五、切片策略选择决策树

文档类型？
├── 纯文本/文章
│   ├── 有标题结构 → 递归字符切片 + Contextual Retrieval
│   └── 无标题结构 → 段落切片 + 10%重叠
├── 代码
│   ├── 检索粒度：函数级 → 代码感知切片（AST）
│   └── 检索粒度：文件级 → 固定大小 + 文件名元数据
├── PDF/Office文档
│   ├── 质量优先 → 结构感知切片 + 语义切片混合
│   └── 成本优先 → 递归字符切片 + 10%重叠
├── 图文混排 → 结构感知 + 多模态元数据
└── 对话/日志 → 时间窗口切片（按时间间隔/轮次）

六、最佳实践

  1. 默认使用递归字符切片：通用性最好，作为baseline
  2. 根据文档类型选择策略：代码用AST、Markdown用结构感知
  3. 附加Contextual Retrieval：成本极低（规则式），收益显著
  4. 记录切片策略到元数据：便于后续分析和切换
  5. 建立评估集：用Golden Dataset评估不同策略的检索效果
  6. 分批实验：小批量测试 → 全量应用

七、反模式

  • 固定大小一刀切：忽略文档结构，检索结果语义不完整
  • 盲目追求语义切片：Embedding API成本可能很高，先评估收益
  • 切分过小（<100 tokens）：检索碎片化，无法回答任何问题
  • 切分过大（>2000 tokens）：上下文噪音，Token浪费
  • 忽略Overlap：关键信息正好落在边界时永久丢失
  • 不记录chunk元数据：无法追溯、无法调试、无法切换策略
