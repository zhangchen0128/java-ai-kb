保险核心业务基础：概念、险种、术语与产品要素

一、保险核心概念

1.1 风险与保险原理

保险的本质是风险管理的金融工具。其数学基础是大数法则（Law of Large Numbers）：当独立同分布的风险单元数量足够大时，实际损失率将趋近于期望损失率，从而使保险公司能够以确定的保费覆盖不确定的损失。

可保风险（Insurable Risk）必须满足以下条件：

  1. 大量同质风险单位：必须有足够多的相似风险暴露单位，才能应用大数法则进行精算定价。
  2. 意外性：损失的发生必须是偶然的、非故意的，被保险人不能控制损失是否发生。
  3. 可测性：损失的概率分布和严重程度必须可以被量化估算。
  4. 非巨灾性：单个事件不应导致所有风险单位同时发生损失（否则需要再保险分散）。
  5. 经济可行性：保费必须在投保人可承受范围内，同时覆盖保险公司的赔付和运营成本。

风险分散（Risk Pooling）机制：保险公司将大量个体投保人的保费汇集为保险基金，当少数人发生保险事故时，从基金中支付赔款。个体将不确定的大额损失转化为确定的小额保费支出。

1.2 合同主体

保险合同涉及四个核心主体，各自享有不同的权利并承担相应的义务。在Java领域建模中，这些主体对应独立的实体。

主体 角色定义 权利义务
保险人（Insurer） 经营保险业务的保险公司 收取保费，承担保险责任；在保险事故发生时履行赔偿或给付义务
投保人（Applicant/Policyholder） 与保险人订立合同并支付保费的人 支付保费，如实告知；享有合同约定的权利
被保险人（Insured） 受保险合同保障的人 享有保险金请求权（在财产险中）；在人身险中，其身体或生命为保险标的
受益人（Beneficiary） 由被保险人或投保人指定的享有保险金请求权的人 在人身保险中，当被保险人死亡时领取保险金

投保人与被保险人可以是同一人，也可以是不同人。当投保人与被保险人不是同一人时，投保人必须对被保险人具有保险利益，否则合同无效。

1.3 保费与保额

保费（Premium）是投保人为获得保障而支付的费用，其构成如下：

  • 纯保费（Net Premium）：基于风险概率精算得出的预期赔付成本。纯保费 = 保险金额 × 损失概率。
  • 附加保费（Loading）：包括保险公司运营成本（管理费用、佣金、税费等）和利润边际。

保额（Sum Insured / Coverage Amount）是保险人承担赔偿或给付责任的最高限额。保额的确定受以下因素影响：

  • 被保险人的收入水平和财务状况
  • 保险标的的实际价值（财产险中遵循"损失补偿原则"）
  • 保险费率与投保人预算约束
  • 监管规定的最高/最低保额限制

1.4 保险利益原则

保险利益（Insurable Interest）是指投保人或被保险人对保险标的具有的法律上承认的经济利益。这一原则的核心目的是：

  1. 防止赌博行为：防止将保险合同变成对他人生命/财产的赌博。
  2. 防止道德风险：减少故意制造保险事故以获取保险金的动机。
  3. 限制赔偿额度：被保险人不能获得超过其实际损失的赔偿。

在人身保险中，投保人对下列人员具有保险利益：本人、配偶、子女、父母；与投保人有抚养/赡养关系的其他家庭成员；与投保人有劳动关系的劳动者（团体保险的基础）。

二、险种分类

2.1 寿险（Life Insurance）

寿险以被保险人的生命为标的，是最基础的人身保险险种。

定期寿险（Term Life Insurance）

  • 保障一定期间（如20年、至60岁），期间内身故则赔付，期满生存则不赔付不返还
  • 纯消费型，保费低廉，杠杆比高
  • 适合家庭经济支柱在责任重大期的保障需求

终身寿险（Whole Life Insurance）

  • 保障至终身，无论何时身故均赔付
  • 具有现金价值（Cash Value），可退保领取或保单贷款
  • 保费远高于定期寿险，兼具储蓄和传承功能

两全保险（Endowment Insurance）

  • 保障期内身故赔付，期满生存返还满期金（通常为已交保费或保额）
  • "生死两全"，储蓄属性强
  • 常见于银行渠道销售的储蓄型保险产品

2.2 健康险（Health Insurance）

医疗险（Medical Insurance）

  • 报销型：按实际发生的医疗费用报销，设有免赔额和赔付上限
  • 保障范围：住院医疗、门诊医疗、特殊门诊（放化疗/肾透析等）
  • 代表产品：百万医疗险（高保额、高免赔额）、中端医疗险、高端医疗险

重大疾病保险（Critical Illness Insurance）

  • 给付型：确诊合同约定的重大疾病后一次性给付保险金
  • 不限制保险金用途（可用于治疗费、康复费、收入损失补偿）
  • 病种覆盖：监管规定的28种核心重疾 + 各公司自行增加的中症/轻症

护理险（Long-Term Care Insurance）

  • 当被保险人因年老、疾病或伤残导致失能、需要长期护理时提供保障
  • 给付形式：护理服务费用报销或定额护理金给付
  • 随着人口老龄化加速，护理险的重要性日益凸显

2.3 意外险（Accident Insurance）

意外医疗（Accident Medical）

  • 报销因意外伤害导致的医疗费用
  • 包含意外门诊和意外住院
  • 通常设有免赔额和赔付比例

意外伤害（Accidental Death & Dismemberment）

  • 意外身故：一次性给付保额
  • 意外伤残：按《人身保险伤残评定标准》1-10级比例给付（1级100%、10级10%）
  • 特点是高杠杆、低保费，按职业类别定价

2.4 年金险（Annuity Insurance）

年金险是以被保险人生存为给付条件的保险产品，核心功能是防范长寿风险。

  • 即期年金：趸交保费后立即开始领取年金
  • 延期年金：缴费期结束后经过一段累积期再开始领取
  • 养老年金：专为退休养老设计，通常从法定退休年龄开始领取

年金险的价值在于提供确定性的、与生命等长的现金流，是养老保障体系第三支柱（个人养老金）的核心产品。

2.5 财产险与责任险概述

  • 财产保险：保障房屋、设备、货物、车辆等有形财产因自然灾害或意外事故遭受的损失
  • 责任保险：保障被保险人因过失对第三方造成人身伤害或财产损失而依法应承担的赔偿责任（如公众责任险、雇主责任险、产品责任险）
  • 信用保险：保障因债务人不履行义务造成的经济损失

2.6 团体保险 vs 个人保险

维度 团体保险 个人保险
投保主体 企业/组织/团体 个人
被保险人 团体成员（员工） 个人本人或家庭成员
核保方式 团体核保为主（免体检或简易核保） 个人逐一核保（健康告知+体检）
费率 团体费率，通常低于个人费率 个人标准费率
最低人数 通常要求3-5人以上 1人
合同形式 一张主保单 + 被保险人清单 每人一张保单

团体保险的优势：

  1. 费率低：团体风险分散性好，管理成本低，平均费率通常比个人险低20%-40%
  2. 核保宽松：团体达到一定规模后，可免体检或仅需简易健康告知
  3. 手续简便：企业统一办理，员工无需逐一核保
  4. 税务优惠：企业保费支出可在一定比例内税前扣除

三、核心业务术语表

以下是保险业务中最常使用的专业术语，在系统设计和Java建模中需要精确理解其含义。

3.1 时间类术语

术语 英文 定义
等待期 Waiting Period 投保后到保障生效的期间。健康险通常30天，重疾险通常90-180天。等待期内出险不赔付（仅退还保费）。目的是防范带病投保
犹豫期 Free Look Period 投保人收到保单后可无条件退保的期间。长期险通常15天，一年期以上产品通常10-20天。犹豫期内退保全额退还保费
宽限期 Grace Period 缴费日后可延迟缴费且保障仍然有效的期间。长期险宽限期通常60天。宽限期内出险赔付但扣除欠缴保费
复效期 Reinstatement Period 宽限期满后仍未缴费导致合同中止，可在2年内申请恢复合同效力

3.2 赔付类术语

术语 英文 定义
免赔额 Deductible 被保险人自行承担的金额部分。分为次免赔（每次事故）和年免赔（年度累计）。医疗险常见免赔额1万元/年
赔付比例 Coinsurance Ratio 保险公司赔付的比例。如有社保先赔付后100%赔付，无社保则60%-80%
保额上限 Coverage Limit 单次事故或年度累计赔付的最高限额
给付方式 Payout Method 报销型（按实际费用）vs 给付型（确诊即赔固定金额）

3.3 核保与风控术语

术语 英文 定义
职业类别 Occupation Class 1-6级风险分类：1类（内勤文员）最低风险，6类（高空作业/矿工）最高风险。不同类别对应不同费率和承保限制
费率表 Rate Table 按被保险人年龄、性别、职业、保额、缴费期等因素列示的保费标准。是精算定价的核心输出
核保 Underwriting 对被保险人进行风险评估并决定是否承保、以何种条件承保的过程
批单 Endorsement 保险合同内容的书面变更证明。包括被保险人变更、保额调整、受益人变更等
再保险 Reinsurance 保险公司将部分风险转移给其他保险公司（再保险人）的行为。目的是分散巨灾风险
理赔 Claim 保险事故发生后，被保险人或受益人向保险人提出赔偿/给付申请的过程
现金价值 Cash Value 长期人身保险退保时可领取的金额。通常缴费前几年现金价值远低于已缴保费
如实告知义务 Duty of Disclosure 投保人在投保时应如实回答保险人关于保险标的的询问。故意或因重大过失未履行告知义务的，保险人有权解除合同

3.4 产品设计术语

术语 英文 定义
趸交 Single Premium 一次性缴清全部保费
期交 Regular Premium 分期缴纳保费，如年交、半年交、季交、月交
缴费期间 Premium Payment Period 缴费的年限（3年/5年/10年/20年/30年或至特定年龄）
保障期限 Coverage Period 保障持续的期限（定期保障如至60岁/70岁、终身保障）
保险责任 Coverage 保险人承担的赔偿/给付范围
责任免除 Exclusion 保险人不承担责任的特定情形
主险 Primary Coverage 可独立投保的基本保险责任
附加险 Rider 不能独立投保，须附加于主险之上的保险责任
既往症 Pre-existing Condition 投保前已存在的疾病或症状。通常在责任免除范围内

四、产品要素：一个保险产品的完整定义

一个商业保险产品的完整要素结构包括以下核心维度：

4.1 投保规则

  • 投保年龄范围：如出生满28天至60周岁
  • 投保关系：本人、配偶、子女、父母
  • 职业类别限制：如1-4类职业可投保，5-6类拒保
  • 健康告知：需要回答的健康问题和核保要求
  • 地域限制：部分地区可能无法投保

4.2 保障要素

  • 保障期限：定期（1年/20年/至60岁/至70岁）或终身
  • 缴费期间：趸交、3年、5年、10年、20年、30年
  • 基本保额：最低/最高保额限制，保额递增规则
  • 保险责任：身故赔付、全残赔付、重大疾病赔付、医疗费用报销等
  • 责任免除：战争、核辐射、故意行为、既往症、高风险运动等
  • 等待期：各保险责任的等待期设置
  • 犹豫期：通常15天

4.3 费率要素

  • 基准费率：基于年龄、性别的标准保费
  • 职业系数：不同职业类别的费率乘数
  • 折扣规则：多人投保折扣、家庭单折扣、优选体折扣
  • 附加险费率：各附加险的独立费率和组合
  • 续保规则：保证续保 vs 非保证续保，费率调整规则

// Policy.java — 保单聚合根
package com.insurance.domain.policy;

import jakarta.persistence.*;
import java.math.BigDecimal;
import java.time.LocalDate;
import java.time.LocalDateTime;
import java.util.ArrayList;
import java.util.List;

@Entity
@Table(name = "t_policy")
public class Policy {

    @Id
    @GeneratedValue(strategy = GenerationType.UUID)
    private String id;

    @Column(name = "policy_no", nullable = false, unique = true, length = 32)
    private String policyNo;

    @Column(name = "product_code", nullable = false, length = 32)
    private String productCode;

    @Enumerated(EnumType.STRING)
    @Column(name = "policy_type", nullable = false)
    private PolicyType policyType;

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "applicant_id", nullable = false)
    private Applicant applicant;

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "insurant_id", nullable = false)
    private Insurant insurant;

    @OneToMany(mappedBy = "policy", cascade = CascadeType.ALL, orphanRemoval = true)
    private List<Beneficiary> beneficiaries = new ArrayList<>();

    @Column(name = "sum_insured", nullable = false, precision = 15, scale = 2)
    private BigDecimal sumInsured;

    @Column(name = "annual_premium", nullable = false, precision = 15, scale = 2)
    private BigDecimal annualPremium;

    @Enumerated(EnumType.STRING)
    @Column(name = "payment_period", nullable = false)
    private PaymentPeriod paymentPeriod;

    @Enumerated(EnumType.STRING)
    @Column(name = "coverage_period", nullable = false)
    private CoveragePeriod coveragePeriod;

    @Enumerated(EnumType.STRING)
    @Column(name = "policy_status", nullable = false)
    private PolicyStatus policyStatus;

    @Column(name = "effective_date", nullable = false)
    private LocalDate effectiveDate;

    @Column(name = "expiry_date")
    private LocalDate expiryDate;

    @Column(name = "waiting_period_days")
    private Integer waitingPeriodDays;

    @Column(name = "free_look_period_days")
    private Integer freeLookPeriodDays;

    @Column(name = "grace_period_days")
    private Integer gracePeriodDays;

    @Column(name = "signed_date")
    private LocalDate signedDate;

    @Column(name = "created_at", nullable = false)
    private LocalDateTime createdAt;

    @Column(name = "updated_at")
    private LocalDateTime updatedAt;

    // 构造函数
    public Policy() {}

    // 业务方法：计算犹豫期截止日
    public LocalDate calculateFreeLookEndDate() {
        if (signedDate == null || freeLookPeriodDays == null) {
            return null;
        }
        return signedDate.plusDays(freeLookPeriodDays);
    }

    // 业务方法：计算宽限期截止日
    public LocalDate calculateGracePeriodEndDate(LocalDate premiumDueDate) {
        if (gracePeriodDays == null) {
            return premiumDueDate;
        }
        return premiumDueDate.plusDays(gracePeriodDays);
    }

    // 业务方法：添加受益人
    public void addBeneficiary(Beneficiary beneficiary) {
        beneficiary.setPolicy(this);
        this.beneficiaries.add(beneficiary);
    }

    // 业务方法：检查是否在等待期内
    public boolean isWithinWaitingPeriod(LocalDate claimDate) {
        if (waitingPeriodDays == null || effectiveDate == null) {
            return false;
        }
        var waitingEndDate = effectiveDate.plusDays(waitingPeriodDays);
        return claimDate.isBefore(waitingEndDate);
    }

    // Getters and Setters (省略标准getter/setter)

    // 静态工厂方法
    public static Policy create(String productCode, PolicyType type,
                                Applicant applicant, Insurant insurant,
                                BigDecimal sumInsured, BigDecimal annualPremium,
                                PaymentPeriod paymentPeriod, CoveragePeriod coveragePeriod) {
        var policy = new Policy();
        policy.policyNo = generatePolicyNo();
        policy.productCode = productCode;
        policy.policyType = type;
        policy.applicant = applicant;
        policy.insurant = insurant;
        policy.sumInsured = sumInsured;
        policy.annualPremium = annualPremium;
        policy.paymentPeriod = paymentPeriod;
        policy.coveragePeriod = coveragePeriod;
        policy.policyStatus = PolicyStatus.PENDING;
        policy.createdAt = LocalDateTime.now();
        return policy;
    }

    private static String generatePolicyNo() {
        var timestamp = System.currentTimeMillis();
        var random = (int) (Math.random() * 10000);
        return String.format("PL%s%04d", timestamp % 100000000, random);
    }
}

package com.insurance.domain.party;

import jakarta.persistence.*;
import java.time.LocalDate;
import java.time.LocalDateTime;

@Entity
@Table(name = "t_insurant")
public class Insurant {

    @Id
    @GeneratedValue(strategy = GenerationType.UUID)
    private String id;

    @Column(name = "name", nullable = false, length = 100)
    private String name;

    @Column(name = "id_type", nullable = false, length = 20)
    private String idType;  // ID_CARD, PASSPORT, etc.

    @Column(name = "id_no", nullable = false, length = 50)
    private String idNo;

    @Column(name = "gender", nullable = false, length = 10)
    private String gender;

    @Column(name = "birth_date", nullable = false)
    private LocalDate birthDate;

    @Column(name = "phone", length = 20)
    private String phone;

    @Column(name = "occupation_code", length = 20)
    private String occupationCode;

    @Column(name = "occupation_class")
    private Integer occupationClass;  // 1-6 职业类别

    @Column(name = "has_social_insurance")
    private Boolean hasSocialInsurance;

    @Column(name = "created_at", nullable = false)
    private LocalDateTime createdAt;

    // 计算年龄
    public int getAge() {
        return LocalDate.now().getYear() - birthDate.getYear();
    }

    // 计算年龄（到指定日期）
    public int getAgeAt(LocalDate date) {
        var age = date.getYear() - birthDate.getYear();
        if (date.getDayOfYear() < birthDate.getDayOfYear()) {
            age--;
        }
        return age;
    }
}

    private BigDecimal benefitRatio;  // 受益份额比例（如 0.5 表示50%）

    @Column(name = "priority")
    private Integer priority;  // 受益顺序（第一顺位=1，第二顺位=2）

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "policy_id", nullable = false)
    private Policy policy;

    // 验证受益份额总和不超过100%
    public static boolean validateBenefitRatioSum(List<Beneficiary> beneficiaries, int priority) {
        var sum = beneficiaries.stream()
                .filter(b -> b.priority != null && b.priority == priority)
                .map(Beneficiary::getBenefitRatio)
                .filter(r -> r != null)
                .reduce(BigDecimal.ZERO, BigDecimal::add);
        return sum.compareTo(BigDecimal.ONE) <= 0;
    }

    Policy getPolicy() { return policy; }
    void setPolicy(Policy policy) { this.policy = policy; }
    BigDecimal getBenefitRatio() { return benefitRatio; }
}

package com.insurance.domain.claim;

import jakarta.persistence.*;
import java.math.BigDecimal;
import java.time.LocalDate;
import java.time.LocalDateTime;
import java.util.ArrayList;
import java.util.List;

@Entity
@Table(name = "t_claim")
public class Claim {

    @Id
    @GeneratedValue(strategy = GenerationType.UUID)
    private String id;

    @Column(name = "claim_no", nullable = false, unique = true, length = 32)
    private String claimNo;

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "policy_id", nullable = false)
    private Policy policy;

    @Column(name = "claim_date", nullable = false)
    private LocalDate claimDate;

    @Enumerated(EnumType.STRING)
    @Column(name = "claim_type", nullable = false)
    private ClaimType claimType;

    @Column(name = "incident_date", nullable = false)
    private LocalDate incidentDate;

    @Column(name = "incident_description", length = 2000)
    private String incidentDescription;

    @Column(name = "claimed_amount", precision = 15, scale = 2)
    private BigDecimal claimedAmount;

    @Column(name = "approved_amount", precision = 15, scale = 2)
    private BigDecimal approvedAmount;

    @Column(name = "deductible", precision = 15, scale = 2)
    private BigDecimal deductible;

    @Column(name = "coinsurance_ratio", precision = 5, scale = 4)
    private BigDecimal coinsuranceRatio;  // 赔付比例

    @Enumerated(EnumType.STRING)
    @Column(name = "claim_status", nullable = false)
    private ClaimStatus claimStatus;

    @OneToMany(mappedBy = "claim", cascade = CascadeType.ALL, orphanRemoval = true)
    private List<ClaimDocument> documents = new ArrayList<>();

    @Column(name = "submitted_at")
    private LocalDateTime submittedAt;

    @Column(name = "approved_at")
    private LocalDateTime approvedAt;

    @Column(name = "rejection_reason", length = 1000)
    private String rejectionReason;

    // 业务方法：计算赔付金额
    public BigDecimal calculatePayableAmount() {
        if (claimedAmount == null) return BigDecimal.ZERO;

        var payable = claimedAmount;

        // 减去免赔额
        if (deductible != null) {
            payable = payable.subtract(deductible);
            if (payable.compareTo(BigDecimal.ZERO) < 0) {
                payable = BigDecimal.ZERO;
            }
        }

        // 应用赔付比例
        if (coinsuranceRatio != null) {
            payable = payable.multiply(coinsuranceRatio);
        }

        // 不超过保额上限
        if (policy != null && policy.getSumInsured() != null) {
            if (payable.compareTo(policy.getSumInsured()) > 0) {
                payable = policy.getSumInsured();
            }
        }

        return payable.setScale(2, java.math.RoundingMode.HALF_UP);
    }

    // 判断是否在等待期内
    public boolean isInWaitingPeriod() {
        if (policy == null) return false;
        return policy.isWithinWaitingPeriod(incidentDate);
    }

    Policy getPolicy() { return policy; }
}

        return sumInsured.divide(new BigDecimal("1000"), 6, java.math.RoundingMode.HALF_UP)
                         .multiply(ratePerThousand)
                         .setScale(2, java.math.RoundingMode.HALF_UP);
    }
}

5.5 保费计算引擎

java
// PremiumCalculator.java — 保费计算引擎
package com.insurance.domain.rating;

import java.math.BigDecimal;
import java.math.RoundingMode;
import java.time.LocalDate;
import java.util.Optional;

import com.insurance.domain.party.Insurant;
import com.insurance.domain.party.OccupationClass;
import com.insurance.infrastructure.repository.RateTableRepository;
import org.springframework.stereotype.Service;

@Service
public class PremiumCalculator {

    private final RateTableRepository rateTableRepository;

    public PremiumCalculator(RateTableRepository rateTableRepository) {
        this.rateTableRepository = rateTableRepository;
    }

    /**
     * 计算年缴保费
     *
     * @param productCode   产品代码
     * @param insurant      被保险人
     * @param sumInsured    保额
     * @param paymentPeriod 缴费期间
     * @param coveragePeriod 保障期限
     * @return 计算后的年缴保费
     */
    public PremiumResult calculateAnnualPremium(
            String productCode,
            Insurant insurant,
            BigDecimal sumInsured,
            String paymentPeriod,
            String coveragePeriod) {

        // 1. 获取基准费率
        var baseRate = findBaseRate(productCode, insurant, paymentPeriod, coveragePeriod)
                .orElseThrow(() -> new RateNotFoundException(
                    "Rate not found for product=" + productCode +
                    ", age=" + insurant.getAge() +
                    ", gender=" + insurant.getGender()));

        // 2. 基础保费
        var basePremium = baseRate.calculateBasePremium(sumInsured);

        // 3. 职业类别系数调整
        var occupationMultiplier = getOccupationMultiplier(insurant);

        // 4. 社保折扣（有社保的医疗险通常费率更低）
        var socialInsuranceDiscount = calculateSocialInsuranceDiscount(insurant);

        // 5. 总保费计算
        var adjustedPremium = basePremium
                .multiply(BigDecimal.valueOf(occupationMultiplier))
                .multiply(socialInsuranceDiscount)
                .setScale(2, RoundingMode.HALF_UP);

        return new PremiumResult(basePremium, adjustedPremium,
                                  occupationMultiplier, socialInsuranceDiscount);
    }

    private Optional<RateTable> findBaseRate(String productCode, Insurant insurant,
                                              String paymentPeriod, String coveragePeriod) {
        // 使用 Virtual Thread 并行查询（JDK 25 特性）
        try (var executor = java.util.concurrent.Executors.newVirtualThreadPerTaskExecutor()) {
            var future = executor.submit(() ->
                rateTableRepository.findByProductCodeAndAgeAndGenderAndPaymentPeriodAndCoveragePeriodAndIsActiveTrue(
                    productCode, insurant.getAge(), insurant.getGender(),
                    paymentPeriod, coveragePeriod));
            return future.get();
        } catch (Exception e) {
            throw new RuntimeException("Rate lookup failed", e);
        }
    }

    private double getOccupationMultiplier(Insurant insurant) {
        if (insurant.getOccupationClass() == null) {
            return 1.0;  // 默认为标准费率
        }
        return OccupationClass.fromLevel(insurant.getOccupationClass()).getRateMultiplier();
    }

    private BigDecimal calculateSocialInsuranceDiscount(Insurant insurant) {
        // 有社保的享有费率折扣，无社保的费率上浮
        if (Boolean.TRUE.equals(insurant.getHasSocialInsurance())) {
            return new BigDecimal("0.85");  // 15% 折扣
        }
        return BigDecimal.ONE;
    }

    /**
     * 保费计算结果记录
     */
    public record PremiumResult(
            BigDecimal basePremium,          // 基准保费
            BigDecimal adjustedPremium,       // 调整后保费
            double occupationMultiplier,      // 职业系数
            BigDecimal socialInsuranceDiscount // 社保折扣
    ) {
        // Record 类自动提供构造函数、equals、hashCode、toString
        // 可以添加额外方法
        public BigDecimal getTotalDiscount() {
            return BigDecimal.ONE.subtract(
                adjustedPremium.divide(basePremium, 4, RoundingMode.HALF_UP));
        }
    }
}

    }

五、A 偿付能力监管体系

偿付能力（Solvency）是衡量保险公司是否有足够资产履行其保单赔付义务的核心指标。各国保险监管机构均建立了偿付能力监管体系，确保保险公司在极端情况下仍能保障被保险人利益。

中国 C-ROSS 体系

中国自 2016 年起实施中国风险导向偿付能力体系（C-ROSS，简称偿二代），2022 年升级为偿二代二期工程。其核心框架遵循国际通行的"三支柱"模式：

第一支柱 — 定量资本要求：保险公司必须持有与其风险敞口相匹配的最低资本。核心指标：

  • 综合偿付能力充足率 = 实际资本 / 最低资本，监管红线 ≥ 100%
  • 核心偿付能力充足率 = 核心资本 / 最低资本，监管红线 ≥ 50%
  • 低于红线将面临监管措施：限制新业务、限制分红、强制增资

第二支柱 — 定性风险管理：要求保险公司建立全面的风险管理框架，包括风险偏好声明、压力测试、自身风险与偿付能力评估（ORSA）。

第三支柱 — 市场纪律：强制公开披露偿付能力报告，借助市场力量约束保险公司行为。

欧盟 Solvency II

欧盟 Solvency II 与 C-ROSS 设计理念相似，使用 SCR（Solvency Capital Requirement，偿付能力资本要求，对应 99.5% VaR）和 MCR（Minimum Capital Requirement，最低资本要求，对应 85% VaR）。

对 AI 系统设计的影响

在设计保险 AI 系统（尤其是核保、定价类 Agent）时，必须理解偿付能力约束：

  • 风险分类结果直接影响最低资本计算——将高风险标的错误分类为低风险会导致实际资本不足
  • AI 辅助定价模型输出的费率必须经精算师审核，确保整体保费收入满足偿付能力要求
  • 核保决策日志需保留完整审计轨迹，以满足第二支柱的定性风险管理要求

五、B 保险责任准备金

保险责任准备金（Policy Reserve）是保险公司为履行未来保险赔付义务而提取的负债科目。它是保险公司资产负债表中最大的负债项，直接决定保险公司的偿付能力状态。

主要准备金类型

类型 说明 计算基础
未到期责任准备金（UPR） 保单已收保费但保险责任尚未到期 按时间比例法：保费 × (剩余天数 / 总天数)
未决赔款准备金（OCR） 已发生但尚未结案的赔款 逐案评估法 + 统计修正
IBNR 准备金 已发生但尚未报告的赔款（Incurred But Not Reported） 精算估计模型
长期险责任准备金 寿险/健康险的未来赔付义务 精算现值公式

IBNR 估计方法

IBNR 是准备金计算中最具技术挑战的部分，常用方法包括：

  1. 链梯法（Chain Ladder Method）：基于历史赔付的发展因子（Development Factor）预测最终赔付额。假设未来的赔付发展模式与历史一致。

  2. Bornhuetter-Ferguson 方法：结合链梯法的发展因子与先验损失率估计，比纯链梯法更稳定——适用于数据量较少的新业务线。

java
import java.math.BigDecimal;
import java.math.RoundingMode;
import java.util.List;
import java.util.stream.IntStream;

/**
 * 保险责任准备金计算器
 * 实现传统精算方法：链梯法 + Bornhuetter-Ferguson
 */
public class ReserveCalculator {

    /**
     * 链梯法估计 IBNR
     * @param paidLossTriangle 已付赔款发展三角形（按事故年和进展年排列）
     * @return 每个事故年的最终赔款估计 + IBNR
     */
    public record ChainLadderResult(List<BigDecimal> ultimateLosses,
                                     List<BigDecimal> ibnrReserves,
                                     List<BigDecimal> developmentFactors) {}

    public ChainLadderResult chainLadder(BigDecimal[][] paidLossTriangle) {
        var numAccidentYears = paidLossTriangle.length;

        // Step 1: 计算逐年的发展因子（Development Factors）
        var factors = new BigDecimal[numAccidentYears - 1];
        for (var devYear = 0; devYear < numAccidentYears - 1; devYear++) {
            BigDecimal sumCurrent = BigDecimal.ZERO;
            BigDecimal sumPrevious = BigDecimal.ZERO;

            for (var accidentYear = 0;
                 accidentYear < numAccidentYears - devYear - 1;
                 accidentYear++) {
                sumCurrent = sumCurrent.add(
                    paidLossTriangle[accidentYear][devYear + 1]);
                sumPrevious = sumPrevious.add(
                    paidLossTriangle[accidentYear][devYear]);
            }

            // 加权平均发展因子
            factors[devYear] = sumPrevious.compareTo(BigDecimal.ZERO) != 0
                ? sumCurrent.divide(sumPrevious, 6, RoundingMode.HALF_UP)
                : BigDecimal.ONE;
        }

        // Step 2: 使用发展因子填充右下三角 → 得到最终赔款估计
        var ultimateLosses = new BigDecimal[numAccidentYears];
        var ibnr = new BigDecimal[numAccidentYears];

        for (var accYear = 0; accYear < numAccidentYears; accYear++) {
            var cumLoss = paidLossTriangle[accYear][numAccidentYears - accYear - 1];
            var ultimate = cumLoss;

            // 沿着发展因子链乘到最终
            for (var devYear = numAccidentYears - accYear - 1;
                 devYear < numAccidentYears - 1; devYear++) {
                ultimate = ultimate.multiply(factors[devYear]);
            }

            ultimateLosses[accYear] = ultimate.setScale(2, RoundingMode.HALF_UP);
            ibnr[accYear] = ultimate.subtract(cumLoss)
                    .setScale(2, RoundingMode.HALF_UP);
        }

        return new ChainLadderResult(
                List.of(ultimateLosses), List.of(ibnr), List.of(factors));
    }

    /**
     * Bornhuetter-Ferguson 方法 — 结合链梯法与先验损失率
     * @param earnedPremium 已赚保费
     * @param expectedLossRatio 预期损失率（如 0.65）
     * @param cumulativeDevFactor 累积发展因子的倒数（即已报告比例）
     */
    public BigDecimal bornhuetterFerguson(BigDecimal earnedPremium,
                                           BigDecimal expectedLossRatio,
                                           BigDecimal reportedPercent) {
        // IBNR = 已赚保费 × 预期损失率 × (1 - 已报告比例)
        var expectedUltimateLoss = earnedPremium.multiply(expectedLossRatio);
        var unreportedPercent = BigDecimal.ONE.subtract(reportedPercent);
        return expectedUltimateLoss.multiply(unreportedPercent)
                .setScale(2, RoundingMode.HALF_UP);
    }
}

五、C 续保流程详解

续保（Renewal）是保险业务的持续生命线。一个好的续保流程能显著提升客户留存率（Retention Rate），降低获客成本。对于 AI 保险系统，续保流程是自动化价值最高的环节之一。

续保标准工作流

[保单到期前 30 天] → 续保提醒通知（短信/App推送/邮件）
[保单到期前 15 天] → 续保二次提醒 + 续保报价单生成
[保单到期前 7 天]  → 最后续保提醒（强调保障中断风险）
[保单到期日]       → 以下两种情况之一：
                       ├── 客户已确认续保 → 生成新保单，原保单到期自然终止
                       └── 客户未确认 → 进入宽限期（Grace Period）
[宽限期内]         → 客户仍可续保（部分险种可回溯至到期日）
[宽限期结束]       → 保单正式终止，向监管机构报送终止报告

自动续保 vs 手动续保

  • 自动续保（Auto-Renewal）：适用于短期险（如一年期意外险）。监管要求必须获得客户的明示同意（Opt-in），不能默认勾选。通常通过上一期投保时的"是否开通自动续保"选项控制。

  • 手动续保（Manual Renewal）：适用于长期险或需要重新核保的险种。客户需主动确认续保并可能重新填写健康告知。

宽限期处理

宽限期（Grace Period）根据险种不同，通常为：

  • 长期寿险/健康险：60 天（自应交保费日起算）
  • 短期意外险/财产险：15-30 天
  • 宽限期内出险仍需赔付，但可扣除欠缴保费
java
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.time.LocalDate;
import java.time.temporal.ChronoUnit;
import java.util.List;

@Service
public class RenewalWorkflowService {

    private final PolicyRepository policyRepo;
    private final NotificationService notificationService;
    private final PremiumCalculator premiumCalculator;

    public RenewalWorkflowService(PolicyRepository policyRepo,
             NotificationService notificationService,
             PremiumCalculator premiumCalculator) {
        this.policyRepo = policyRepo;
        this.notificationService = notificationService;
        this.premiumCalculator = premiumCalculator;
    }

    /**
     * 每日定时任务：扫描即将到期的保单并发送续保提醒
     */
    @Transactional(readOnly = true)
    public void processDailyRenewalReminders() {
        var today = LocalDate.now();

        // 到期前 30 天提醒
        var policies30d = policyRepo.findExpiringBetween(
                today.plusDays(30), today.plusDays(31));
        policies30d.forEach(p -> notificationService.sendRenewalReminder(
                p, 30, RenewalStage.FIRST_NOTICE));

        // 到期前 15 天提醒 + 生成续保报价
        var policies15d = policyRepo.findExpiringBetween(
                today.plusDays(15), today.plusDays(16));
        policies15d.forEach(p -> {
            var renewalQuote = premiumCalculator.calculateRenewalPremium(
                    p.getPolicyId());
            notificationService.sendRenewalReminderWithQuote(
                    p, 15, renewalQuote, RenewalStage.SECOND_NOTICE);
        });

        // 到期前 7 天最后提醒
        var policies7d = policyRepo.findExpiringBetween(
                today.plusDays(7), today.plusDays(8));
        policies7d.forEach(p -> notificationService.sendRenewalReminder(
                p, 7, RenewalStage.FINAL_NOTICE));
    }

    /**
     * 续保状态流转
     */
    public enum RenewalStatus {
        PENDING_REMINDER,  // 待发送提醒
        NOTIFIED,          // 已通知
        QUOTE_SENT,        // 报价已发送
        CONFIRMED,         // 客户确认续保
        AUTO_RENEWED,      // 自动续保
        IN_GRACE_PERIOD,   // 宽限期中
        EXPIRED,           // 已到期未续保
        RENEWED            // 已完成续保（新保单已生成）
    }

    /**
     * 处理客户续保确认
     */
    @Transactional
    public Policy confirmRenewal(String oldPolicyId, String customerId) {
        var oldPolicy = policyRepo.findByIdAndCustomerId(oldPolicyId, customerId)
                .orElseThrow(() -> new RuntimeException(
                        "Policy not found: " + oldPolicyId));

        if (oldPolicy.getRenewalStatus() == RenewalStatus.RENEWED) {
            throw new IllegalStateException("Policy already renewed");
        }

        // 计算续保保费（可能因年龄增长、理赔记录调整）
        var newPremium = premiumCalculator.calculateRenewalPremium(oldPolicyId);

        // 创建新保单
        var newPolicy = Policy.builder()
                .policyNumber(generatePolicyNumber())
                .customerId(customerId)
                .productId(oldPolicy.getProductId())
                .sumInsured(oldPolicy.getSumInsured())
                .premium(newPremium)
                .effectiveDate(oldPolicy.getExpiryDate().plusDays(1))
                .expiryDate(oldPolicy.getExpiryDate().plusYears(1))
                .renewalFrom(oldPolicyId) // 记录续保来源
                .status(PolicyStatus.ACTIVE)
                .build();

        var saved = policyRepo.save(newPolicy);

        // 更新旧保单状态
        oldPolicy.setRenewalStatus(RenewalStatus.RENEWED);
        oldPolicy.setRenewedToPolicyId(saved.getPolicyId());
        policyRepo.save(oldPolicy);

        return saved;
    }

    /**
     * 每日检查宽限期是否到期
     */
    @Transactional
    public void processGracePeriodExpiry() {
        var today = LocalDate.now();
        var policiesInGrace = policyRepo.findByRenewalStatus(
                RenewalStatus.IN_GRACE_PERIOD);

        for (var policy : policiesInGrace) {
            var graceEndDate = switch (policy.getProductType()) {
                case "LIFE", "HEALTH" -> policy.getExpiryDate().plusDays(60);
                case "ACCIDENT", "PROPERTY" -> policy.getExpiryDate().plusDays(30);
                default -> policy.getExpiryDate().plusDays(15);
            };

            if (today.isAfter(graceEndDate)) {
                // 宽限期结束，保单正式终止
                policy.setStatus(PolicyStatus.TERMINATED);
                policy.setRenewalStatus(RenewalStatus.EXPIRED);
                policy.setTerminationReason("GRACE_PERIOD_EXPIRED");
                policyRepo.save(policy);

                // 向监管报送终止报告
                notificationService.reportPolicyTermination(policy);
            }
        }
    }

    private String generatePolicyNumber() {
        // 实现保单号生成逻辑
        return "POL-" + System.currentTimeMillis();
    }
}

enum RenewalStage { FIRST_NOTICE, SECOND_NOTICE, FINAL_NOTICE }

六、最佳实践与常见问题

6.1 领域建模最佳实践

  1. 聚合设计：Policy 是聚合根，Beneficiary 是它的子实体。外部访问 Beneficiary 必须通过 Policy。
  2. 值对象与实体区分：PremiumResult 使用 Record 实现为值对象（不可变），而 Policy 是有生命周期的实体。
  3. 枚举优先：职业类别、保单类型、缴费期间等固定分类应使用枚举，而非字符串常量。
  4. 金额精度：所有金额字段使用 BigDecimal，禁止使用 double 或 float。

6.2 常见问题

Q1: 为什么保费计算中要用 BigDecimal？ A: 浮点数在二进制中无法精确表示十进制小数（如0.1），在金额计算中会导致精度误差累积。BigDecimal 使用任意精度定点数，保证计算精确。

Q2: Record 类适合什么场景？ A: Record 类（JDK 16+）适用于不可变的数据载体，如 DTO、VO、计算结果等。它自动生成构造函数、equals、hashCode、toString，减少样板代码。但对于需要JPA管理的实体类，Record 不适用（JPA实体需要无参构造函数和setter）。

Q3: 如何保证等待期判断的准确性？ A: 等待期从保单生效日（effectiveDate）开始计算，以自然日为准（不扣除节假日）。核保理赔时先从保单查询 waitingPeriodDays，再判断事故发生日是否在等待期内。

Q4: 团体保险的核保与个人保险有何不同？ A: 团体保险采用"团体核保 + 个人简易核保"模式。对于规模达到一定标准的团体（如50人以上），可免去个人的全面健康告知。对于小团体（3-10人），可能需要每个被保险人提供健康告知。系统设计时应支持"团体投保单 + 被保险人清单"的数据结构。

6.3 性能与并发考虑

  • 费率表查询是高频操作，建议使用 Redis 缓存热点费率数据，TTL设置为24小时
  • 保单生成时需要分布式锁防止保单号重复（使用 Redis SETNX 或数据库唯一约束）
  • 理赔审核是低频率但高复杂度的操作，适合使用 Workflow 引擎（如 Camunda）编排审核流程
  • 所有外部调用（如再保险接口、银行支付接口）都应使用 Virtual Threads 提高吞吐量
