数据结构与算法 — Java 实现深度解析

概述

数据结构与算法是计算机科学的核心基础，也是 Java 后端工程师在系统设计、性能优化、技术面试中最重要的能力之一。本文聚焦于 Java 标准库中核心数据结构的源码实现和算法应用，从线性结构到树图结构，从排序算法到复杂度分析，系统性地梳理了日常开发中最常用的数据结构和算法知识。

本文不是算法的纯理论介绍——每个数据结构的讲解都会深入到 JDK 25 源码的关键方法，揭示其设计决策和性能权衡。

核心内容

一、线性结构

1.1 ArrayList vs LinkedList — 源码级对比

ArrayList 基于 Object[] elementData 动态数组。核心操作复杂度：随机访问 O(1)、尾部插入均摊 O(1)、中间插入/删除 O(n)。

关键源码分析（JDK 25 ArrayList.java）：

java
// 扩容机制：grow() 方法
private Object[] grow(int minCapacity) {
    int oldCapacity = elementData.length;
    if (oldCapacity > 0 || elementData != DEFAULTCAPACITY_EMPTY_ELEMENTDATA) {
        int newCapacity = ArraysSupport.newLength(oldCapacity,
                minCapacity - oldCapacity,    // 最小增长量
                oldCapacity >> 1);            // 优先增长量 = 旧容量的 50%
        return elementData = Arrays.copyOf(elementData, newCapacity);
    } else {
        return elementData = new Object[Math.max(DEFAULT_CAPACITY, minCapacity)];
    }
}

核心要点：扩容因子是 1.5 倍（oldCapacity >> 1 即 50%），不是 2 倍。ArraysSupport.newLength 确保新容量不小于 minCapacity，且不会超过 Integer.MAX_VALUE - 8。

LinkedList 基于双向链表。每个节点 Node<E> 包含 item、next、prev 三个字段。随机访问 O(n)（需要遍历），但头尾操作 O(1)。实现 Deque 接口，可作为队列和栈使用。

选型决策树：

  • 频繁随机访问 → ArrayList
  • 频繁头尾操作（队列/栈场景）→ LinkedList（但 ArrayDeque 通常更快）
  • 频繁中间插入删除 → LinkedList 理论上有优势，但实际中由于缓存局部性，ArrayList 的 System.arraycopy 对于中小规模数据的移动性能也未必差

实测参考（JMH 基准）： 对于 100 万元素的列表，ArrayList 中间插入比 LinkedList 慢约 200 倍（因为 arraycopy 移动 50 万元素），但头部遍历 ArrayList 快约 10 倍（缓存友好）。

1.2 栈与队列

ArrayDeque 是 JDK 推荐的栈和队列实现（JDK 文档明确说"ArrayDeque 比 Stack 快，比 LinkedList 快"）。基于循环数组，头尾插入/删除均为 O(1)。

java
// 使用 ArrayDeque 作为栈
var stack = new ArrayDeque<String>();
stack.push("a");           // addFirst
var top = stack.pop();     // removeFirst

// 使用 ArrayDeque 作为队列
var queue = new ArrayDeque<String>();
queue.offer("a");          // addLast
var head = queue.poll();   // removeFirst

内部实现：elements 数组长度始终是 2 的幂（通过 calculateSize 保证）。head 和 tail 指针在数组中循环移动，tail == head 时触发扩容（翻倍）。

PriorityQueue 基于二叉堆（最小堆），默认是小顶堆。siftUp 和 siftDown 维护堆性质。入队 O(log n)，出队 O(log n)，查看堆顶 O(1)。

二、树结构

2.1 红黑树与 TreeMap 源码分析

TreeMap 基于红黑树实现，是有序 Map（按 key 的自然顺序或 Comparator 排序）。核心操作为 O(log n)。

红黑树的五条性质：

  1. 每个节点是红色或黑色
  2. 根节点是黑色
  3. 每个叶子节点（NIL）是黑色
  4. 红色节点的两个子节点都是黑色
  5. 从任一节点到其每个叶子的所有路径都包含相同数目的黑色节点

TreeMap 中 put() 的关键流程：

java
public V put(K key, V value) {
    Entry<K,V> t = root;
    if (t == null) {
        root = new Entry<>(key, value, null);
        size = 1;
        return null;
    }
    // 1. 二叉搜索树插入（按 key 比较走左或右）
    // 2. fixAfterInsertion(e) → 修复红黑树性质
    //    - Case 1: 叔叔是红色 → 重新着色，上溯
    //    - Case 2: 叔叔是黑色，当前是右孩子 → 左旋
    //    - Case 3: 叔叔是黑色，当前是左孩子 → 右旋
}

fixAfterInsertion 是红黑树最复杂的部分，涉及三种情况的旋转和着色。TreeMap 的红黑树实现不要求完美平衡（不像 AVL），但保证最长路径不超过最短路径的 2 倍。

2.2 B+Tree 与数据库索引原理

B+Tree 是大多数关系数据库（MySQL InnoDB、PostgreSQL）的默认索引结构。与红黑树不同，B+Tree 是为磁盘 I/O 优化的——每个节点大小通常设为操作系统页大小（4KB/8KB/16KB），一个节点可存储大量 key。

B+Tree 特性：

  • 所有数据存储在叶子节点，非叶子节点只存 key 用于导航
  • 叶子节点通过指针形成有序链表，支持范围查询
  • 树的高度通常为 2-4 层（对于千万级数据）

为什么不用红黑树做数据库索引？ 红黑树每个节点只存一个 key，树高度大（100 万数据需约 20 层），意味着 20 次磁盘 I/O。而 B+Tree 每个节点存 100-1000 个 key，3 层即可覆盖百万级数据，只需 3 次磁盘 I/O。

InnoDB B+Tree 的关键参数： 页大小 16KB，假设主键为 8 字节 BIGINT，指针 6 字节，则每个非叶子节点可存约 1170 个 key。三层 B+Tree 可索引 1170^2 * 16 ≈ 2000 万行数据。

2.3 Trie（前缀树）

Trie 是一种用于高效字符串检索的树结构，每个节点代表一个字符。从根到某节点的路径构成该节点对应的前缀。

Java 实现（简化版）：

java
class TrieNode {
    Map<Character, TrieNode> children = new HashMap<>();
    boolean isEndOfWord;
}

class Trie {
    TrieNode root = new TrieNode();

    void insert(String word) {
        var node = root;
        for (char c : word.toCharArray()) {
            node = node.children.computeIfAbsent(c, k -> new TrieNode());
        }
        node.isEndOfWord = true;
    }

    boolean search(String word) {
        var node = root;
        for (char c : word.toCharArray()) {
            node = node.children.get(c);
            if (node == null) return false;
        }
        return node.isEndOfWord;
    }
}

应用场景： 自动补全、拼写检查、IP 路由最长前缀匹配、Elasticsearch 的 Completion Suggester。

三、哈希：HashMap 源码分析

HashMap 是 Java 中最常用的数据结构之一，JDK 25 的实现基于 数组 + 链表/红黑树。

3.1 核心字段

java
// 默认初始容量 16（必须是 2 的幂）
static final int DEFAULT_INITIAL_CAPACITY = 1 << 4;
// 最大容量 2^30
static final int MAXIMUM_CAPACITY = 1 << 30;
// 默认负载因子 0.75
static final float DEFAULT_LOAD_FACTOR = 0.75f;
// 链表转红黑树阈值：链表长度 >= 8
static final int TREEIFY_THRESHOLD = 8;
// 红黑树退化为链表阈值：树节点数 <= 6
static final int UNTREEIFY_THRESHOLD = 6;

3.2 哈希函数

java
static final int hash(Object key) {
    int h;
    return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
}

设计要点：将 hashCode 的高 16 位与低 16 位做异或，让高位参与索引计算（(n-1) & hash），减少低位相同时的碰撞。这称为"扰动函数"。

3.3 哈希碰撞解决

JDK 使用 拉链法（Separate Chaining）：

  1. 初始使用链表
  2. 当链表长度达到 TREEIFY_THRESHOLD(8) 且数组长度 >= 64 时，链表转为红黑树
  3. 当树节点数降到 UNTREEIFY_THRESHOLD(6) 时，退化为链表

为什么阈值是 8？根据泊松分布，在负载因子 0.75 下，链表长度达到 8 的概率约为千万分之六，极为罕见。一旦出现，说明 hashCode 分布极不均匀，转为红黑树可以防止退化为 O(n)。

3.4 扩容机制

resize() 方法将容量翻倍，并重新哈希所有节点：

  • 单节点：直接 newTab[e.hash & (newCap - 1)]
  • 链表：节点保持相对顺序（JDK 8+），拆分为高位链和低位链（e.hash & oldCap 判断）
  • 红黑树：类似逻辑，用 split() 方法

JDK 7 vs JDK 8+ 的差异： JDK 7 使用头插法（并发 resize 可能造成死循环），JDK 8+ 使用尾插法避免了此问题（但仍然是线程不安全的）。

3.5 负载因子的权衡

  • 负载因子越高（接近 1.0）→ 空间利用率高，但碰撞概率大，查询慢
  • 负载因子越低（接近 0.5）→ 碰撞少，查询快，但空间浪费大
  • 0.75 是在时间与空间之间的经验最优值

四、堆与 PriorityQueue

PriorityQueue 默认是最小堆（可通过 Comparator.reverseOrder() 变为最大堆）。

堆排序与 Top-K 问题：

java
// Top-K 最大元素：使用大小为 K 的最小堆
public int[] topKLargest(int[] nums, int k) {
    var minHeap = new PriorityQueue<Integer>(k);
    for (int num : nums) {
        minHeap.offer(num);
        if (minHeap.size() > k) {
            minHeap.poll();  // 弹出最小的，保留 K 个最大的
        }
    }
    return minHeap.stream().mapToInt(Integer::intValue).toArray();
}
// 时间复杂度：O(n log k)，空间复杂度：O(k)

对于 Top-K 频率问题（如 Top-K 高频词），组合 HashMap + PriorityQueue：

java
var freq = new HashMap<String, Integer>();
// ... 统计频率
var heap = new PriorityQueue<Map.Entry<String, Integer>>(
    Comparator.comparingInt(Map.Entry::getValue));
for (var entry : freq.entrySet()) {
    heap.offer(entry);
    if (heap.size() > k) heap.poll();
}

五、图算法

5.1 表示方法

  • 邻接矩阵： int[][] graph，适合稠密图，O(V^2) 空间
  • 邻接表： List<Integer>[] adj 或 Map<V, List<V>>，适合稀疏图，O(V+E) 空间

5.2 BFS 与 DFS

java
// BFS 模板（队列，最短路径、层序遍历）
void bfs(Map<Integer, List<Integer>> graph, int start) {
    var queue = new ArrayDeque<Integer>();
    var visited = new HashSet<Integer>();
    queue.offer(start);
    visited.add(start);

    while (!queue.isEmpty()) {
        int node = queue.poll();
        // 处理 node
        for (int neighbor : graph.getOrDefault(node, List.of())) {
            if (visited.add(neighbor)) {
                queue.offer(neighbor);
            }
        }
    }
}

// DFS 模板（栈或递归，路径搜索、环检测、拓扑排序）
void dfs(Map<Integer, List<Integer>> graph, int node, Set<Integer> visited) {
    visited.add(node);
    for (int neighbor : graph.getOrDefault(node, List.of())) {
        if (!visited.contains(neighbor)) {
            dfs(graph, neighbor, visited);
        }
    }
}

5.3 Dijkstra 最短路径

java
int[] dijkstra(Map<Integer, List<int[]>> graph, int n, int start) {
    int[] dist = new int[n];
    Arrays.fill(dist, Integer.MAX_VALUE);
    dist[start] = 0;

    var pq = new PriorityQueue<int[]>(Comparator.comparingInt(a -> a[1]));
    pq.offer(new int[]{start, 0});

    while (!pq.isEmpty()) {
        int[] cur = pq.poll();
        int u = cur[0], d = cur[1];
        if (d > dist[u]) continue;  // 跳过过时的记录

        for (int[] edge : graph.getOrDefault(u, List.of())) {
            int v = edge[0], w = edge[1];
            if (dist[u] + w < dist[v]) {
                dist[v] = dist[u] + w;
                pq.offer(new int[]{v, dist[v]});
            }
        }
    }
    return dist;
}

时间复杂度：O((V+E) log V)（使用二叉堆优化）。

5.4 拓扑排序（Kahn 算法）

java
List<Integer> topologicalSort(int n, List<int[]> edges) {
    int[] indegree = new int[n];
    var graph = new HashMap<Integer, List<Integer>>();
    for (int[] e : edges) {
        graph.computeIfAbsent(e[0], k -> new ArrayList<>()).add(e[1]);
        indegree[e[1]]++;
    }

    var queue = new ArrayDeque<Integer>();
    for (int i = 0; i < n; i++) {
        if (indegree[i] == 0) queue.offer(i);
    }

    var result = new ArrayList<Integer>();
    while (!queue.isEmpty()) {
        int u = queue.poll();
        result.add(u);
        for (int v : graph.getOrDefault(u, List.of())) {
            if (--indegree[v] == 0) queue.offer(v);
        }
    }
    return result.size() == n ? result : List.of(); // 有环则返回空
}

六、算法复杂度分析

6.1 时间复杂度

符号 含义
O(1) 常数时间
O(log n) 对数时间（二分查找、平衡树操作）
O(n) 线性时间（遍历数组）
O(n log n) 线性对数时间（比较排序的下界）
O(n^2) 平方时间（冒泡/选择/插入排序）

6.2 均摊分析（Amortized Analysis）

ArrayList 的 add(E e) 方法，大多数情况下是 O(1)，偶尔扩容时为 O(n)。均摊复杂度为 O(1)，因为扩容操作被均摊到 n 次插入中。

证明（聚合分析法）：插入 n 个元素的扩容总开销 = n(插入) + 16 + 24 + 36 + ... + 1.5^k * 16 ≈ n + 3n = O(n)。均摊到每个元素：O(n)/n = O(1)。

HashMap 的 put() 同样具有 O(1) 均摊复杂度（考虑扩容）。

6.3 空间复杂度

Java 对象的额外开销：在 64 位 JVM（无压缩指针）下，每个对象的对象头占 16 字节。Integer 对象占用 16（对象头）+ 4（int 值）+ 4（对齐）= 24 字节，是 int 原始类型的 6 倍。大内存场景下这是不容忽视的。

七、排序算法对比

算法 平均时间复杂度 最坏时间复杂度 空间复杂度 稳定性 JDK 中的使用
快速排序 O(n log n) O(n^2) O(log n) 不稳定 Arrays.sort(基本类型) — Dual-Pivot QuickSort
归并排序 O(n log n) O(n log n) O(n) 稳定 Arrays.sort(对象类型) — TimSort

JDK 的排序策略：

  • 基本类型数组 → Dual-Pivot QuickSort（不需要稳定性，追求速度）
  • 对象数组 → TimSort（需要稳定性，兼顾利用已有序数据）

TimSort 是归并排序的优化版，利用现实数据通常部分有序的特点：将数组分成若干个自然有序的 run，然后归并这些 run。对部分有序数据接近 O(n)。

八、跳表（ConcurrentSkipListMap）

ConcurrentSkipListMap 是基于跳表（Skip List）的并发有序 Map，是对 TreeMap 的并发替代。

跳表结构： 多层链表，底层包含所有元素，每上升一层元素数量减半（概率性）。查找时从顶层开始，向右移动直到下一个元素大于目标，然后下降一层重复。期望时间复杂度 O(log n)。

为什么用跳表而不是红黑树实现并发有序 Map？

  • 跳表的插入/删除只影响局部节点，容易实现无锁/细粒度锁并发
  • 红黑树的旋转可能影响大量节点，并发控制非常复杂
  • 跳表的概率性平衡避免了全局重组

核心用法：

java
var map = new ConcurrentSkipListMap<String, Integer>();
map.put("b", 2);
map.put("a", 1);
// 自动按 key 排序：{a=1, b=2}
// 范围查询（跳表相比 HashMap 的核心优势）
var subMap = map.subMap("a", true, "c", true);

九、布隆过滤器（Guava 实现）

布隆过滤器（Bloom Filter）是一种空间效率极高的概率性数据结构，用于判断"一个元素是否可能存在于集合中"。

原理： 使用一个位数组和 k 个独立哈希函数。插入时，对元素计算 k 个哈希值，将对应位置设为 1。查询时，检查 k 个位置是否都为 1——若是，则"可能存在"；若有一个为 0，则"绝对不存在"。

Guava 实现：

java
import com.google.common.hash.BloomFilter;
import com.google.common.hash.Funnels;

// 期望插入 100 万条记录，误报率 0.01%
var bloomFilter = BloomFilter.create(
    Funnels.integerFunnel(),
    1_000_000,
    0.0001
);

for (int i = 0; i < 1_000_000; i++) {
    bloomFilter.put(i);
}

bloomFilter.mightContain(999999);  // true
bloomFilter.mightContain(2000000); // false（绝对不存在）
// 注意：可能有极少数 false positive

误报率公式： P ≈ (1 - e^(-kn/m))^k，其中 n 为元素数，m 为位数组大小，k 为哈希函数数。

应用场景：

  • 缓存穿透防护（Redis 缓存前加布隆过滤器过滤不存在 key）
  • 垃圾邮件过滤
  • 爬虫 URL 去重
  • HBase/Cassandra 的 SSTable 查询优化

局限： 不支持删除（Counting Bloom Filter 可以但空间开销增大），不能列出所有元素，有误报率。

代码示例 — HashMap 性能对比

java
@Test

}

十、动态规划 (Dynamic Programming)

动态规划（DP）将复杂问题分解为更小的子问题来求解，依赖两个关键性质：

最优子结构：问题的最优解包含其子问题的最优解。例如，从 A 到 C 的最短路径经过 B，则 A→B 和 B→C 也必定是各自的最短路径。

重叠子问题：递归过程中同一子问题被反复计算。DP 通过缓存子问题结果（记忆化或填表）将指数时间降为多项式时间。斐波那契数列是最直观的例子——fib(5) 需要 fib(4) 和 fib(3)，而 fib(4) 又需要 fib(3)，造成大量重复计算。

自顶向下（记忆化搜索）：从原问题出发，递归求解子问题，用数组/哈希表缓存已计算过的结果。优势是代码结构与递归一致、且只计算实际需要的子问题，劣势是递归有调用栈开销。

自底向上（填表法）：先求解最小子问题，逐步向上推导到原问题，通常用迭代 + 数组实现。优势是消除递归开销、通常更快，劣势是可能计算了一些不需要的子问题。

经典例题：0/1 背包问题

给定 n 件物品，每件重量 w[i]、价值 v[i]，背包容量为 W，每件物品只能选或不选，求能装入背包的最大总价值。

java
// 0/1 背包 — 自底向上二维 DP
public int knapsack(int[] w, int[] v, int W) {
    int n = w.length;
    int[][] dp = new int[n + 1][W + 1]; // dp[i][j]: 前 i 件物品, 容量 j 的最大价值
    for (int i = 1; i <= n; i++) {
        for (int j = 0; j <= W; j++) {
            if (j < w[i - 1]) {
                dp[i][j] = dp[i - 1][j];               // 装不下，跳过
            } else {
                dp[i][j] = Math.max(dp[i - 1][j],      // 不选第 i 件
                                    dp[i - 1][j - w[i - 1]] + v[i - 1]); // 选第 i 件
            }
        }
    }
    return dp[n][W];
}

空间优化（一维 DP）：dp 行只依赖上一行，可将二维数组压缩为一维。关键点——内层循环必须逆序，防止同一物品被重复使用（0/1 背包要求每件物品只能选一次）：

java
public int knapsack1D(int[] w, int[] v, int W) {
    int[] dp = new int[W + 1];
    for (int i = 0; i < w.length; i++) {
        for (int j = W; j >= w[i]; j--) {  // 逆序！防止物品重复使用
            dp[j] = Math.max(dp[j], dp[j - w[i]] + v[i]);
        }
    }
    return dp[W];
}

时间复杂度 O(nW)，空间复杂度 O(W)。注意这是伪多项式算法——复杂度依赖 W 的数值大小而非编码长度。

最长公共子序列（LCS）：dp[i][j] 表示 s1 前 i 字符与 s2 前 j 字符的 LCS 长度。若 s1[i-1]==s2[j-1]，则 dp[i][j]=dp[i-1][j-1]+1；否则取 max(dp[i-1][j], dp[i][j-1])。时间复杂度 O(mn)，空间可优化到 O(min(m,n))。

编辑距离（Levenshtein Distance）：将 word1 转换为 word2 所需的最少单字符操作数（插入、删除、替换）。递推式：dp[i][j]=min(dp[i-1][j]+1, dp[i][j-1]+1, dp[i-1][j-1]+(word1[i-1]!=word2[j-1]?1:0))。广泛应用于拼写检查、DNA 序列比对、模糊搜索。

十一、贪心算法 (Greedy)

贪心算法的核心思想：每一步都做出当前看起来最优的选择（局部最优），期望最终累积为全局最优解。与动态规划不同，贪心不做回溯、不考虑未来，因此速度快但适用范围有限。

贪心 vs DP 对比：

维度 动态规划 贪心算法
决策方式 考虑所有子问题组合 每步只做一次最优选择
回溯 隐含在状态转移中 不做回溯
正确性保证 最优子结构 + 无后效性 需证明贪心选择性质
时间复杂度 通常较高 通常较低
是否最优 保证全局最优 不一定

判断一个问题应选 DP 还是贪心，关键是验证贪心选择性质——局部最优能否推导出全局最优。例如 0/1 背包不能用贪心（物品不可分割，贪心可能选错），但分数背包可以（按单位价值贪心即得最优解）。

活动选择问题（Activity Selection）：给定 n 个活动，每个有开始时间 s[i] 和结束时间 f[i]，求最大兼容活动子集（活动时间不重叠）。贪心策略：每次选择结束时间最早的活动。

java
// 活动选择 — 贪心 O(n log n)
public List<int[]> selectActivities(int[][] activities) {
    Arrays.sort(activities, Comparator.comparingInt(a -> a[1])); // 按结束时间排序
    var result = new ArrayList<int[]>();
    int lastEnd = Integer.MIN_VALUE;
    for (int[] act : activities) {
        if (act[0] >= lastEnd) {   // 与上一个选中活动不冲突
            result.add(act);
            lastEnd = act[1];
        }
    }
    return result;
}

贪心选择性质的证明思路：假设最优解不包含最早结束的活动 A，将最优解中第一个活动替换为 A，结束时间不会更晚，仍合法且活动数不变——因此存在包含 A 的最优解。归纳证明贪心策略正确。

哈夫曼编码（Huffman Coding）：无损数据压缩的最优前缀编码。贪心策略：每次从频率集合中取出两个频率最小的节点合并为新节点，重复至只剩一个根。Java 中用 PriorityQueue 维护最小堆，时间复杂度 O(n log n)。哈夫曼编码保证平均编码长度最短——贪心选择合并频率最低的两个节点不会影响最优性。

Dijkstra 算法的贪心本质：每次从优先队列中取出距离起点最近的"未确定"节点，声明其最短距离已知——这一操作是贪心的，且由于边权非负，该声明永远不会被后续结果推翻。Dijkstra 不能处理负权边的根源正在于此——一旦"贪心选中"就无法撤销。

十二、回溯算法 (Backtracking)

回溯算法的核心思想是试探 + 回退 + 剪枝：在解空间树上尝试一种可能分支，若发现该分支不可能得到解（或不满足约束），则回退到上一步尝试其他选择。回溯本质是对穷举的智能优化——通过剪枝大幅缩减搜索空间。

回溯 vs DFS：DFS 是搜索策略（尽可能深地遍历树/图），回溯是算法范式。回溯使用 DFS 遍历解空间树，但额外包含两个关键步骤：(1) 在每次选择前做约束检查（剪枝），(2) 递归返回后恢复状态（撤销选择）。DFS 本身不包含"回退"和"约束检查"的概念。

回溯三要素：(1) 路径——已经做出的选择；(2) 选择列表——当前可做的选择；(3) 终止条件——到达决策树的底层，无法再做选择。

N 皇后问题：在 N×N 棋盘上放置 N 个皇后，使其互不攻击（不同行、列、正反对角线）。

java
public List<List<String>> solveNQueens(int n) {
    var result = new ArrayList<List<String>>();
    var board = new char[n][n];
    for (char[] row : board) Arrays.fill(row, '.');
    backtrack(board, 0, result);
    return result;
}

void backtrack(char[][] board, int row, List<List<String>> result) {
    int n = board.length;
    if (row == n) {                               // 终止条件：所有行都放置了皇后
        result.add(Arrays.stream(board).map(String::new).toList());
        return;
    }
    for (int col = 0; col < n; col++) {
        if (!isValid(board, row, col)) continue;  // 剪枝：跳过不合法的列
        board[row][col] = 'Q';                    // 做选择
        backtrack(board, row + 1, result);        // 递归下一行
        board[row][col] = '.';                    // 回退：撤销选择
    }
}

boolean isValid(char[][] board, int row, int col) {
    int n = board.length;
    for (int i = 0; i < row; i++) {            // 只需检查上方（下方尚未放置）
        if (board[i][col] == 'Q') return false; // 同列
        int diff = row - i;
        if (col - diff >= 0 && board[i][col - diff] == 'Q') return false; // 左上对角线
        if (col + diff < n && board[i][col + diff] == 'Q') return false;  // 右上对角线
    }
    return true;
}

时间复杂度 O(N!)（实际因剪枝远小于此），N=8 时解空间从 4,426,165,368 降至仅 20,736 次检查。

全排列与子集生成：全排列用 used[] 数组标记已选元素，子集问题在每一步做"选/不选"两个分支，两者均为回溯的经典模板题。

剪枝优化策略：(1) 可行性剪枝——当前选择已违反约束，直接跳过（如 N 皇后的 isValid 检查）；(2) 最优性剪枝——当前部分解不可能优于已有最优解，直接 return；(3) 顺序剪枝——通过排序或限定搜索顺序让分支更早发现冲突（如组合总和问题先排序，让分支更快超限）。

十三、分治算法 (Divide and Conquer)

分治算法的核心步骤为三步：分（Divide）——将原问题分解为若干个规模较小的同类子问题；治（Conquer）——递归求解每个子问题；合（Combine）——将子问题的解合并为原问题的解。

与递归的关系：所有分治算法都是递归的（子问题与原问题结构相同），但并非所有递归都是分治。例如：斐波那契的递归没有"合"这一步骤（减治，Decrease and Conquer）；分治的典型特征是多个子问题 + 合并步骤。

Master Theorem（主定理）：用于求解递推式 T(n) = a·T(n/b) + f(n) 的渐进界，其中 a 个子问题、每个规模 n/b、f(n) 是分解和合并的开销。三种情况：

  • 递归主导：若 f(n) = O(n^(log_b(a) - ε))，则 T(n) = Θ(n^(log_b(a)))。分解合并开销远小于递归，瓶颈在递归本身。
  • 均衡：若 f(n) = Θ(n^(log_b(a)))，则 T(n) = Θ(n^(log_b(a)) · log n)。分解合并与递归同量级。
  • 合并主导：若 f(n) = Ω(n^(log_b(a) + ε))，则 T(n) = Θ(f(n))。分解合并开销远大于递归，瓶颈在合并。

归并排序的分治视角：分——数组从中间对半拆分（O(1)）；治——递归排序左右子数组（2 T(n/2)）；合——归并两个有序子数组（O(n)）。Master Theorem：a=b=2, f(n)=O(n)，属于第二种（均衡），T(n) = Θ(n log n)。

java
// 归并排序 — 核心 merge 步骤（"合"）
void merge(int[] arr, int l, int m, int r) {
    int[] left = Arrays.copyOfRange(arr, l, m + 1);
    int[] right = Arrays.copyOfRange(arr, m + 1, r + 1);
    int i = 0, j = 0, k = l;
    while (i < left.length && j < right.length) {
        arr[k++] = left[i] <= right[j] ? left[i++] : right[j++];
    }
    while (i < left.length) arr[k++] = left[i++];
    while (j < right.length) arr[k++] = right[j++];
}

快速排序的分治分析：分——选取 pivot 并分区（partition），使左侧元素 <= pivot，右侧 >= pivot；治——递归排序左右子数组；合——不需要显式合并（分区后 pivot 已在最终正确位置）。Master Theorem：平均情况下，a=b=2, f(n)=O(n)，Θ(n log n)；最坏情况下分区极不平衡，退化为 O(n^2)。

Strassen 矩阵乘法：将两个 n×n 矩阵乘法的 8 次子乘法巧妙减少为 7 次（通过 18 次矩阵加法），时间复杂度从 Θ(n^3) 降至 Θ(n^log₂7) ≈ Θ(n^2.807)。Coppersmith-Winograd 等后续算法进一步将指数压至约 2.371。

最近点对问题：在平面上 n 个点中找距离最近的一对。分治法：按 x 坐标排序并对半分治，递归求每侧最近距离 δ，合并时只需检查 x 坐标在 ±δ 范围内的 O(1) 个点。总时间复杂度 O(n log n)，优于暴力 O(n^2)。

十四、字符串匹配 (String Matching)

字符串匹配是计算机科学中最基础的问题之一：在文本串 T（长度 n）中查找模式串 P（长度 m）的所有出现位置。

暴力匹配（Brute Force）：从 T 的每个位置开始，逐字符与 P 比较。匹配失败则将模式串右移一位重新开始。最坏时间复杂度 O(nm)（例如 T="aaaaaab", P="aaab"，每次比较到 P 的最后一位才失败），平均性能通常尚可。JDK 中 String.indexOf 在某些短模式串场景下直接使用暴力匹配。

KMP 算法（Knuth-Morris-Pratt）：充分利用已匹配部分的信息，避免文本串指针回退。核心是 next 数组（"部分匹配表"）——next[i] 表示 P[0..i-1] 的最长相等前后缀长度。匹配失败时，i（文本串指针）不回退，j（模式串指针）跳到 next[j] 继续比较。

java
// KMP 算法 — next 数组构建 + 匹配
public int[] kmp(String text, String pattern) {
    int n = text.length(), m = pattern.length();
    if (m == 0) return new int[]{0};
    // 1. 构建 next 数组（模式串自匹配）
    int[] next = new int[m];
    for (int i = 1, j = 0; i < m; i++) {
        while (j > 0 && pattern.charAt(i) != pattern.charAt(j)) {
            j = next[j - 1];   // 回退到之前匹配的前缀位置
        }
        if (pattern.charAt(i) == pattern.charAt(j)) j++;
        next[i] = j;
    }
    // 2. 匹配过程
    var result = new ArrayList<Integer>();
    for (int i = 0, j = 0; i < n; i++) {
        while (j > 0 && text.charAt(i) != pattern.charAt(j)) {
            j = next[j - 1];
        }
        if (text.charAt(i) == pattern.charAt(j)) j++;
        if (j == m) {            // 完全匹配
            result.add(i - m + 1);
            j = next[j - 1];     // 继续找下一个匹配位置
        }
    }
    return result.stream().mapToInt(Integer::intValue).toArray();
}

next 数组构建时间复杂度 O(m)，匹配过程 O(n)，总复杂度 O(n+m)。KMP 的性能与字符集大小无关，在最坏情况下仍保持线性，这是相比暴力匹配的核心优势。

Boyer-Moore 算法：从模式串末尾向前匹配，利用"坏字符规则"（当前不匹配字符在模式串中最右出现位置）和"好后缀规则"（已匹配后缀在模式串中的前一次出现位置）计算最大安全滑动距离。实践中通常是最快的单模式匹配算法，尤其在长模式串和大字符集场景。

Rabin-Karp 算法：基于哈希的匹配。计算模式串的哈希值，在文本串上滑动窗口，使用滚动哈希（Rolling Hash）在 O(1) 时间内从窗口哈希推导出下一窗口哈希。仅当哈希值匹配时才逐字符验证。平均时间 O(n+m)，最坏 O(nm)（哈希碰撞严重时需逐字符验证每个位置）。

在 AI 中的应用：(1) Tokenizer 子词匹配——BPE/WordPiece 分词需要高效地在文本中查找已知子词；(2) 敏感词过滤——多模式匹配使用 AC 自动机（Aho-Corasick，Trie + KMP 思想）；(3) RAG 检索——关键词提取和精确匹配阶段频繁使用字符串搜索；(4) Elasticsearch 倒排索引——底层依赖高效的字符串处理和匹配算法。

常见问题 / 面试题

Q1: HashMap 为什么线程不安全？ 在 JDK 8+ 中，多线程同时 put 可能导致：数据覆盖（两个线程同时 hash 到同一位置）、size 字段不一致（非原子操作）、resize 时可能造成数据丢失。使用 ConcurrentHashMap 替代。

Q2: 为什么 HashMap 的容量必须是 2 的幂？ 因为索引计算使用 (n-1) & hash（位运算取模），2 的幂保证 n-1 的二进制全是 1，哈希值可以均匀分布。如果容量不是 2 的幂，位运算取模会产生大量碰撞。

Q3: 红黑树 vs AVL 树的权衡？ AVL 树更严格平衡（高度差 <= 1），查找更快但插入/删除旋转次数更多。红黑树牺牲部分平衡性（最长路径 <= 2*最短路径），换取更少的旋转操作，插入/删除更高效。Java TreeMap 选择红黑树，因为 Map 场景写操作频繁。

Q4: 如何实现 LRU 缓存？ 使用 LinkedHashMap 并重写 removeEldestEntry，或手动实现 HashMap + 双向链表。LinkedHashMap 的 accessOrder=true 模式自动维护访问顺序。

Q5: Bloom Filter 的 mightContain 返回 true，元素一定存在吗？ 不是。Bloom Filter 可能产生假阳性（false positive），但不会产生假阴性。返回 true 意味着"可能存在"，需要进一步验证（如查数据库）；返回 false 意味着"绝对不存在"。
