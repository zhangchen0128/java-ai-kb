AI 评估三层次 + LLM-as-a-Judge + Golden Dataset + 可观测性技术栈

一、概述

AI 应用的质量保障比传统软件更复杂——输出是非确定性的、评估标准主观性强、链路长（检索+生成+工具调用）。本文提出一个系统化的 AI 评估和可观测性框架，涵盖离线评估、在线评估、Agent 评估三个层次，结合 LLM-as-a-Judge、Golden Dataset 回归测试和 OpenTelemetry 全链路追踪。

所有代码使用 JDK 25 + Spring Boot 4.x + Spring AI 2.x，充分利用 var 关键字和 Virtual Threads。

二、AI 评估三层次

MRR 和 NDCG 计算实现：

java
public class RetrievalMetricsCalculator {

    /**
     * 计算 Mean Reciprocal Rank。
     * MRR = (1/|Q|) * sum(1/rank_i)
     * 其中 rank_i 是第 i 个查询的第一个相关文档的排名位置。
     */
    public static double calculateMRR(List<QueryRelevance> queryRelevances) {
        return queryRelevances.stream()
            .mapToDouble(qr -> {
                var firstRelevantRank = qr.relevanceScores().stream()
                    .takeWhile(score -> score == 0)  // 0=不相关
                    .count();
                return firstRelevantRank < qr.relevanceScores().size()
                    ? 1.0 / (firstRelevantRank + 1)
                    : 0.0;
            })
            .average()
            .orElse(0.0);
    }

    /**
     * 计算 NDCG@k。
     * DCG@k = sum(rel_i / log2(i+1)) for i=1..k
     * IDCG@k = 理想排序下的 DCG@k
     * NDCG@k = DCG@k / IDCG@k
     */
    public static double calculateNDCG(List<Double> relevanceScores, int k) {
        var dcg = 0.0;
        for (int i = 0; i < Math.min(relevanceScores.size(), k); i++) {
            dcg += relevanceScores.get(i) / (Math.log(i + 2) / Math.log(2));
        }

        // IDCG: 按相关性降序排列的理想 DCG
        var sortedScores = relevanceScores.stream()
            .sorted(Comparator.reverseOrder())
            .toList();
        var idcg = 0.0;
        for (int i = 0; i < Math.min(sortedScores.size(), k); i++) {
            idcg += sortedScores.get(i) / (Math.log(i + 2) / Math.log(2));
        }

        return idcg == 0 ? 0.0 : dcg / idcg;
    }

    public record QueryRelevance(String queryId, List<Integer> relevanceScores) {}
}

2.3 Agent 评估（Agent Evaluation）

Agent 场景比单次问答更复杂，需要评估工具选择和调用链路的正确性。

java
public record AgentEvalMetrics(
    // 工具选择
    double toolSelectionAccuracy,       // 选择的工具是否正确
    double toolParameterAccuracy,       // 工具参数是否正确

    // 执行质量
    double stepCountDelta,              // 实际步骤数与最优步骤数的偏差
    double authorizationViolationRate,  // 越权调用检测率
    double finalResultCorrectness,      // 最终结果正确率
    double hallucinatedToolCallRate,    // 幻觉工具调用率（调用了不存在的工具）

    // 效率
    double avgToolCallLatencyMs,        // 平均工具调用延迟
    double toolCallChainLength          // 工具调用链平均长度
) {}

/**
 * Agent 执行追踪和评估
 */
@Service
public class AgentEvaluator {

    private final MeterRegistry registry;
    private final Tracer tracer;

    /**
     * 评估一次 Agent 执行轨迹。
     * @param trace 实际执行轨迹
     * @param goldenTrace 期望的执行轨迹（人工标注的"标准答案"）
     */
    public AgentEvalMetrics evaluate(AgentExecutionTrace trace,
                                      AgentExecutionTrace goldenTrace) {
        var toolAccuracy = evaluateToolSelection(trace, goldenTrace);
        var paramAccuracy = evaluateParameters(trace, goldenTrace);
        var stepDelta = Math.abs(trace.steps().size() - goldenTrace.steps().size());
        var violations = detectAuthorizationViolations(trace);
        var resultCorrect = evaluateFinalResult(trace, goldenTrace);

        return new AgentEvalMetrics(
            toolAccuracy,
            paramAccuracy,
            stepDelta,
            violations,
            resultCorrect,
            calculateAvgToolLatency(trace),
            trace.steps().size()
        );
    }

    private double evaluateToolSelection(AgentExecutionTrace trace,
                                          AgentExecutionTrace goldenTrace) {
        var actualTools = trace.steps().stream()
            .map(AgentStep::toolName)
            .collect(Collectors.toSet());
        var expectedTools = goldenTrace.steps().stream()
            .map(AgentStep::toolName)
            .collect(Collectors.toSet());

        if (expectedTools.isEmpty()) return 1.0;

        var intersection = new HashSet<>(actualTools);
        intersection.retainAll(expectedTools);
        // F1-like: 综合考虑 precision 和 recall
        var precision = (double) intersection.size() / actualTools.size();
        var recall = (double) intersection.size() / expectedTools.size();
        return precision + recall > 0
            ? 2 * precision * recall / (precision + recall)
            : 0.0;
    }

    private double evaluateParameters(AgentExecutionTrace trace,
                                       AgentExecutionTrace goldenTrace) {
        var correctCount = 0;
        var totalParamCount = 0;

        for (var goldenStep : goldenTrace.steps()) {
            var actualStep = trace.findStepByToolName(goldenStep.toolName());
            if (actualStep == null) continue;

            for (var entry : goldenStep.parameters().entrySet()) {
                totalParamCount++;
                var actualValue = actualStep.parameters().get(entry.getKey());
                if (Objects.equals(entry.getValue(), actualValue)) {
                    correctCount++;
                }
            }
        }

        return totalParamCount == 0 ? 1.0 : (double) correctCount / totalParamCount;
    }

    private double detectAuthorizationViolations(AgentExecutionTrace trace) {
        var violations = trace.steps().stream()
            .filter(step -> step.requiredPermissions() != null)
            .filter(step -> !step.grantedPermissions()
                .containsAll(step.requiredPermissions()))
            .count();
        return trace.steps().isEmpty()
            ? 0.0
            : (double) violations / trace.steps().size();
    }

    private double evaluateFinalResult(AgentExecutionTrace trace,
                                        AgentExecutionTrace goldenTrace) {
        // 可以使用 LLM-as-a-Judge 对比最终输出
        return trace.finalOutput() != null
                && trace.finalOutput().equals(goldenTrace.finalOutput())
            ? 1.0 : 0.0;
    }
}

三、LLM-as-a-Judge 实现

用大模型作为裁判来评估另一个大模型的输出，是一种可扩展的自动化评估方法。

3.1 Rubric 设计

设计清晰的 1-5 分评分标准（Rubric），确保评估的一致性和可复现性。

            "评估回答的事实准确性",
            Map.of(

                3, "回答基本正确但存在细节偏差或遗漏关键信息。",
                4, "回答准确，仅有极少数非关键信息偏差。",

    }

        return new EvaluationRubric(

3.2 Judge 服务实现

java
@Service
public class LlmAsJudgeService {

    private final ChatClient judgeClient;  // 用于打分的大模型
    private final PromptTemplateEngine promptEngine;

    private static final String JUDGE_SYSTEM_PROMPT = """
        你是一个专业的AI回答质量评估员。请严格根据以下评分准则对候选回答打分。

        评分维度：{{rubric.dimension}}
        评分标准：
        {% for entry in rubric.scoringCriteria %}
        - 分数 {{entry.key}}：{{entry.value}}
        {% endfor %}

        评估规则：
        1. 仔细阅读【参考标准答案】（如有）和【检索到的上下文】（如有）
        2. 对比【候选回答】，给出 1-5 分的评分
        3. 你必须在 JSON 中返回评分和详细理由

        请以 JSON 格式返回：
        {
          "score": <整数1-5>,
          "reasoning": "<评分理由，不超过200字>"
        }
        """;

    private static final String JUDGE_USER_TEMPLATE = """
        【问题】
        {{question}}

        {% if referenceAnswer %}
        【参考标准答案】
        {{referenceAnswer}}
        {% endif %}

        {% if retrievedContexts %}
        【检索到的上下文】
        {% for ctx in retrievedContexts %}
        --- 文档 {{loop.index}} ---
        {{ctx}}
        {% endfor %}
        {% endif %}

        【候选回答】
        {{candidateAnswer}}

        请开始评分。
        """;

    /**
     * 单次评估。
     * @param rubric 评分准则
     * @param question 原始问题
     * @param candidateAnswer 待评估的回答
     * @param referenceAnswer 参考标准答案（Golden Dataset 提供，可为 null）
     * @param retrievedContexts 检索到的上下文文档
     */
    public JudgeResult evaluate(EvaluationRubric rubric,
                                 String question,
                                 String candidateAnswer,
                                 String referenceAnswer,
                                 List<String> retrievedContexts) {
        var systemPrompt = promptEngine.render(JUDGE_SYSTEM_PROMPT,
            Map.of("rubric", rubric));

        var userPrompt = promptEngine.render(JUDGE_USER_TEMPLATE, Map.of(
            "question", question,
            "referenceAnswer", referenceAnswer != null ? referenceAnswer : "",
            "retrievedContexts", retrievedContexts != null ? retrievedContexts : List.of(),
            "candidateAnswer", candidateAnswer
        ));

        var response = judgeClient.prompt()
            .system(systemPrompt)
            .user(userPrompt)
            .call()
            .content();

        return parseJudgeResponse(response);
    }

    private JudgeResult parseJudgeResponse(String response) {
        // 解析 JSON 响应
        try {
            var objectMapper = new ObjectMapper();
            var node = objectMapper.readTree(response);
            return new JudgeResult(
                node.get("score").asInt(),
                node.get("reasoning").asText()
            );
        } catch (Exception e) {
            return new JudgeResult(-1, "Failed to parse judge response: " + e.getMessage());
        }
    }

    public record JudgeResult(int score, String reasoning) {}
}

3.3 位置偏差缓解与多 Judge 一致性

java
@Service
public class RobustJudgeService {

    private final LlmAsJudgeService judgeService;

    /**
     * 通过交换对比顺序缓解位置偏差（Position Bias）。
     * 某些 LLM Judge 倾向于给先出现或后出现的答案打高分。
     * 我们运行两轮评估（交换顺序），取平均分。
     */
    public JudgeResult evaluatePositionDebiased(
            EvaluationRubric rubric,
            String question,
            String candidateAnswer,
            String referenceAnswer,
            List<String> contexts) {

        // 第一轮：候选回答在前
        var result1 = judgeService.evaluate(
            rubric, question, candidateAnswer, referenceAnswer, contexts);

        // 第二轮：候选回答在后（通过修改模板
        // 在实际实现中，可创建一个"翻转"的 prompt 模板）
        var result2 = judgeService.evaluate(
            rubric, question, referenceAnswer, candidateAnswer, contexts);

        return new JudgeResult(
            (result1.score() + result2.score()) / 2,
            "Position-debiased average of two rounds. Round1: %d (\"%s\"), Round2: %d (\"%s\")"
                .formatted(result1.score(), result1.reasoning(),
                    result2.score(), result2.reasoning())
        );
    }

    /**
     * 多 Judge 一致性评估。使用多个不同模型作为 Judge，计算 Fleiss' Kappa。
     */
    public MultiJudgeResult evaluateWithMultipleJudges(
            EvaluationRubric rubric,
            String question,
            String candidateAnswer,
            String referenceAnswer,
            List<String> contexts,
            List<String> judgeModels) {

        var results = new ArrayList<JudgeResult>();
        for (var model : judgeModels) {
            var result = judgeService.evaluate(
                rubric, question, candidateAnswer, referenceAnswer, contexts);
            results.add(result);
        }

        var kappa = calculateFleissKappa(results);
        var avgScore = results.stream()
            .mapToInt(JudgeResult::score)
            .average()
            .orElse(0);

        return new MultiJudgeResult(avgScore, results, kappa,
            kappa >= 0.6 ? "substantial_agreement" : "poor_agreement");
    }

    /**
     * 计算 Fleiss' Kappa 系数来衡量多个评分者之间的一致性。
     * Kappa > 0.6：基本一致
     * Kappa > 0.8：高度一致
     */
    private double calculateFleissKappa(List<JudgeResult> results) {
        int n = results.size();          // 评分者数量
        int k = 5;                       // 类别数 (1-5分)
        int[][] matrix = new int[1][k];  // 简化版：单个样本

        for (var result : results) {
            int score = Math.clamp(result.score(), 1, 5);
            matrix[0][score - 1]++;
        }

        // P_i: 每个样本的观察一致性
        double sumPi = 0;
        for (int i = 0; i < 1; i++) {
            double sumSquared = 0;
            for (int j = 0; j < k; j++) {
                sumSquared += (double) matrix[i][j] * matrix[i][j];
            }
            sumPi += (sumSquared - n) / (n * (n - 1.0));
        }
        double P_bar = sumPi / 1.0;

        // P_e: 期望一致性
        double sumPjSquared = 0;
        for (int j = 0; j < k; j++) {
            double pj = (double) matrix[0][j] / n;
            sumPjSquared += pj * pj;
        }

        return P_bar == 1.0 ? 1.0
            : (P_bar - sumPjSquared) / (1.0 - sumPjSquared);
    }
}

/**
 * Golden Dataset 版本化管理与自动回归测试
 */
@Service
public class GoldenDatasetService {

    private final GoldenDatasetRepository repo;
    private final ChatClient chatClient;
    private final LlmAsJudgeService judgeService;
    private final OfflineEvaluator offlineEvaluator;

    /**
     * 执行回归测试：在每次模型/Prompt/Embedding 变更后，对 Golden Dataset
     * 中的所有条目重新跑一遍评估，对比历史基线，发现退化（regression）。
     */
    public RegressionTestReport runRegressionTest(
            String datasetVersion, String modelName, String promptVersionId) {

        var items = repo.findByDatasetVersion(datasetVersion);
        var report = new RegressionTestReport(datasetVersion, modelName,
            promptVersionId, Instant.now());

        try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
            var futures = items.stream()
                .map(item -> executor.submit(() -> evaluateSingleItem(
                    item, modelName, promptVersionId)))
                .toList();

            for (var future : futures) {
                try {
                    var result = future.get(5, TimeUnit.MINUTES);
                    report.addItemResult(result);
                } catch (TimeoutException e) {
                    report.addTimeout();
                } catch (Exception e) {
                    report.addError(e.getMessage());
                }
            }
        }

        report.computeSummary();
        return report;
    }

    private GoldenItemEvalResult evaluateSingleItem(
            GoldenDatasetItem item, String modelName, String promptVersionId) {

        var start = Instant.now();

        // 调用模型获取实际回答
        var actualAnswer = chatClient.prompt()
            .user(item.getQuestion())
            .call()
            .content();

        var duration = Duration.between(start, Instant.now());

        // LLM-as-Judge 评估
        var correctnessResult = judgeService.evaluate(
            EvaluationRubric.correctnessRubric(),
            item.getQuestion(), actualAnswer, item.getExpectedAnswer(), null);

        var faithfulnessResult = judgeService.evaluate(
            EvaluationRubric.faithfulnessRubric(),
            item.getQuestion(), actualAnswer, null, item.getReferenceDocuments());

        return new GoldenItemEvalResult(
            item.getId(), item.getQuestion(),
            item.getExpectedAnswer(), actualAnswer,
            Map.of(
                "correctness", (double) correctnessResult.score(),
                "faithfulness", (double) faithfulnessResult.score()
            ),
            duration,
            null  // no error
        );
    }

    /**
     * 回归检测：对比本次得分与基线得分，标记退化的条目。
     */

public class OpenTelemetryAiTrace implements AiTracePort {

        span.setAttribute("retrieval.latency_ms", latencyMs);

        span.setAttribute("tool.success", result != null);

        span.addEvent("tool.call.completed",

/**
 * 通过 Spring AI 的 Advisor 机制自动为每次 LLM 调用添加追踪。
 */
@Component
public class AiTracingAdvisor implements RequestResponseAdvisor {

    private final AiTracePort aiTrace;
    private final MeterRegistry meterRegistry;

    @Override
    public AdvisedRequest adviseRequest(AdvisedRequest request,
                                         Map<String, Object> context) {
        var span = aiTrace.startAiSpan("llm_call", Map.of(
            "model", request.model() != null ? request.model() : "unknown"
        ));
        context.put("ai.span", span);
        context.put("ai.start_time", System.currentTimeMillis());
        return request;
    }

    @Override
    public ChatResponse adviseResponse(ChatResponse response,
                                        Map<String, Object> context) {
        var span = (Span) context.get("ai.span");
        var startTime = (Long) context.get("ai.start_time");
        if (span != null && startTime != null) {
            var latency = System.currentTimeMillis() - startTime;
            var metadata = response.getMetadata();
            var usage = metadata.getUsage();

            // 记录 LLM 调用事件
            aiTrace.recordLlmEvent(span,
                metadata.getModel(),
                usage != null ? (int) usage.getPromptTokens() : 0,
                usage != null ? (int) usage.getGenerationTokens() : 0,
                calculateCost(metadata.getModel(), usage),
                latency
            );

            // 记录 Micrometer 指标
            meterRegistry.timer("ai.llm.call",
                "model", metadata.getModel())
                .record(latency, TimeUnit.MILLISECONDS);

            span.end();
        }
        return response;
    }

    private double calculateCost(String model, Usage usage) {
        if (usage == null) return 0;
        // 简化的成本计算
        var costPer1kPrompt = switch (model) {
            case "gpt-4o" -> 0.0025;
            case "gpt-4o-mini" -> 0.00015;
            case "claude-sonnet-4-20250514" -> 0.003;
            default -> 0.001;
        };
        var costPer1kCompletion = costPer1kPrompt * 4;  // 通常 completion 是 prompt 的 4 倍
        return (usage.getPromptTokens() * costPer1kPrompt
            + usage.getGenerationTokens() * costPer1kCompletion) / 1000.0;
    }
}

六、评估流水线完整编排

将离线评估、Golden Dataset 回归测试和报告生成整合为一个可自动运行的流水线。

java
@Service
public class EvaluationPipeline {

    private final GoldenDatasetService datasetService;
    private final LlmAsJudgeService judgeService;
    private final OfflineEvaluator offlineEvaluator;
    private final OnlineMetricsCollector onlineCollector;
    private final NotificationService notificationService;

    /**
     * 在以下时机触发自动评估流水线：
     * 1. 模型版本升级
     * 2. Prompt 模板变更
     * 3. Embedding 模型切换
     * 4. RAG 检索策略调整
     */
    public PipelineReport runPipeline(EvaluationTrigger trigger) {
        var report = new PipelineReport(trigger, Instant.now());

        // Phase 1: Golden Dataset 回归测试
        var regressionReport = datasetService.runRegressionTest(
            "v2.0", trigger.modelName(), trigger.promptVersionId());
        report.setRegressionReport(regressionReport);

        // Phase 2: LLM-as-a-Judge 专项评估（多个维度）
        var judgeScores = evaluateWithAllRubrics(regressionReport);
        report.setJudgeScores(judgeScores);

        // Phase 3: 性能基准测试
        var perfBaseline = measurePerformanceBaseline(trigger);
        report.setPerfBaseline(perfBaseline);

        // Phase 4: 判定是否通过
        report.evaluatePassCriteria(List.of(
            new PassCriterion("regression_passed",
                !regressionReport.passed(), false),
            new PassCriterion("judge_score_min",
                judgeScores.values().stream().mapToDouble(Double::doubleValue)
                    .average().orElse(0) >= 3.5, false),
            new PassCriterion("latency_p99_ms",
                perfBaseline.latencyP99Ms() < 5000, true)
        ));

        // Phase 5: 发送通知
        notificationService.sendEvaluationReport(report);

        return report;
    }

    private Map<String, Double> evaluateWithAllRubrics(
            RegressionTestReport regressionReport) {
        var scores = new HashMap<String, Double>();
        var rubrics = List.of(
            EvaluationRubric.correctnessRubric(),
            EvaluationRubric.faithfulnessRubric(),
            EvaluationRubric.correctnessRubric() // 可替换为其他 Rubric
        );

        for (var rubric : rubrics) {
            var avgScore = regressionReport.results().stream()
                .mapToDouble(r -> {
                    var result = judgeService.evaluate(rubric, r.question(),
                        r.actualAnswer(), r.expectedAnswer(), null);
                    return result.score();
                })
                .average()
                .orElse(0);
            scores.put(rubric.dimension(), avgScore);
        }
        return scores;
    }
}

七、最佳实践与常见问题

最佳实践

  1. 评估前置：在 Prompt 或模型变更的 PR 中，CI 流水线自动运行 Golden Dataset 评估，不通过则阻止合并。
  2. 分层评估：离线评估保证底线质量，在线评估反映真实用户体验，Agent 评估覆盖复杂交互场景。三层缺一不可。
  3. Rubric 持续迭代：LLM-as-a-Judge 的评分标准需要根据人工评审反馈持续校准。定期抽样人工复核 Judge 的评分。
  4. Golden Dataset 多样性：确保覆盖不同难度、类别和边缘情况。避免数据泄露（Golden Dataset 的问题不能出现在模型的训练数据中）。
  5. 可观测性从 Day 1 开始：在第一个 API 调用前就接入 OpenTelemetry。没有追踪数据，一切优化都是盲人摸象。
  6. Virtual Threads 处理并发评估：评估流水线中大量 IO 操作（调用 Judge 模型、读数据库），使用 Virtual Threads 可大幅提升吞吐量。

常见问题

Q: LLM-as-a-Judge 可靠吗？会不会有偏差？ A: LLM-as-a-Judge 存在已知偏差：位置偏差、长度偏差（偏好长回答）、格式偏差（偏好列表格式）。缓解措施包括：交换对比顺序、使用多个 Judge 模型、与人工评审结果定期校准。研究表明，GPT-4 作为 Judge 与人类评审的一致性可达到 0.8+ 的 Spearman 相关系数。

Q: Golden Dataset 需要多大？ A: 建议至少 100-500 条。关键在于覆盖范围和多样性而非单纯的数量。确保覆盖：事实性问题、推理问题、创意问题、边界情况、对抗性样本。可以从小规模开始（30-50 条核心 case），逐步扩充。

Q: 如何平衡评估成本和评估频率？ A: 采用分级策略。每次 PR：快速评估（50 条核心 case，5 分钟内完成）。每日：全量评估（所有 case）。每次模型升级：完整评估（所有 case + 所有维度 + 多 Judge）。使用更便宜的模型（如 GPT-4o-mini）作为 Judge 来降低成本。

Q: OpenTelemetry 和 Langfuse 如何选择？ A: 不互斥。OpenTelemetry 是基础设施标准，Langfuse 是 AI 专用分析工具。推荐：用 OTEL Collector 统一采集，同时导出到 Jaeger（基础设施团队）和 Langfuse（AI 团队）。

Q: 评估指标太多，如何确定核心指标？ A: 建议聚焦 3-5 个北极星指标（North Star Metrics）：对 RAG 应用，关注 Faithfulness + Recall@10 + User Like Rate；对 Agent 应用，关注 Final Result Correctness + Tool Selection Accuracy + Task Completion Rate。

Agent步骤链可观测

Agent 应用与传统的请求-响应式 AI 应用有本质区别：Agent 在一次任务中会经历多轮思考-行动-观察循环（ReAct Loop）。传统的单次 Trace Span 无法完整刻画 Agent 内部的决策链条，因此需要专门的 Agent 步骤链可观测 方案。

步骤链 Span 模型

Agent 的每一次 ReAct 迭代应建模为三层 Span 层级：

  1. Planning Span（规划层）：记录 Agent 在每个迭代开始时的思考过程（Thought），包括对当前任务状态的理解、下一步计划的推理文本。该 Span 的 attributes 应包含 agent.step.thought（完整思考文本）和 agent.step.number（当前迭代序号）。

  2. Execution Span（执行层）：记录 Agent 选择了哪个 Tool、传入什么参数、Tool 返回什么结果。关键属性包括 tool.name、tool.input（脱敏后）、tool.output（截断）、tool.duration_ms。如果 Tool 调用失败，还应记录 error.type 和 error.message。

  3. Replanning Span（重规划层）：当 Tool 执行结果返回后，Agent 需要评估结果是否满足预期、是否需要调整计划。该 Span 记录 agent.replanning.decision（继续/重试/放弃）和 agent.replanning.reason。

java
import io.micrometer.tracing.Span;
import io.micrometer.tracing.Tracer;
import org.springframework.ai.tool.definition.ToolResult;
import org.springframework.stereotype.Component;

import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;

@Component
public class AgentExecutionTracer {

    private final Tracer tracer;
    private final Map<String, Span> activeStepSpans = new ConcurrentHashMap<>();

    public AgentExecutionTracer(Tracer tracer) {
        this.tracer = tracer;
    }

    // 记录一个完整的 ReAct 步骤
    public Span traceReActStep(String taskId, int stepNumber, String thought,
                                String toolName, String toolInput, ToolResult result) {
        var stepSpan = tracer.spanBuilder()
                .name("agent.reat.step-" + stepNumber)
                .tag("task.id", taskId)
                .tag("step.number", String.valueOf(stepNumber))
                .start();

        // 记录思考过程
        tracer.spanBuilder()
                .name("agent.planning")
                .tag("agent.step.thought", thought)
                .tag("step.number", String.valueOf(stepNumber))
                .start()
                .end();

        // 记录工具执行
        var execSpan = tracer.spanBuilder()
                .name("agent.execution." + toolName)
                .tag("tool.name", toolName)
                .tag("tool.input", sanitizeForLogging(toolInput))
                .start();
        execSpan.tag("tool.duration_ms",
                String.valueOf(result.getDuration().toMillis()));
        execSpan.tag("tool.success",
                String.valueOf(!result.hasError()));
        if (result.hasError()) {
            execSpan.tag("error.message", result.getError().getMessage());
        }
        execSpan.end();

        // 记录重规划决策
        tracer.spanBuilder()
                .name("agent.replanning")
                .tag("agent.replanning.decision", determineDecision(result))
                .start()
                .end();

        stepSpan.end();
        return stepSpan;
    }

    private String sanitizeForLogging(String input) {
        // 脱敏：移除 API Key、Token 等敏感字段
        return input.replaceAll("(api[Kk]ey=|Bearer\\s)[^&\\s]+", "$1***");
    }

    private String determineDecision(ToolResult result) {
        return result.hasError() ? "RETRY" : "CONTINUE";
    }
}

Agent 专用 Dashboard

除标准的 Trace 查看外，Agent 可观测还需要专门的 Dashboard 面板：

  • 执行图可视化：以树状图展示每一轮的 Thought → Action → Observation 链路，节点颜色表示成功（绿）/ 重试（黄）/ 失败（红）。
  • Tool 调用成功率：按 Tool 名称分组统计成功率和平均耗时，识别高频失败的工具。
  • 重规划频率：统计 Agent 在单次任务中执行 Replanning 的次数，异常偏高说明 Prompt 或 Tool 设计有问题。
  • 北极星指标：平均每任务步数（avg steps per task）、Tool 选择准确率（tool accuracy）、人工介入率（human intervention rate）。通常 avg steps ≤ 5 为优秀，5-10 为可接受，>10 需要优化。

九、总结

本文构建了一个完整的 AI 应用评估和可观测性体系。三层次评估框架（离线/在线/Agent）覆盖了从开发到生产的全生命周期质量保障。LLM-as-a-Judge 提供了可扩展的自动化评估能力，Golden Dataset 回归测试确保每次变更不会引入退化。基于 OpenTelemetry + Micrometer + Prometheus + Grafana 的可观测性技术栈，让 AI 应用的每一步调用都透明可追踪。

这套体系已在多个生产级 AI 应用中验证，能够有效降低模型升级风险、加速 Prompt 迭代周期、提升最终用户体验质量。
